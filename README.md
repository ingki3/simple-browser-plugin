# 간편 브라우저 도우미 (Simple Browser Plugin)

Chrome Side Panel에 탑재되는 OpenRouter 기반 채팅 에이전트입니다. 현재 탭의 페이지를 이해하고, 사용자의 자연어 요청을 ReAct 패턴으로 해석해 사이트 이동·번역·폼 채우기·이미지 다운로드·링크 클릭 등 실제 동작을 수행합니다.

## 주요 기능

- **채팅 기반 ReAct 에이전트** — 요청을 받으면 `describe_page`로 먼저 페이지를 관측하고, 필요한 도구를 체인 호출한 뒤 결과를 답변
- **페이지 조작 도구**
  - `describe_page` — 랜드마크(main/article/nav/aside/header/footer)별 텍스트 미리보기·대표 링크 스냅샷. 같은 구조의 페이지에서 전에 통한 읽기 방법이 있으면 함께 알려 줌
  - `get_page_content` — Readability 스타일 본문 추출
  - `translate_page` — 가시 텍스트 노드 단위 번역 교체 + MutationObserver 동적 재번역
  - `find_form_fields` / `fill_form_fields` — 입력 필드 탐색·자동 입력, 칸마다 반영 여부 확인 (승인 카드). 찾기 결과에 사용자가 입력한 값은 담지 않음(글자 칸은 값 유무, checkbox·radio는 체크 여부, select는 선택지 글자와 선택 위치). select는 보이는 글자가 정확히 하나와 같을 때만 그 선택지 자체를 고름, checkbox·radio는 true/false로만 지정. 각 칸에 행 문맥(`context`: 칸이 든 행·묶음의 화면 글자, 입력값 제외)을 붙여 라벨 없는 행 체크박스(메일 목록 등)를 구분함. 화면에서 숨긴 checkbox·radio도 구조로 연결된 보이는 label(for·감싼 label, 링크·버튼 안이 아닌 것)이 있으면 돌려줌. checkbox·radio 채우기는 사용자가 누를 때처럼 칸 자신에 상태를 쓰고 click → input → change를 보냄(click만 듣는 필터 대화상자에도 반영됨, label에는 click을 보내지 않음). click은 브라우저 활성화 동작을 일으키지 않는 이벤트로 보내 input·change는 늘 확장이 보내며, click 처리기 뒤·input 처리기 뒤에 재확인해 막히면 input·change를 아예 보내지 않음. 페이지가 click을 취소하면 체크를 되돌리고 applied:false로 알림. 누르는 동작이라 같은 칸을 click_element로 누를 때의 위험 신호(감싼 링크·ping·내려받기·htmx 클릭 요청 등)도 승인 판정과 재확인에 넣음. 이런 대리 label 칸은 자동 실행을 켜도 늘 승인 카드로 물으며, 카드에 '보이지 않는 칸' 경고와 보이는 label의 표시 이름을 보여 줌(aria-labelledby 참조 포함, 승인 뒤 바뀌면 실행하지 않음). 승인 카드는 이름 없는 칸·이름이 겹치는 칸에 행 문맥을 함께 보여 줌
  - `list_page_images` / `download_images` — 이미지 URL 수집 → 지정한 이미지 저장 (선택 카드, 아래 "지정한 이미지·첨부 파일 내려받기")
  - `download_files` — 페이지의 첨부·다운로드 파일 링크 저장 (선택 카드, 로그인 쿠키 포함, 최대 20개)
  - `capture_page` — 보고 있는 페이지를 PNG로 캡처해 저장: 보이는 화면, 또는 `fullPage`로 스크롤해 페이지 전체 (승인 카드, 아래 "페이지 캡처")
  - `find_clickables` / `click_element` — 링크·버튼 탐색·클릭, 클릭 뒤 이동·화면 변화 보고 (승인 카드). 검색어를 `주문|배송|마이페이지`처럼 `|`로 묶으면 맞은 낱말이 많은 순으로 반환. 목록에서 고르는 위젯(role=option·menuitem*·tab, 선택 팝업 트리거 role=combobox·aria-haspopup=listbox — 편집형 입력 칸은 제외)과 체크 위젯(role=checkbox·switch·radio, 진짜 checkbox·radio — 화면에서 숨긴 칸은 대신 보여 주는 label(그 label 클릭은 자동 실행해도 늘 묻고, 판정에 숨긴 칸 쪽 위험 신호와 연결된 모든 label의 전체 글자를 넣음), 지금 체크 상태는 `states.checked`)도 찾아 트리거 클릭 → 다시 찾기 → 선택지 클릭으로 고름. 글자가 같아도 요소마다 따로 돌려주고, 각 대상에 묶음 문맥(`context`: 대상이 든 행·패널의 화면 글자, 구조로 찾은 표제를 앞에)과 상태(`states`: selected·checked·pressed·expanded·current·disabled)를 붙임
  - `navigate_to_url` — 현재 탭을 지정한 URL이나 사이트 홈으로 직접 이동 (승인 카드). 새 탭·설정 같은 브라우저 내부 페이지(chrome://·edge://·about:)에서도 http(s) 주소로는 이동함. 내부 페이지에서는 페이지를 읽거나 조작하는 도구가 "웹 페이지로 먼저 이동하세요" 오류를 내고, 모델은 관측 없이 이동부터 함. 주소가 열리지 않아 Chrome 오류 화면(없는 도메인·인증서 오류 등)이 뜨면, 페이지 도구는 "주입할 수 없음" 대신 `webNavigation.onErrorOccurred`의 오류 코드와 출처(scheme://host, 경로·쿼리 제외)를 알리고 짐작한 주소로 거듭 이동하지 말고 검색하거나 사용자에게 물으라고 안내(`src/lib/navError.ts`). 판단은 Chrome 오류 코드로만 하며, 기록은 탭 주소가 실패한 주소와 같을 때만 씀
  - `query_dom` — CSS 선택자 기반 DOM 조회. 화면 글자와 정해 둔 구조 속성(href·role·aria-selected 등)만 돌려줌
  - `get_youtube_transcript` — YouTube 영상의 "스크립트 표시" 패널을 열어 타임스탬프 포함 자막 추출
  - `list_file_links` — 페이지의 첨부·다운로드 파일 링크와 짐작한 형식 목록. 읽을 수 없지만 저장할 수 있는 파일(zip·구형 Office·이미지 등)은 `readable: false`·`ext`로 따로 표시(`download_files`용, `read_document` 판정은 그대로). 사용자 이름·비밀번호가 실린 주소는 이 목록·`list_page_images`·저장 후보 어디에도 넣지 않음
  - `read_linked_pages` — 지금 페이지에 있는 링크(기사 등)를 탭 이동 없이 받아 본문 읽기 (선택 카드, 최대 8개). 페이지의 a[href]에 실제로 있는 주소만(모델이 만든 주소 거절), 로그인 쿠키 없이. 리다이렉트(#47)는 webRequest로 목적지를 관찰해 원래 링크와 같은 사이트(등록 도메인, http→https 승격 포함) 안이면 최대 3번 새 요청으로 따라가고(단계마다 http(s)·계정 정보·결제·개인정보 주소 신호·루프 검사, 쿠키는 계속 싣지 않음), 다른 사이트면 따라가지 않고 목적지를 알림 — 그 목적지는 이번 요청(턴)·이 탭 동안만(최대 16개) 기억해 모델이 그 주소로 다시 부르면 새 승인 카드(다른 사이트·원래 링크 표시)의 후보가 됨. 결제·개인정보 신호가 있는 목적지는 따라가지도 기억하지도 않음. 실패는 리다이렉트(목적지)·HTTP 상태·네트워크 오류로 나눠 알리고, 401·403·429는 blocked로 표시해 클릭 없이 navigate_to_url 한 번으로 열어 읽도록 안내. 결제·개인정보 신호가 있는 주소는 경고와 함께 기본 미선택, 다른 사이트 표시. 받아 온 HTML은 offscreen 문서의 DOMParser로 파싱해(스크립트 실행·하위 자원 요청 없음, offscreen CSP로 외부 자원 차단) 본문을 뽑음 — 요소 수·깊이·순회 글자 예산과 글자 상한으로 작업량 제한, 기사당 4,000자·전체 24,000자, 짧은 본문은 short 표시. 읽으면 외부 본문 보호가 켜짐
  - `read_other_tabs` — 같은 창의 다른 탭 본문 읽기 (선택 카드). 탭 목록은 모델에 보내지 않고, 카드를 띄우기 전에 후보(탭·최상위 문서·주소)를 고정해 패널에만 제목·사이트를 보임. 사용자가 고른 탭(최대 5개)만, 승인 직후 같은 창·시크릿 아님·로딩 완료·같은 문서·같은 주소인지 다시 확인하고 그 문서에서만 읽음(바뀌었으면 읽지 않음, 재주입 없음). 탭당 12,000자·전체 40,000자, 한 요청 2번까지. 읽으면 외부 본문 보호가 켜짐
  - `read_document` — 링크된 파일을 화면 이동 없이 내려받아 텍스트로 읽기 (브라우저 안에서 처리, 최대 20MB, 한 요청에 5개까지) (승인 카드)
    - Word·Excel·PowerPoint(.docx/.xlsx/.pptx), OpenDocument(.odt/.ods/.odp) → Markdown ([docling.rs-wasm](https://github.com/docling-project/docling.rs))
    - PDF → 쪽별 글자 ([pdf.js](https://github.com/mozilla/pdf.js)), 한글(.hwp/.hwpx) → Markdown ([kordoc](https://github.com/chrisryugj/kordoc)), CSV/TSV → Markdown 표(구분자 자동 판별, 설정한 글자 수 한도에서 멈춤 — 기본 40,000자, 1,000~100,000), TXT/MD → 원문
    - 확장자 없는 다운로드 링크(`download.do?fileId=…`)는 응답 헤더와 파일 서명으로 형식 판별. CSV·TXT의 EUC-KR(CP949) 자동 인식
- **지정한 이미지·첨부 파일 내려받기** (#48) — "상품 사진 3번째부터 5번째까지 저장해 줘", "첨부 파일 중 PDF만 받아 줘"처럼 지정하면 모델이 `list_page_images`·`list_file_links`의 관측(순서·형식·alt·링크 글자)으로 어느 것인지 골라 `download_images`·`download_files`에 주소를 넘김(코드는 넘긴 주소만 쓰고 낱말 규칙으로 고르지 않음). 판정은 `src/lib/downloadPick.ts`(순수 함수, 단위 테스트)
  - 후보 고정: 카드를 띄우기 전에 넘긴 주소가 지금 페이지에 실제로 있는 이미지(`list_page_images`와 같은 수집)·링크(최상위 + 같은 출처 프레임 + 열린 shadow root의 `a[href]`·`area[href]`, 해시만 다른 주소는 같은 링크)인지 확인해 후보(id·주소)를 고정. 링크 존재 확인은 넘긴 주소를 문서 끝까지 찾음(카드에 함께 보일 링크 수 한도와 별개). 페이지에 없는 주소·http(s)가 아닌 주소·계정 정보가 실린 주소는 받지 않음(전부 없으면 카드 없이 오류, 섞이면 카드에 "받지 않는 주소"로 알림)
  - 선택 카드: 모델이 넘긴 것은 미리 체크, 모델이 고르지 않은 페이지 항목(이미지 전부, 링크는 파일 링크로 보이는 것)은 선택 해제로 함께 보임(최대 30개). 결제·개인정보 주소 신호(`sensitiveUrlReason`)는 경고와 기본 해제, 다른 사이트(등록 도메인) 첨부 파일도 기본 해제. 이미지는 페이지가 이미 그 사이트에서 불러와 보여 준 것(CDN)이 대부분이라 다른 사이트를 표시만 함. 확장자 없는 다운로드 링크(`download.do?fileId=…`)에는 "파일이 아닌 다른 동작을 하는 주소일 수 있음" 경고. 이미지는 alt·크기, 파일은 링크 글자·짐작한 형식·주소를 보임(썸네일·파일 크기는 승인 전 요청이 필요해 보이지 않음)
  - 받는 것은 사용자가 고른 고정 후보뿐: 패널은 후보 id만 돌려주고 백그라운드는 고정한 후보에 있는 id만 받아들이며, 실행은 모델 인자의 주소를 다시 쓰지 않음(패널 메시지로 임의 주소를 넣을 수 없음). 한 번 실행하면 후보를 버림
  - 파일 이름: 첨부 파일은 브라우저가 정한 이름(Content-Disposition → 주소)을 `onDeterminingFilename`에서 고른 폴더와 정리한 이름으로 바꿈(이 확장이 시작한 내려받기 중 기다리는 주소만, 내려받는 동안만 등록). 확장자가 없거나 서버 처리기 이름(.do·.php 등)이면 받은 형식(MIME)의 확장자를 붙이고, 이름이 없으면 `file-N`. 이미지는 주소의 이름(허락 경로의 data:는 받은 형식으로 확장자). 같은 이름은 uniquify(`report (1).pdf`). 이름 힌트는 실행마다 소유하고 다운로드 id로 묶어(id가 오기 전에 이름 정하기 이벤트가 오면 그 주소의 "시작 중" 힌트로 맞춤, 같은 주소의 시작만 한 번에 하나씩) 두 대화가 같은 주소를 다른 폴더로 받아도 섞이지 않음
  - 결과: 시작부터 끝날 때까지(최대 45초, 응답 헤더가 늦어 시작하지 못한 것도 이 안에서) 기다려 성공·실패 이유(401 로그인 필요·403·404·네트워크 등)와 저장 위치(다운로드 폴더 아래 `폴더/파일 이름` — 사용자 폴더 경로는 모델에 보내지 않음)를 돌려줌. 사용자가 중단하면 바로 끝내고 아직 받는 중이거나 중단 뒤에 늦게 시작된 내려받기는 취소함. 받은 것이 웹 페이지(HTML, 로그인 화면일 수 있음)·이미지가 아닌 응답이거나 다른 사이트로 리다이렉트되어 받았으면 note로 알림. 모델로 가는 이유·note는 고정된 분류 문구만 쓰고 서버가 정한 문자열(MIME·리다이렉트 목적지·오류 문구)은 싣지 않음. 이미지(외부 본문 보호를 켜지 않는 도구)의 저장 위치는 확장이 정한 이름과 uniquify 꼬리표만 알리고, 브라우저가 이름을 바꿨으면 그 이름 대신 note로 알림. 첨부 파일은 서버가 정한 이름(Content-Disposition) 그대로 알리고 보호를 켬
  - 안전: 첨부 파일은 로그인 쿠키가 필요한 경우가 많아 브라우저 다운로드(쿠키 포함, 리다이렉트를 따라감 — 사용자가 그 링크를 누른 것과 같음)로 받으므로 자동 실행·"이번 대화 동안 묻지 않기"의 대상이 아니고 늘 카드에서 고름(외부 본문 보호 중에도). 결과에 서버가 정한 파일 이름이 실려 실행하면 외부 본문 보호를 켬. 이미지의 "이번 대화 동안 묻지 않기"(#53)는 그대로 — 허락 경로는 모델이 넘긴 주소의 후보만(함께 보인 다른 이미지는 아님) 쿠키 없이·리다이렉트 없이 받은 이미지 바이트로 저장
- **팝업 창 (달력 등)** — 출발일처럼 읽기 전용 칸을 `window.open` 팝업 창(달력)에서 고르게 하는 사이트(SRT 등)를 위해
  - 클릭 결과에 팝업을 보고: 클릭하는 동안만 페이지(MAIN world)의 `window.open`을 감싸 불린 주소와 null 반환을 세고(noopener 창은 열려도 null이라, null 반환 수가 그 클릭 동안 만들어진 탭·창 수보다 많을 때만 막힌 것으로 봄), 끝나면 원래 함수로 되돌림(`src/background/popups.ts`). 막혔으면 "새 창(팝업)을 열려 했지만 브라우저가 팝업을 막았습니다(주소) … 팝업 허용을 요청하거나 직접 선택해 달라고 안내하세요". 확장의 클릭은 사용자 활성화가 없어 실제 Chrome에서는 팝업 차단기에 걸리는 경우가 많음 — 사용자가 주소창의 차단 표시에서 그 사이트 팝업을 허용하면 이후에는 열림. 주소는 호스트·경로만(쿼리는 `?…`, 계정 정보 없음, 100자) 싣고 문구는 고정(`popupWhere`·`describePopup`, `src/lib/actionTarget.ts`)
  - 열린 팝업 창 따라가기: 클릭하는 동안 그 탭의 문서가 연 탐색 대상(`webNavigation.onCreatedNavigationTarget` — 탭 줄 opener가 없는 별도 창·noopener 창도, 보조로 `openerTabId`) 중 창 종류가 `popup`인 것만, 그 턴의 도구가 그 창에서 동작하게 함(결과에 "이제 도구는 팝업 창에서 동작합니다"). 사용자가 따로 연 창·일반 새 탭(target=_blank, 크기 없는 `window.open`)은 따라가지 않음. 창이 닫히면(달력이 고른 날짜를 원래 페이지에 써 넣고 닫힘) 원래 탭으로 돌아오고 그 클릭 결과나 다음 도구 결과(`tab`)에 알림. 팝업이 또 연 팝업은 3단계까지(팝업이 다음 창을 열고 닫히면 새 창을 따라감). 따라간 적 있는 창을 페이지가 같은 이름으로 다시 쓰면(`window.open(url, "calendar")` — 새 탭 없이 그 창이 이동) 이 클릭의 성공한 `window.open` 주소와 그 창의 이동 주소가 같을 때만 다시 따라감. 같은 원래 탭에서 시작한 다음 턴은 아직 열린 팝업을 이어 따라감(탭 머리말의 URL·제목·PDF 판별도 그 창 기준). 단 원래 탭이 따라가기를 시작할 때의 문서(최상위 `documentId`)가 아니면(다른 페이지로 옮겼거나 새로 고침) 잇지 않고 원래 탭에서 시작
  - 탭으로 열린 팝업: 팝업을 요청한 `window.open`을 브라우저가 같은 창의 일반 탭으로 여는 경우(macOS 창 전체 화면 등)도 따라감. 조건은 모두 구조로만 봄 — 이 클릭 동안 브라우저 관계로 새로 만들어진 탭이 정확히 하나, 성공한(창을 돌려준) `window.open` 기록이 정확히 하나이고 기록이 완전함(모든 프레임을 한도 안에서 읽음, 주소 2,000자·창 옵션 1,000자 이하), 그 호출의 창 옵션이 HTML 표준 "check if a popup window is requested"로 팝업 요청(noopener·noreferrer 제거 뒤 판정, `src/lib/popupMatch.ts`), 탭이 클릭한 탭과 같은 창에서 브라우저가 앞에 띄운 활성 탭이고 확정된 문서 주소가 그 호출 주소와 해시까지 같음. 크기 없는 `window.open`·`target=_blank`·noopener 창은 따라가지 않음. 따라가는 동안 도구마다 그 탭이 아직 그 창의 활성 탭이고 창이 내려가 있지 않은지 확인하고(아니면 작업하지 않고 사용자에게 앞에 띄워 달라고 안내), 첫 도구 전에는 따라가기 시작할 때의 문서인지도 확인. 다음 턴은 그 탭이 앞에 있을 때만 이어 따라가고(원래 탭은 기록한 원래 탭으로 유지), 원래 탭이 앞에 있으면 원래 탭에서 시작. `navigate_to_url`은 원래 탭을 앞으로 띄워 이동. 따라가지 않은 후보는 디버그 로그(`popup:skip`)에 이유를 남김(탭 id와 고정 문구만)
  - 안전: 자동 실행·링크 허락의 사이트 경계는 지금 도구가 동작하는 창의 주소로 판정해, 다른 사이트의 팝업 안 클릭·입력은 다른 사이트로 이동한 페이지처럼 승인 카드로 물음. 찾기 id는 문서마다 따로라 원래 탭의 id를 팝업에(또는 반대로) 쓰면 실패하고 오류에 "지금 도구는 팝업 창에서 동작합니다"를 덧붙임. `navigate_to_url`은 늘 원래 탭을 이동하고 팝업 따라가기를 끝냄. `describe_page`는 팝업 창이면 `window`에 그 안내를 붙임. 캡처는 팝업 창(그 창의 활성 탭)을 찍고 카드에 "따라가는 팝업 창"으로 표시

  - 안전: 늘 승인 카드(자동 실행·"이번 대화 동안 묻지 않기" 대상 아님, 외부 본문 보호 중에도 카드). 카드에 "화면에 보이는 내용(입력한 값·개인정보 포함)이 그대로 담긴다"와 모델 제공자로 보내지 않음을 표시. 캡처한 이미지는 저장만 하고 모델에 보내지 않음(화면 내용을 이미지로 묻는 기능은 입력값 보호(#43) 원칙과 함께 별도로 정할 일). 브라우저 내부 페이지(chrome://·about: 등)·확장 페이지·웹 스토어·data:/blob: 탭, 그 창의 앞에 보이지 않는 탭(captureVisibleTab은 창의 활성 탭을 찍음)은 카드 없이 이유를 알림. PDF 뷰어는 보이는 화면만(전체 캡처는 이유를 알림). 카드에 보인 대상(탭·창·주소·최상위 문서 documentId)을 호출에 고정해, 카드가 열린 사이 다른 페이지로 이동했거나 새로 고쳤거나 탭이 다른 창으로 옮겨졌으면 찍지 않음. `captureVisibleTab`은 창의 활성 탭을 찍으므로 고정한 창 id로만 찍고, 매 장 찍기 전후에 같은 문서인지·탭이 그 창에 있고 그 창의 활성 탭인지 확인하며, 그 사이 그 창의 탭 활성화·탭 창 이동·문서 이동 이벤트가 한 번이라도 오면 버림(전체 캡처의 단계 메시지도 그 문서에만 보냄). 창 포커스는 찍는 대상과 무관함. 캡처하는 동안 창 크기·배율이 바뀌면(첫 장 포함 모든 장의 이미지 폭·높이를 처음 잰 창 안쪽 크기 × 배율과 비교, 스크롤 뒤와 찍은 뒤에도 다시 재어 비교), 찍은 뒤 잰 스크롤 위치가 스크롤해 둔 위치와 다르거나(사용자 스크롤·페이지 스크립트), 화면들이 맨 위부터 빈 구간 없이 이어지지 않으면(기다리는 사이 페이지가 아래로 건너뜀) 어긋난 이미지를 성공으로 남기지 않게 저장하지 않고 이유를 알림. - **목표 페이지 찾아가기** — "배송 상황 확인해줘"처럼 지금 페이지에 없는 정보를 물으면 마이페이지 → 주문/배송 조회처럼 링크를 2~4단계 따라가며 찾고, 막다른 페이지면 직전 주소로 돌아가 다른 후보를 시도. 답에 거쳐 온 경로를 밝힘. 로그인 화면에서는 멈추고, 결제·주문하기 버튼은 경로로 쓰지 않음. 자동 실행에서도 주문 조회 링크(글자·주소에 '주문'·order가 있는 링크)는 결제 판정 규칙에 걸려 승인 카드를 띄움(카드의 "이번 요청 동안 링크 이동 묻지 않기"로 나머지 단계는 묻지 않게 할 수 있음). 페이지마다 도구를 2~3회 쓰므로 도구 호출 한도 기본값을 16으로 올림(이 버전 전에 저장된 설정의 8은 예전 기본값으로 보고 16으로 읽음. 이후 설정 화면에서 8로 저장하면 그대로 씀)
- **도구 호출 한도와 이어 가기** (#55) — 한 요청의 도구 호출 순환 한도(모델 요청 횟수)는 설정에서 1~100(기본 16). 응답 중에는 입력창 위에 진행 단계(`단계 12/30`)를 보이고, 한도에 가까우면 강조함. 한도에 닿으면 끝내지 않고 "지금까지 한 일"(도구별 횟수·실패·취소 수·최근 결과 3줄)과 함께 "N단계 더 진행" 카드를 띄움(N은 설정한 한도). 허락하면 같은 요청을 대화 맥락 그대로 이어 가고(다시 닿으면 다시 물음), 그만하면 도구 없이(`tool_choice: none`) 지금까지의 관측으로 답을 한 번 받아 끝냄 — 그 마무리 안내는 그 요청에만 붙이고 대화 기록에는 남기지 않음. 카드가 떠 있을 때 중단·새 대화·패널 닫힘이면 마무리 요청 없이 끝남. 한도는 사용자가 카드에서 고를 때만 늘어남
- **헛돌기 감지** (#55) — 한도와 별개로 다음이면 도구 사용을 멈추고 알린 뒤 도구 없이 지금까지의 결과로 답함. 판정은 구조로만 함(`src/lib/hopGuard.ts`, 오류 문구의 낱말은 보지 않음)
  - 같은 도구를 같은 인자로 연속 3번 불러 같은 결과(오류면 같은 오류 글자)를 냄. 클릭은 뒤따른 이동·화면 변경(DOM 변경)·대화상자·새 탭이 관측되면 반복으로 세지 않음 — '다음 달'처럼 같은 버튼을 여러 번 누르는 것은 정상. 화면 변화 없이 같은 결과만 되풀이한 클릭만 셈
  - 한 도구가 그 도구의 성공 없이 3번 실패(사이에 다른 도구가 끼어도 이어서 셈 — "다시 찾기 → 클릭 실패" 고리). 오류 글자에는 대상 id처럼 바뀌는 값이 들어 있어 글자 비교 대신 도구 이름과 실패 여부로만 봄. 사용자가 카드에서 취소한 호출은 실패로 세지 않음
- **민감 작업 승인 UI** — 사이트 이동·폼 입력·다운로드·클릭 같은 페이지 상태 변경과 문서 URL 요청(쿠키 포함)은 실행 전 사이드 패널에 미리보기 카드를 띄워 사용자 승인을 받음
- **이번 요청 동안 링크 이동 허락** — 같은 사이트 안의 일반 링크(다른 페이지로 가는 `<a href>`, 감싼 링크·양식 제출·내려받기·ping 없음, 개인정보가 채워진 양식과 무관, 주소와 주변 양식의 제출 주소에 개인정보 없음)를 누르는 승인 카드에 "승인 + 이번 요청 동안 링크 이동 묻지 않기"가 함께 뜸. 고르면 그 요청이 끝날 때까지(중단·새 요청이면 끝) 같은 조건의 링크는 결제 문구 판정 없이 카드 없이 누름(삭제·스팸 같은 되돌리기 어려운 동작으로 보이는 링크는 이 허락을 제안하지도 쓰지도 않음, #62). 버튼·양식 제출·다른 사이트로 가는 링크는 계속 물음. 자동 실행 설정과 관계없이 쓸 수 있음. 링크의 클릭 처리기가 이동 대신 다른 동작을 할 수는 있어 사용자가 고른 요청 하나에만 적용
- **이 주소는 이번 대화에서 다시 묻지 않기** — 자동 실행 중 클릭·입력 카드가 뜬 이유가 주소의 개인정보 모양 신호뿐이면(예: SRT 양식 주소의 `pageId=TK0101010000`이 휴대전화 번호 모양으로 걸림) 카드에 걸린 주소 목록과 "승인 + 이 주소는 이번 대화에서 다시 묻지 않기"가 함께 뜸. 고르면 이번 대화 동안(새 대화·패널 닫힘·서비스 워커 재시작이면 끝, 저장하지 않음) 그 주소(글자 그대로 같을 때만. 예외로 양식이 그 action 주소 뒤에 개인정보 신호 없는 칸 값만 덧붙여 만든 제출 주소는 같은 주소로 봄)의 개인정보 주소 신호만 면제하고, 결제·계정 정보·끝까지 못 본 주소(감싼 주소 안 포함)·제출 문구·개인정보 칸·사이트 경계·되돌리기 어려운 동작·외부 본문 보호는 그대로 물음. 요소의 값이 붙을 수 있는 htmx 요청 주소는 면제 대상이 아님. 그 선택지를 보인 카드의 주소만 받아들임(`src/lib/autoApprove.ts` `personalOnlyUrl`)
- **이번 대화 동안 이 도구 묻지 않기** (#53) — 위험이 낮은 세 도구(`read_linked_pages`·`translate_page`·`download_images`)의 승인 카드에 "승인 + 이번 대화 동안 이 도구 묻지 않기"가 함께 뜸. 대상은 도구 이름으로만 정하고 그 밖의 도구 카드에는 뜨지 않음. 허락은 그 대화가 끝날 때까지(새 대화·패널 닫힘·확장이나 서비스 워커 재시작이면 끝) 백그라운드의 대화 객체 메모리에만 두고 저장소에 남기지 않음. 판정은 `src/lib/chatGrant.ts`(순수 함수, 단위 테스트)
  - `read_linked_pages`: 고른 링크가 모두 지금 페이지에 있는 같은 사이트 링크이고 카드에 붙는 경고(결제·개인정보 주소 신호, 다른 사이트, 리다이렉트 목적지)가 없으며 페이지에 없는 주소가 섞이지 않았을 때만 카드 없이 모두 읽음. 하나라도 섞이면 카드(제안 없음)
  - `download_images`: 허락한 저장 폴더(실제 저장 폴더 이름 기준)와 같고, 주소가 모두 지금 페이지의 이미지(`list_page_images`와 같은 수집) 그대로이며 결제·개인정보 주소 신호가 없을 때만. 다른 폴더면 카드에서 그 폴더로 바꿔 허락할 수 있음. 허락으로 저장할 때는 브라우저 다운로드(그 호스트의 쿠키를 싣고 리다이렉트를 따라감)를 쓰지 않고, 쿠키 없이·리다이렉트를 따르지 않고 직접 받은 이미지 바이트(Content-Type이 image/*, 하나 10MB·전체 40MB·30개까지)만 data: 주소로 저장함 — 로드되지 않은 `<picture><source>` 주소가 로그인 사이트의 상태 변경 주소로 리다이렉트해도 인증된 요청이 나가지 않음. 하나라도 받지 못하면(리다이렉트·HTTP 오류·이미지 아님·너무 큼) 그 이유와 함께 카드로 묻고, 카드로 승인하면 기존 다운로드 경로. 폴더를 생략한 호출은 카드·허락 판정에 쓴 기본 폴더에 저장(그 사이 설정이 바뀌어도)
  - `translate_page`: 기존 범위 그대로. 평소에는 카드 없이 실행되는 도구라, 실제로 카드가 뜨는 것은 외부 본문 보호 중뿐이고 그때는 허락을 쓰지 않으므로 지금은 제안이 뜰 일이 없음
  - 외부 본문 보호(#37) 중에는 모델이 만든 값을 밖으로 보낼 수 있는 도구(`translate_page`의 번역 언어·`download_images`의 주소)는 허락과 관계없이 카드로 물음. `read_linked_pages`는 페이지가 준 주소만 쿠키 없이 받아 모델 유래 값을 보내지 못하고 그 자체가 보호를 켜므로, 보호 중에도 위 조건 안에서 허락을 씀(숨긴 지시문이 같은 링크를 고르게 하는 것은 보호를 켜지 않는 지금 페이지의 글로도 가능)
  - `read_other_tabs`, 클릭·입력·이동은 대상이 아님(자동 실행·링크 이동 허락 규칙 그대로). 링크 이동 허락은 페이지 상태를 바꾸는 클릭이라 한 요청에만 쓰고, 이 허락과 대상 도구가 겹치지 않음
  - 입력창 위에 이 대화에서 허락한 도구(이미지 저장은 폴더)를 작게 표시하고(진행 단계 표시와 다른 줄), 누르면 취소. 허락으로 실행한 결과 카드에는 "이번 대화 허락으로 실행", 허락했는데 묻는 카드에는 그 이유를 붙임
- **자동 실행 (설정, 기본 꺼짐)** — 켜면 페이지 이동·클릭·입력을 승인 카드 없이 실행하고 결과 카드에 "자동 실행"으로 표시. 그래도 다음은 카드를 띄움:
  - 결제·주문 버튼, 결제 화면(주소의 경로·쿼리·해시, 제목, 큰 제목, 버튼이 든 양식·대화상자에 결제 단서)의 버튼
  - 사용자가 고르지 않은 사이트에서의 동작. 이동·클릭·입력은 요청을 시작한 탭의 사이트와 이 대화에서 카드로 이동을 허락한 사이트 안에서만 자동(모델이 만든 주소·호스트 이름이나 낯선 페이지의 입력 칸으로 대화 내용이 새지 않게). 다른 사이트로 가는 링크 클릭과 다른 사이트로 제출하는 양식 버튼도 물음. 사이트 경계는 브라우저의 "같은 사이트"처럼 등록 도메인 기준(공개 접미사 목록 [tldts](https://github.com/remusao/tldts)로 확인된 것만: www.naver.com에서 shopping·mail.naver.com은 안, example.co.kr에서 other.co.kr은 밖, a.github.io와 b.github.io는 다름). 목록으로 확인되지 않는 접미사는 같은 호스트와 그 하위 도메인만 안. 공유 호스팅·접미사 자체·IP·localhost에서 시작한 경우는 같은 호스트만 안(script.google.com에서 www.google.com은 밖). github.io·s3.amazonaws.com·Apps Script·Google Docs/Forms 같은 공유 호스팅·사용자 콘텐츠 주소는 늘 물음. 같은 등록 도메인의 다른 하위 서비스로 가는 이동·클릭은 묻지 않으므로, 페이지 속 지시문이 같은 회사의 다른 서비스로 이동을 유도하는 경우는 막지 않음. 자동 이동·클릭으로 들어간 사이트는 신뢰 사이트가 되지 않음
  - 새 탭·설정 같은 내부 페이지에서 시작한 요청은 시작한 사이트가 없으므로, 이동은 이번 요청 글에 사용자가 직접 적은 웹 주소·도메인(`naver.com`, `https://…` 같은 주소 모양만 봄 — 사이트 이름 "네이버" 같은 낱말은 해당 없음, 이메일 주소의 도메인·주소 속 경로와 매개변수는 제외. 공백으로 나눈 덩어리가 그대로 주소일 때만 인정해 "naver.com으로"처럼 조사가 붙으면 카드로 물음)과 등록 도메인이 같거나 이 대화에서 카드로 허락한 사이트일 때만 자동. 그렇게 이동하면 그 사이트를 이 요청의 사이트로 삼아 이후 클릭·입력도 자동 실행 범위로 씀. 내부 페이지에는 페이지 글이 없어 숨긴 지시문이 끼어들 수 없지만, 모델이 만든 주소로 대화 내용이 나갈 수 있어 이렇게 제한함. 외부 본문 보호 중에는 늘 물음
  - 가입·신청·제출·인증 버튼
  - 되돌리기 어려운 동작(삭제·스팸)(#62) — 클릭·입력·이동 모두:
    - 구조 선언: `data-method`·`data-turbo-method="delete"`, `hx-delete`, 양식 칸·누른 제출 버튼의 `_method=DELETE`(대상·조상·양식·label이 작동시키는 컨트롤, 입력 칸 자신 포함)
    - 실제로 실릴 값: 누른 제출 버튼의 name=value(`<button name="action" value="delete">확인</button>`), 클릭·입력으로 바뀌는 checkbox·radio 자신의 name=value, 양식을 제출하면 실릴 선택 컨트롤(숨은 칸, 이미 체크된 checkbox·radio, select의 선택된 option의 value·글자)의 name=value(입력은 쓰기 전 상태로 판정). 누르지 않은 다른 제출 버튼의 값과 사용자가 치는 글자 칸·textarea의 값(검색어 등)은 보지 않음
    - htmx는 **허용 목록 방식**: htmx가 관여하면 기본은 "htmx 요청(GET 아님·확인할 수 없음)"으로 묻고, 카드 없이 자동 실행되는 것은 이번 클릭·입력이 일으킬 수 있는 htmx 요청 요소(대상·연결 컨트롤·제출자·양식에서 문서 끝까지의 경로, 페이지의 모든 `from:` 리스너 — 선택자를 해석하지 않고 열린 shadow root·같은 출처 iframe까지 찾음(닫힌 shadow root·다른 출처 iframe 안은 볼 수 없는 한계), hx-boost 적용 요소)와 그 조상의 htmx 속성(hx-*·data-hx-*)이 모두 {hx-get, hx-target, hx-swap, hx-select, hx-select-oob, hx-push-url, hx-replace-url, hx-indicator, hx-disabled-elt, hx-sync, hx-boost, hx-trigger(이벤트 필터 `[…]`와 `js:` 없음)} 안이고 요청이 GET(hx-get, hx-boost의 링크·GET 양식)일 때뿐. hx-get 없는 `from:` 리스너(hx-boost POST 양식 등)도 물음. htmx가 관여하는 경로에서는 양식의 method가 있으면 'get'이어야 하고, 경로의 모든 button·input(type 무관 — htmx는 type=button도 추적해 그 버튼의 덮어쓰기와 값을 씀)의 form* 속성은 formmethod=get·formaction(주소의 삭제 단서를 봄)·formnovalidate 밖이면 묻고, 그 name=value의 삭제 단서도 봄. htmx는 이전에 추적한 버튼의 덮어쓰기를 나중 요청에도 쓰므로, 경로에 htmx가 있거나 페이지에 `from:` 리스너가 있으면 페이지(접근 가능한 모든 루트)의 버튼 전체를 같은 규칙으로 봄(버튼이 2000개를 넘으면 모름). 통과한 GET 요청에도 주소·요청 요소 자신의 name=value(글자 칸·textarea는 이름만 — 입력값은 보지 않음)·양식이면 실릴 값의 삭제 단서 검사를 그대로 적용(묶음 입력이 승인한 선택 칸 쓰기는 제외). rails-ujs `data-params`의 글자에 삭제 단서가 있어도 물음. 경로가 1만 단계를 넘거나 from: 요소가 200개를 넘거나 양식 칸이 5000개를 넘거나 hx-get 주소가 풀리지 않으면 모르는 것으로 보고 물음
    - 자동 실행되는 htmx GET 요청도 그 목적지(hx-get 주소, 요청하는 양식의 action, htmx가 쓸 수 있는 버튼의 formaction)를 다른 목적지처럼 사이트 경계·결제·개인정보·삭제 주소로 검사함(클릭과 입력 모두, 승인 뒤 바뀌면 실행하지 않음, 50개를 넘으면 묻기)
    - 글자: 버튼 자신과 실제로 작동하는 바깥 버튼·링크(입력 칸은 라벨)의 글자·aria-label·title·alt에 삭제·지우기·제거·휴지통·스팸·차단·영구·비우기·탈퇴·delete·remove·trash·spam·junk·discard·erase·purge·block 등(아이콘 버튼은 aria-label·title로). select는 고를 선택지의 글자·value에 같은 단서가 있으면 물음(다른 선택지를 고르면 묻지 않음)
    - 주소: 링크·감싼 링크·양식 제출 주소(action·formaction)·ping·선택지 주소와 `navigate_to_url`의 이동 주소의 경로·쿼리 낱말
    - 선택지(메뉴 항목)는 펼친 트리거에도 적용. 행 문맥(메일 제목 등)은 보지 않아 제목에 '삭제'가 든 메일 행의 체크박스·열기 버튼은 그대로 자동 실행됨(그 행의 링크 글자 자체가 제목이면 물음). 범위 안 다른 양식·누르지 않은 제출 버튼의 주소는 보지 않음(목록 양식의 '삭제' 버튼 하나로 화면의 모든 체크가 걸리지 않게 — 처리기가 다른 양식을 대신 제출하는 삭제는 놓침)
    - "이번 요청 동안 링크 이동 묻지 않기"·"이번 대화 동안 묻지 않기"로도 건너뛰지 않고, 자동 실행이 꺼져 있어도 카드에 경고를 붙임. 승인 뒤 삭제 선언·실릴 값·삭제 선택지가 새로 생기면 실행하지 않음(같은 입력 묶음이 선택 칸에 쓴 상태(쓴 직후·페이지 처리기 전에 기록: select는 선택된 option 요소·그 value·선택 상태·select name, checkbox·radio는 name·value·checked)만으로 생긴 신호(실릴 값의 삭제 단서와 `<select name="_method">`의 DELETE 같은 구조 선언 모두)는 묶음의 모든 칸에서 예상된 변화로 보고 끝까지 실행 — 지금 상태가 기록과 하나라도 다르거나(처리기가 글자는 두고 value만 바꾼 경우 등) 그 칸들을 뺀 나머지로 신호가 생기면 멈춤)
    - 구조 선언 밖의 신호는 낱말·경로 단서라 더 묻는 쪽의 최선일 뿐 완전하지 않음(글자·주소·값 어디에도 단서가 없는 삭제는 놓침)
  - 비밀번호·결제 정보·개인정보 칸(이름·연락처·이메일·주소·생년월일 등) 입력
  - 개인정보·비밀번호·결제 값이 채워진 양식 안의 버튼
  - 이미지·첨부 파일 저장·파일 읽기·Google 문서 쓰기(자동 실행 대상이 아님. 이미지 저장은 위의 "이번 대화 동안 묻지 않기"로만 생략, 첨부 파일 저장은 늘 카드)

  카드에는 자동 실행하지 않은 이유가 붙음. 승인 뒤 실행 직전에 칸이 개인정보로 채워지거나 결제 화면으로 바뀌면 실행하지 않음. 판정은 버튼 글자·칸 이름·autocomplete 속성을 보는 규칙이라 놓칠 수 있고, 웹페이지에 숨긴 지시문이 모델을 속여 원치 않는 곳으로 이동하거나 누르게 할 수 있으므로 믿을 수 있는 사이트에서만 켜 두기를 권함
- **OpenRouter 모델 지원** — `provider/model` 형식의 모델 ID를 직접 선택하며, reasoning과 tool calling 결과를 실시간 스트리밍
- **생각 중 표시** — 모델이 추론하는 동안 추론 글자 대신 "생각 중…"과 움직이는 아이콘만 보임(도구 전 짧은 설명과 답변은 그대로). 설정의 "생각 과정 보기"를 켜면 추론 글자를 접이식 상자로 봄
- **사용자 기본 지침** — "모든 출력은 한글로" 같은 시스템 지침을 설정해 모든 대화에 적용
- **모델별 reasoning 호환성** — Gemini 3 계열의 필수 effort와 gpt-oss 출력 제한·스트림 종료 처리
- **고속 페이지 번역 경로** — 처리량 우선 provider routing, 대형 배치·중복 제거·메모리 캐시 적용
- **Shadow DOM + 동일 출처 iframe 커버리지** — 모든 툴이 shadow root와 iframe 내부까지 순회
- **PDF 이해** — 현재 탭이 PDF면 자동으로 내려받아 OpenRouter의 PDF file input으로 붙여 내용 기반 질의응답 가능 (최대 20MB)
- **디버그 타임라인** — 사이드 패널에서 🐞 버튼으로 BG·content·panel 이벤트를 실시간 추적, 복사 버튼으로 공유 가능

## 아키텍처

```
[Side Panel React UI] ⇄ long-lived port ⇄ [Background Service Worker] ⇄ tabs.sendMessage ⇄ [Content Script]
                                                    │
                                                    ├── OpenRouter Chat Completions API
                                                    ├── ReAct stream loop (reasoning_details 보존)
                                                    ├── Tool dispatcher (zod 인자 검증)
                                                    └── webNavigation 통합 (settle 대기)
```

### 주요 구성

- **Manifest V3** — `sidePanel`, `storage`, `scripting`, `activeTab`, `downloads`, `tabs`, `alarms`, `webNavigation`, `identity`, `offscreen`, `webRequest`, `debugger`(실제 입력 클릭, 설정에서 켤 때만 사용) 권한 + `host_permissions: ["<all_urls>"]`
- **Port 하트비트 + 자동 재연결** — MV3 서비스 워커 유휴 종료 대응
- **스트림 청크 무활동 워치독** (60초) + **초기 연결 타임아웃** (20초) + **툴별 타임아웃** (기본 30초, translate 180초)
- **webNavigation 기반 settle 대기** — URL 이동·클릭 직후 페이지 전환 중에 후속 툴이 경쟁 조건 만나지 않도록
- **캡처 이어 붙이기** (#49) — 전체 캡처의 화면들(PNG Blob)을 offscreen 문서(`BLOBS` 사유 추가)에서 조각마다 캔버스 하나씩 만들어 그 조각에 걸친 화면만 디코드해 그리고 PNG로 만든 뒤 캔버스를 놓음(한 번에 한 조각만 메모리에). 결과 blob: 주소는 저장 뒤 놓고, 놓지 않아도 5분 뒤 스스로 놓음
- **문서 변환 격리** — `read_document`는 offscreen 문서 안의 Worker에서 변환하고(형식에 맞는 변환기만 불러옴), 10초가 지나거나 사용자가 중단하면 Worker를 강제 종료. zip 기반 문서(Office·OpenDocument·HWPX)는 직접 풀어 크기를 센 뒤(본문 6MB·전체 40MB) 다시 만들어 넘기며, 이미지 등 바이너리는 비워서 넘김. PDF(pdf.js 워커에 빌드 때 패치)와 HWP(zlib 셰임)도 압축 해제량에 한도를 둠(문서당 128MB·256MB). 1분 동안 쓰지 않으면 offscreen 문서를 닫음
- **클릭·입력 확인 경로** — `find_clickables`·`find_form_fields`가 준 id마다 그때의 대상 기술(역할·글자·주소·영역·목록 순번·대상이 든 행의 글자)을 content script 메모리에 둠. 승인 카드를 띄울 때 지금 요소가 그때와 같은지 확인해 사람이 알아볼 수 있게 보여 주고(비밀번호 칸은 값을 가림), 실행 직전과, 클릭은 스크롤·포커스 뒤 누르기 바로 앞에서 다시 승인한 기술과 같을 때만 실행. 요소가 다시 그려져 사라졌으면 비슷한 요소로 대신하지 않고 멈춤(다시 찾아 새로 승인). 클릭 대상은 모델에 준 묶음 문맥과 상태도 비교함(승인 뒤 이미 체크·펼침으로 바뀐 대상을 누르면 반대로 되므로 멈춤). 입력 칸도 모델에 준 행 문맥과 '보이는 label로 바꾸는 칸' 여부를 비교함. 다만 입력 도중(입력 처리기 뒤 change 전, 같은 묶음에서 앞 칸을 채운 뒤의 칸)과 입력 뒤 반영 확인에서는 원문 행 글자가 그대로이고 모델용 행 문맥에 글자가 더해지기만 한 것(행 안의 숨은 안내 글이 보이게 됨 — 승인 당시 낱말이 같은 순서로 모두 남음)은 허용함. 문구를 바꿔 보여 주는 것은 거부(#43 C의 오탐을 늘리지 않게). 목록 다중 선택은 지침으로 '전체 선택' 대신 항목별로 고르고, 지우기·옮기기 같은 되돌리기 어려운 동작 전에는 고른 목록을 사용자에게 확인받으며, 화면 밖 항목은 다음 페이지 링크로 넘김(스크롤로만 더 불러오는 목록은 미지원).
- **선택지와 트리거의 관계** (#43 B) — 선택지(option·menuitem*)는 펼쳐진(aria-expanded=true) 트리거와의 관계를 구조로만 정함: aria-controls/aria-owns로 선택지나 그 목록을 가리키는 펼친 트리거가 정확히 하나면 linked, 연결이 없고 펼친 트리거가 0~1개면 unlinked, 그 밖(펼친 트리거 둘 이상·연결 없음, 연결 둘 이상)은 어느 위젯의 선택지인지 정할 수 없어 클릭 대상으로 돌려주지 않음. 관계(트리거·목록 요소, 연결 방식, 트리거 기술)는 승인 카드 때·실행 직전·스크롤과 포커스 뒤에 다시 계산해 같아야 누름. 트리거의 위험 정보(결제 화면·개인정보가 채워진 양식·제출 주소 등)는 선택지와 따로 background로 보내 승인·사이트 판정을 양쪽 모두에 적용(포털로 그린 목록이라도 트리거가 결제 대화상자 안이면 카드). 트리거 자신이 다른 목록 안의 항목인 중첩 메뉴의 항목은 상위 트리거들의 위험을 따라가지 않으므로 자동 실행하지 않고 늘 카드로 물음. 한계: unlinked는 소속을 증명하지 않음 — ARIA 펼침 상태를 표시하지 않는 위젯이 같은 목록을 넘겨받는 경우는 구조로 구분할 수 없음(공유 팝업 안의 일반 버튼과 같은 한계). ARIA 역할이 없는 div·li 위젯, pointerdown·keydown에만 반응하는 위젯은 지원하지 않음 승인은 그 호출에 한 번만 쓰임. id에는 페이지마다 바뀌는 꼬리표가 붙어 이전 페이지의 id는 거부
- **실행 결과 확인** — 클릭 뒤 이동 종류(없음·페이지 안 위치(#)·같은 사이트·다른 사이트·오류), 페이지 안 주소 변경, 새 탭, 팝업 창(열림·막힘·닫힘), 화면 변화(DOM 변경 수·대화상자)를 결과로 돌려줌. 입력은 페이지 처리가 끝날 틈(150ms)을 둔 뒤 칸마다 값을 다시 읽어 실제로 반영됐는지 알려 줌
- **동작 기록** — 승인한 클릭·입력마다 페이지 구분 키(주소 틀 + 페이지 뼈대 해시), 대상 요약, 결과(완료·일부 반영·직전 중단·실패·취소)를 `chrome.storage.local`에만 남김. 주소 틀은 사람이 붙인 이름처럼 보이는 경로 낱말만 남기고 숫자·토큰·이메일·한글 이름 같은 칸은 자리표시로 바꾸며, 쿼리는 이름만 남김(`/board/{n}/view?id`). 대상 이름에 섞인 주소·이메일·key=value·긴 숫자·비밀 값처럼 보이는 낱말도 가림. 입력 칸은 이름 글자 대신 해시만 남기고(값·숫자를 지운 뒤 계산), 비밀번호·결제 칸은 해시도 남기지 않음. 뼈대 해시는 랜드마크·목록·표·폼의 중첩만 보고 같은 틀의 목록 항목은 하나로 접어, 내용과 항목 수가 달라도 같은 값. 입력 값, 대상이 든 행의 글자, 링크 주소의 값은 남기지 않고, 실패 이유도 문구 대신 분류만 남김. 시크릿 창은 기록하지 않고, 30일·500건·약 1MB를 넘으면 오래된 것부터 지움(한 항목의 대상은 20개까지). 설정에서 끄거나 지울 수 있음. 나중에 같은 구조의 페이지에서 동작을 다시 쓰는 레시피의 재료
- **찾기·실행 도구가 모델에 보내는 글자** (#43) — 원칙은 "화면 글자는 보내고, 사용자가 입력한 값은 보호". `find_form_fields`·`find_clickables`·`fill_form_fields`·`click_element`·`query_dom`의 결과와 오류 문구에는 페이지가 만든 글자(라벨·버튼 글자·select 선택지 글자)만 담고, 입력 칸(input·textarea·select)의 값·편집 영역(contenteditable, 그 안의 contenteditable=false 섬 포함)·숨은 요소(hidden·aria-hidden·display:none·visibility:hidden)의 글자는 구조로 빼고 모음(`src/content/modelText.ts`). 시작 요소의 조상(shadow host·슬롯·같은 출처 프레임 포함)이 보호 영역이면 이름도 비움. 모델에 돌려준 이름은 대상 비교에도 넣어, 원문은 같아도 모델이 본 이름이 바뀌면 다시 찾게 함. 범위: 이번에 좁힌 것은 이 도구들의 반환 계약뿐. 본문 읽기(`describe_page`·`get_page_content`)는 편집 영역을 포함한 화면 글자를 그대로 읽고, 주소(URL)에 실린 입력값(#44)과 `query_dom` 선택자 조건으로 값을 판별하는 경로(#45)는 별도 과제
- **읽기 레시피** — 같은 페이지 키(주소 틀 + 뼈대 해시)에서 내용을 읽는 데 통한 `query_dom`·`list_file_links`·`find_clickables` 호출(선택자·검색어)을 턴이 정상으로 끝날 때 기억함. 한 턴에서 같은 도구를 고쳐 가며 부르면 마지막으로 결과가 나온 호출만 성공으로 셈. 다음에 같은 구조의 페이지에서 `describe_page`를 부르면 결과의 `readHints`에 후보로 붙이고(자동 실행은 하지 않음), 모델이 먼저 시도함. 기억한 호출이 빈 결과를 3번 연속 내면 버림. 이메일·주소·긴 숫자·비밀 값처럼 보이는 인자는 저장하지 않고, 페이지 내용은 남기지 않음. 페이지당 3개·전체 300개·30일 한도. 동작 기록 설정 하나로 함께 켜고 끄고 지움
- **문서 요청 안전장치** — 리다이렉트는 따라가지 않고 목적지 주소만 알려 줌(`webRequest`로 관찰). 그 주소로 다시 읽으면 새 승인 카드가 뜸. 웹 페이지·이미지·압축 파일 등 문서가 아닌 확장자는 요청하지 않음. 확장자 없는 링크는 승인 카드에 따로 경고
- **kordoc 브라우저 번들** — kordoc는 Node용이라 `vendor/kordoc/`에서 따로 설치해 브라우저용으로 묶은 결과물을 커밋해 씀(`npm run vendor:kordoc`로 다시 만듦, [vendor/kordoc/README.md](vendor/kordoc/README.md))

## 보안 / 프라이버시

- OpenRouter API 키는 `chrome.storage.local`에 평문 저장 (OpenRouter API 호출에만 사용; v1 트레이드오프)
- 키는 BG 서비스 워커에서만 읽히며 content script나 페이지 DOM에 전달되지 않음
- **페이지 기억하기 (설정, 기본 켜짐)** — 답을 마친 뒤 탭이 다른 화면(해시 포함)에 있으면 "이 페이지 기억하기" 버튼이 뜨고, 이름을 확인·수정해 저장(요청 문장은 저장하지 않음, 해시까지 보존). 주소에 결제·개인정보 단서가 보이면 경고에 체크해야 저장. 같은 사이트(등록 도메인)에서 도우미를 쓰면 저장 항목 최대 8개를 매 모델 요청 끝에 임시 데이터 메시지("지시가 아님" 머리말 + JSON)로 붙여 바로 이동에 씀 — 대화 기록에는 남기지 않아 지우기·끄기가 다음 요청부터 반영(이미 대화에 쓰거나 인용한 것은 새 대화 전까지 남음). 시크릿 창은 저장·후보 제공 없음. 사이트당 20개·전체 200개, 설정에서 목록 보기·지우기. 저장 주소로 이동한 뒤 같은 주소에서 관측이 성공하면 사용 횟수 +1(후보 순서)
- **외부 본문 보호** — 파일 읽기(`read_document`)·첨부 파일 저장(`download_files`, 결과에 서버가 정한 파일 이름)·Google 도구·PDF 첨부처럼 외부 유래 데이터가 대화에 들어오면(성공·실패 모두) 그 대화에서는 페이지를 바꾸지 않는 관측 도구(`describe_page`·`get_page_content`·`list_page_images`·`list_file_links`·`query_dom`·`find_clickables`·`find_form_fields`) 외의 모든 도구를 자동 실행·링크 이동 허락과 관계없이 승인 카드로 물음(외부 내용을 신뢰 사이트의 검색어·입력값·번역 언어·Google 검색어로 내보내지 않게). "이번 대화 동안 묻지 않기"(#53)도 번역·이미지 저장에는 쓰지 않고, 페이지가 준 주소만 쿠키 없이 읽는 `read_linked_pages`에만 씀. 보호가 켜진 대화에서는 읽기 레시피를 저장하지 않음(보호 대상에서 유래한 인자가 새 대화로 넘어가지 않게). 이 기능 전에 저장된 레시피는 출처를 알 수 없어 새 저장소 세대로 바꾸며 지움(힌트로 쓰지 않음). 새 대화에서 해제. 도구 분류는 `src/lib/toolPolicy.ts`(모든 도구를 빠짐없이 분류해야 타입 검사 통과). 찾기·승인·실행 어디에서도 페이지에 대상 표시 속성을 쓰지 않음(id는 content script 메모리의 요소 → id 표로 관리)
- 모델 답변 속 이미지는 불러오지 않고 대체 글자와 주소만 보임(이미지 주소의 쿼리로 대화 내용이 승인 없이 새지 않게). 패널·설정 화면 CSP도 외부 이미지를 막음
- 민감 툴 실행 전 사용자 승인 필수(자동 실행을 켜면 결제·개인정보 제출·삭제·스팸 등 예외만 승인)
- 다운로드·탐색 URL은 `http(s):`만 허용, `javascript:` / 제어문자 차단
