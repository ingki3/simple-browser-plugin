# 간편 브라우저 도우미 (Simple Browser Plugin)

Chrome Side Panel에 탑재되는 OpenRouter 기반 채팅 에이전트입니다. 현재 탭의 페이지를 이해하고, 사용자의 자연어 요청을 ReAct 패턴으로 해석해 사이트 이동·번역·폼 채우기·이미지 다운로드·링크 클릭 등 실제 동작을 수행합니다.

## 주요 기능

- **채팅 기반 ReAct 에이전트** — 요청을 받으면 `describe_page`로 먼저 페이지를 관측하고, 필요한 도구를 체인 호출한 뒤 결과를 답변
- **페이지 조작 도구**
  - `describe_page` — 랜드마크(main/article/nav/aside/header/footer)별 텍스트 미리보기·대표 링크 스냅샷. 같은 구조의 페이지에서 전에 통한 읽기 방법이 있으면 함께 알려 줌
  - `get_page_content` — Readability 스타일 본문 추출
  - `translate_page` — 가시 텍스트 노드 단위 번역 교체 + MutationObserver 동적 재번역
  - `find_form_fields` / `fill_form_fields` — 입력 필드 탐색·자동 입력, 칸마다 반영 여부 확인 (승인 카드). 찾기 결과에 사용자가 입력한 값은 담지 않음(글자 칸은 값 유무, checkbox·radio는 체크 여부, select는 선택지 글자와 선택 위치). select는 보이는 글자가 정확히 하나와 같을 때만 그 선택지 자체를 고름, checkbox·radio는 true/false로만 지정
  - `list_page_images` / `download_images` — 이미지 URL 수집·일괄 저장 (승인 카드)
  - `find_clickables` / `click_element` — 링크·버튼 탐색·클릭, 클릭 뒤 이동·화면 변화 보고 (승인 카드). 검색어를 `주문|배송|마이페이지`처럼 `|`로 묶으면 맞은 낱말이 많은 순으로 반환. 목록에서 고르는 위젯(role=option·menuitem*·tab, 선택 팝업 트리거 role=combobox·aria-haspopup=listbox — 편집형 입력 칸은 제외)도 찾아 트리거 클릭 → 다시 찾기 → 선택지 클릭으로 고름. 글자가 같아도 요소마다 따로 돌려주고, 각 대상에 묶음 문맥(`context`: 대상이 든 행·패널의 화면 글자, 구조로 찾은 표제를 앞에)과 상태(`states`: selected·checked·pressed·expanded·current·disabled)를 붙임
  - `navigate_to_url` — 현재 탭을 지정한 URL이나 사이트 홈으로 직접 이동 (승인 카드). 새 탭·설정 같은 브라우저 내부 페이지(chrome://·edge://·about:)에서도 http(s) 주소로는 이동함. 내부 페이지에서는 페이지를 읽거나 조작하는 도구가 "웹 페이지로 먼저 이동하세요" 오류를 내고, 모델은 관측 없이 이동부터 함
  - `query_dom` — CSS 선택자 기반 DOM 조회. 화면 글자와 정해 둔 구조 속성(href·role·aria-selected 등)만 돌려줌
  - `get_youtube_transcript` — YouTube 영상의 "스크립트 표시" 패널을 열어 타임스탬프 포함 자막 추출
  - `list_file_links` — 페이지의 첨부·다운로드 파일 링크와 짐작한 형식 목록
  - `read_linked_pages` — 지금 페이지에 있는 링크(기사 등)를 탭 이동 없이 받아 본문 읽기 (선택 카드, 최대 8개). 페이지의 a[href]에 실제로 있는 주소만(모델이 만든 주소 거절), 로그인 쿠키 없이. 리다이렉트(#47)는 webRequest로 목적지를 관찰해 원래 링크와 같은 사이트(등록 도메인, http→https 승격 포함) 안이면 최대 3번 새 요청으로 따라가고(단계마다 http(s)·계정 정보·결제·개인정보 주소 신호·루프 검사, 쿠키는 계속 싣지 않음), 다른 사이트면 따라가지 않고 목적지를 알림 — 그 목적지는 이번 요청(턴)·이 탭 동안만(최대 16개) 기억해 모델이 그 주소로 다시 부르면 새 승인 카드(다른 사이트·원래 링크 표시)의 후보가 됨. 결제·개인정보 신호가 있는 목적지는 따라가지도 기억하지도 않음. 실패는 리다이렉트(목적지)·HTTP 상태·네트워크 오류로 나눠 알리고, 401·403·429는 blocked로 표시해 클릭 없이 navigate_to_url 한 번으로 열어 읽도록 안내. 결제·개인정보 신호가 있는 주소는 경고와 함께 기본 미선택, 다른 사이트 표시. 받아 온 HTML은 offscreen 문서의 DOMParser로 파싱해(스크립트 실행·하위 자원 요청 없음, offscreen CSP로 외부 자원 차단) 본문을 뽑음 — 요소 수·깊이·순회 글자 예산과 글자 상한으로 작업량 제한, 기사당 4,000자·전체 24,000자, 짧은 본문은 short 표시. 읽으면 외부 본문 보호가 켜짐
  - `read_other_tabs` — 같은 창의 다른 탭 본문 읽기 (선택 카드). 탭 목록은 모델에 보내지 않고, 카드를 띄우기 전에 후보(탭·최상위 문서·주소)를 고정해 패널에만 제목·사이트를 보임. 사용자가 고른 탭(최대 5개)만, 승인 직후 같은 창·시크릿 아님·로딩 완료·같은 문서·같은 주소인지 다시 확인하고 그 문서에서만 읽음(바뀌었으면 읽지 않음, 재주입 없음). 탭당 12,000자·전체 40,000자, 한 요청 2번까지. 읽으면 외부 본문 보호가 켜짐
  - `read_document` — 링크된 파일을 화면 이동 없이 내려받아 텍스트로 읽기 (브라우저 안에서 처리, 최대 20MB, 한 요청에 5개까지) (승인 카드)
    - Word·Excel·PowerPoint(.docx/.xlsx/.pptx), OpenDocument(.odt/.ods/.odp) → Markdown ([docling.rs-wasm](https://github.com/docling-project/docling.rs))
    - PDF → 쪽별 글자 ([pdf.js](https://github.com/mozilla/pdf.js)), 한글(.hwp/.hwpx) → Markdown ([kordoc](https://github.com/chrisryugj/kordoc)), CSV/TSV → Markdown 표(구분자 자동 판별, 설정한 글자 수 한도에서 멈춤 — 기본 40,000자, 1,000~100,000), TXT/MD → 원문
    - 확장자 없는 다운로드 링크(`download.do?fileId=…`)는 응답 헤더와 파일 서명으로 형식 판별. CSV·TXT의 EUC-KR(CP949) 자동 인식
- **목표 페이지 찾아가기** — "배송 상황 확인해줘"처럼 지금 페이지에 없는 정보를 물으면 마이페이지 → 주문/배송 조회처럼 링크를 2~4단계 따라가며 찾고, 막다른 페이지면 직전 주소로 돌아가 다른 후보를 시도. 답에 거쳐 온 경로를 밝힘. 로그인 화면에서는 멈추고, 결제·주문하기 버튼은 경로로 쓰지 않음. 자동 실행에서도 주문 조회 링크(글자·주소에 '주문'·order가 있는 링크)는 결제 판정 규칙에 걸려 승인 카드를 띄움(카드의 "이번 요청 동안 링크 이동 묻지 않기"로 나머지 단계는 묻지 않게 할 수 있음). 페이지마다 도구를 2~3회 쓰므로 도구 호출 한도 기본값을 16으로 올림(이 버전 전에 저장된 설정의 8은 예전 기본값으로 보고 16으로 읽음. 이후 설정 화면에서 8로 저장하면 그대로 씀)
- **민감 작업 승인 UI** — 사이트 이동·폼 입력·다운로드·클릭 같은 페이지 상태 변경과 문서 URL 요청(쿠키 포함)은 실행 전 사이드 패널에 미리보기 카드를 띄워 사용자 승인을 받음
- **이번 요청 동안 링크 이동 허락** — 같은 사이트 안의 일반 링크(다른 페이지로 가는 `<a href>`, 감싼 링크·양식 제출·내려받기·ping 없음, 개인정보가 채워진 양식과 무관, 주소와 주변 양식의 제출 주소에 개인정보 없음)를 누르는 승인 카드에 "승인 + 이번 요청 동안 링크 이동 묻지 않기"가 함께 뜸. 고르면 그 요청이 끝날 때까지(중단·새 요청이면 끝) 같은 조건의 링크는 결제 문구 판정 없이 카드 없이 누름. 버튼·양식 제출·다른 사이트로 가는 링크는 계속 물음. 자동 실행 설정과 관계없이 쓸 수 있음. 링크의 클릭 처리기가 이동 대신 다른 동작을 할 수는 있어 사용자가 고른 요청 하나에만 적용
- **자동 실행 (설정, 기본 꺼짐)** — 켜면 페이지 이동·클릭·입력을 승인 카드 없이 실행하고 결과 카드에 "자동 실행"으로 표시. 그래도 다음은 카드를 띄움:
  - 결제·주문 버튼, 결제 화면(주소의 경로·쿼리·해시, 제목, 큰 제목, 버튼이 든 양식·대화상자에 결제 단서)의 버튼
  - 사용자가 고르지 않은 사이트에서의 동작. 이동·클릭·입력은 요청을 시작한 탭의 사이트와 이 대화에서 카드로 이동을 허락한 사이트 안에서만 자동(모델이 만든 주소·호스트 이름이나 낯선 페이지의 입력 칸으로 대화 내용이 새지 않게). 다른 사이트로 가는 링크 클릭과 다른 사이트로 제출하는 양식 버튼도 물음. 사이트 경계는 브라우저의 "같은 사이트"처럼 등록 도메인 기준(공개 접미사 목록 [tldts](https://github.com/remusao/tldts)로 확인된 것만: www.naver.com에서 shopping·mail.naver.com은 안, example.co.kr에서 other.co.kr은 밖, a.github.io와 b.github.io는 다름). 목록으로 확인되지 않는 접미사는 같은 호스트와 그 하위 도메인만 안. 공유 호스팅·접미사 자체·IP·localhost에서 시작한 경우는 같은 호스트만 안(script.google.com에서 www.google.com은 밖). github.io·s3.amazonaws.com·Apps Script·Google Docs/Forms 같은 공유 호스팅·사용자 콘텐츠 주소는 늘 물음. 같은 등록 도메인의 다른 하위 서비스로 가는 이동·클릭은 묻지 않으므로, 페이지 속 지시문이 같은 회사의 다른 서비스로 이동을 유도하는 경우는 막지 않음. 자동 이동·클릭으로 들어간 사이트는 신뢰 사이트가 되지 않음
  - 새 탭·설정 같은 내부 페이지에서 시작한 요청은 시작한 사이트가 없으므로, 이동은 이번 요청 글에 사용자가 직접 적은 웹 주소·도메인(`naver.com`, `https://…` 같은 주소 모양만 봄 — 사이트 이름 "네이버" 같은 낱말은 해당 없음, 이메일 주소의 도메인·주소 속 매개변수는 제외)과 등록 도메인이 같거나 이 대화에서 카드로 허락한 사이트일 때만 자동. 그렇게 이동하면 그 사이트를 이 요청의 사이트로 삼아 이후 클릭·입력도 자동 실행 범위로 씀. 내부 페이지에는 페이지 글이 없어 숨긴 지시문이 끼어들 수 없지만, 모델이 만든 주소로 대화 내용이 나갈 수 있어 이렇게 제한함. 외부 본문 보호 중에는 늘 물음
  - 가입·신청·제출·인증 버튼
  - 비밀번호·결제 정보·개인정보 칸(이름·연락처·이메일·주소·생년월일 등) 입력
  - 개인정보·비밀번호·결제 값이 채워진 양식 안의 버튼
  - 이미지 저장·파일 읽기·Google 문서 쓰기(예외 없이 늘 물음)

  카드에는 자동 실행하지 않은 이유가 붙음. 승인 뒤 실행 직전에 칸이 개인정보로 채워지거나 결제 화면으로 바뀌면 실행하지 않음. 판정은 버튼 글자·칸 이름·autocomplete 속성을 보는 규칙이라 놓칠 수 있고, 웹페이지에 숨긴 지시문이 모델을 속여 원치 않는 곳으로 이동하거나 누르게 할 수 있으므로 믿을 수 있는 사이트에서만 켜 두기를 권함
- **OpenRouter 모델 지원** — `provider/model` 형식의 모델 ID를 직접 선택하며, reasoning과 tool calling 결과를 실시간 스트리밍
- **생각 중 표시** — 모델이 추론하는 동안 추론 글자 대신 "생각 중…"과 움직이는 아이콘만 보임(도구 전 짧은 설명과 답변은 그대로). 설정의 "생각 과정 보기"를 켜면 추론 글자를 접이식 상자로 봄
- **사용자 기본 지침** — "모든 출력은 한글로" 같은 시스템 지침을 설정해 모든 대화에 적용
- **모델별 reasoning 호환성** — Gemini 3 계열의 필수 effort와 gpt-oss 출력 제한·스트림 종료 처리
- **고속 페이지 번역 경로** — 처리량 우선 provider routing, 대형 배치·중복 제거·메모리 캐시 적용
- **Shadow DOM + 동일 출처 iframe 커버리지** — 모든 툴이 shadow root와 iframe 내부까지 순회
- **PDF 이해** — 현재 탭이 PDF면 자동으로 내려받아 OpenRouter의 PDF file input으로 붙여 내용 기반 질의응답 가능 (최대 20MB)
- **디버그 타임라인** — 사이드 패널에서 🐞 버튼으로 BG·content·panel 이벤트를 실시간 추적, 복사 버튼으로 공유 가능

## 설치

1. 의존성 설치 및 빌드
   ```bash
   npm install
   npm run build
   ```
2. Chrome에서 `chrome://extensions` 열기 → 개발자 모드 활성화
3. "압축해제된 확장 프로그램 로드" 클릭 → `dist/` 폴더 선택
4. 최초 실행 시 설정(⚙)에서 [OpenRouter Keys](https://openrouter.ai/keys)에서 발급한 API 키와 사용할 모델 ID 입력 후 저장

## 사용 예시

- "이 페이지 번역해줘"
- "네이버 홈으로 이동해줘"
- "빈 입력칸 채워줘. 이름: 홍길동, 이메일: test@example.com"
- "이미지 전부 다운받아줘"
- "첫 번째 아티클로 이동해줘"
- "이 페이지 요약해줘"
- "PXG 골프공 검색해서 가장 싼 스토어로 이동해줘"

## 아키텍처

```
[Side Panel React UI] ⇄ long-lived port ⇄ [Background Service Worker] ⇄ tabs.sendMessage ⇄ [Content Script]
                                                    │
                                                    ├── OpenRouter Chat Completions API
                                                    ├── ReAct stream loop (reasoning_details 보존)
                                                    ├── Tool dispatcher (zod 인자 검증)
                                                    └── webNavigation 통합 (settle 대기)
```

### 주요 구성

- **Manifest V3** — `sidePanel`, `storage`, `scripting`, `activeTab`, `downloads`, `tabs`, `alarms`, `webNavigation`, `identity`, `offscreen`, `webRequest` 권한 + `host_permissions: ["<all_urls>"]`
- **Port 하트비트 + 자동 재연결** — MV3 서비스 워커 유휴 종료 대응
- **스트림 청크 무활동 워치독** (60초) + **초기 연결 타임아웃** (20초) + **툴별 타임아웃** (기본 30초, translate 180초)
- **webNavigation 기반 settle 대기** — URL 이동·클릭 직후 페이지 전환 중에 후속 툴이 경쟁 조건 만나지 않도록
- **문서 변환 격리** — `read_document`는 offscreen 문서 안의 Worker에서 변환하고(형식에 맞는 변환기만 불러옴), 10초가 지나거나 사용자가 중단하면 Worker를 강제 종료. zip 기반 문서(Office·OpenDocument·HWPX)는 직접 풀어 크기를 센 뒤(본문 6MB·전체 40MB) 다시 만들어 넘기며, 이미지 등 바이너리는 비워서 넘김. PDF(pdf.js 워커에 빌드 때 패치)와 HWP(zlib 셰임)도 압축 해제량에 한도를 둠(문서당 128MB·256MB). 1분 동안 쓰지 않으면 offscreen 문서를 닫음
- **클릭·입력 확인 경로** — `find_clickables`·`find_form_fields`가 준 id마다 그때의 대상 기술(역할·글자·주소·영역·목록 순번·대상이 든 행의 글자)을 content script 메모리에 둠. 승인 카드를 띄울 때 지금 요소가 그때와 같은지 확인해 사람이 알아볼 수 있게 보여 주고(비밀번호 칸은 값을 가림), 실행 직전과, 클릭은 스크롤·포커스 뒤 누르기 바로 앞에서 다시 승인한 기술과 같을 때만 실행. 요소가 다시 그려져 사라졌으면 비슷한 요소로 대신하지 않고 멈춤(다시 찾아 새로 승인). 클릭 대상은 모델에 준 묶음 문맥과 상태도 비교함(승인 뒤 이미 체크·펼침으로 바뀐 대상을 누르면 반대로 되므로 멈춤).
- **선택지와 트리거의 관계** (#43 B) — 선택지(option·menuitem*)는 펼쳐진(aria-expanded=true) 트리거와의 관계를 구조로만 정함: aria-controls/aria-owns로 선택지나 그 목록을 가리키는 펼친 트리거가 정확히 하나면 linked, 연결이 없고 펼친 트리거가 0~1개면 unlinked, 그 밖(펼친 트리거 둘 이상·연결 없음, 연결 둘 이상)은 어느 위젯의 선택지인지 정할 수 없어 클릭 대상으로 돌려주지 않음. 관계(트리거·목록 요소, 연결 방식, 트리거 기술)는 승인 카드 때·실행 직전·스크롤과 포커스 뒤에 다시 계산해 같아야 누름. 트리거의 위험 정보(결제 화면·개인정보가 채워진 양식·제출 주소 등)는 선택지와 따로 background로 보내 승인·사이트 판정을 양쪽 모두에 적용(포털로 그린 목록이라도 트리거가 결제 대화상자 안이면 카드). 트리거 자신이 다른 목록 안의 항목인 중첩 메뉴의 항목은 상위 트리거들의 위험을 따라가지 않으므로 자동 실행하지 않고 늘 카드로 물음. 한계: unlinked는 소속을 증명하지 않음 — ARIA 펼침 상태를 표시하지 않는 위젯이 같은 목록을 넘겨받는 경우는 구조로 구분할 수 없음(공유 팝업 안의 일반 버튼과 같은 한계). ARIA 역할이 없는 div·li 위젯, pointerdown·keydown에만 반응하는 위젯은 지원하지 않음 승인은 그 호출에 한 번만 쓰임. id에는 페이지마다 바뀌는 꼬리표가 붙어 이전 페이지의 id는 거부
- **실행 결과 확인** — 클릭 뒤 이동 종류(없음·페이지 안 위치(#)·같은 사이트·다른 사이트·오류), 페이지 안 주소 변경, 새 탭, 화면 변화(DOM 변경 수·대화상자)를 결과로 돌려줌. 입력은 페이지 처리가 끝날 틈(150ms)을 둔 뒤 칸마다 값을 다시 읽어 실제로 반영됐는지 알려 줌
- **동작 기록** — 승인한 클릭·입력마다 페이지 구분 키(주소 틀 + 페이지 뼈대 해시), 대상 요약, 결과(완료·일부 반영·직전 중단·실패·취소)를 `chrome.storage.local`에만 남김. 주소 틀은 사람이 붙인 이름처럼 보이는 경로 낱말만 남기고 숫자·토큰·이메일·한글 이름 같은 칸은 자리표시로 바꾸며, 쿼리는 이름만 남김(`/board/{n}/view?id`). 대상 이름에 섞인 주소·이메일·key=value·긴 숫자·비밀 값처럼 보이는 낱말도 가림. 입력 칸은 이름 글자 대신 해시만 남기고(값·숫자를 지운 뒤 계산), 비밀번호·결제 칸은 해시도 남기지 않음. 뼈대 해시는 랜드마크·목록·표·폼의 중첩만 보고 같은 틀의 목록 항목은 하나로 접어, 내용과 항목 수가 달라도 같은 값. 입력 값, 대상이 든 행의 글자, 링크 주소의 값은 남기지 않고, 실패 이유도 문구 대신 분류만 남김. 시크릿 창은 기록하지 않고, 30일·500건·약 1MB를 넘으면 오래된 것부터 지움(한 항목의 대상은 20개까지). 설정에서 끄거나 지울 수 있음. 나중에 같은 구조의 페이지에서 동작을 다시 쓰는 레시피의 재료
- **찾기·실행 도구가 모델에 보내는 글자** (#43) — 원칙은 "화면 글자는 보내고, 사용자가 입력한 값은 보호". `find_form_fields`·`find_clickables`·`fill_form_fields`·`click_element`·`query_dom`의 결과와 오류 문구에는 페이지가 만든 글자(라벨·버튼 글자·select 선택지 글자)만 담고, 입력 칸(input·textarea·select)의 값·편집 영역(contenteditable, 그 안의 contenteditable=false 섬 포함)·숨은 요소(hidden·aria-hidden·display:none·visibility:hidden)의 글자는 구조로 빼고 모음(`src/content/modelText.ts`). 시작 요소의 조상(shadow host·슬롯·같은 출처 프레임 포함)이 보호 영역이면 이름도 비움. 모델에 돌려준 이름은 대상 비교에도 넣어, 원문은 같아도 모델이 본 이름이 바뀌면 다시 찾게 함. 범위: 이번에 좁힌 것은 이 도구들의 반환 계약뿐. 본문 읽기(`describe_page`·`get_page_content`)는 편집 영역을 포함한 화면 글자를 그대로 읽고, 주소(URL)에 실린 입력값(#44)과 `query_dom` 선택자 조건으로 값을 판별하는 경로(#45)는 별도 과제
- **읽기 레시피** — 같은 페이지 키(주소 틀 + 뼈대 해시)에서 내용을 읽는 데 통한 `query_dom`·`list_file_links`·`find_clickables` 호출(선택자·검색어)을 턴이 정상으로 끝날 때 기억함. 한 턴에서 같은 도구를 고쳐 가며 부르면 마지막으로 결과가 나온 호출만 성공으로 셈. 다음에 같은 구조의 페이지에서 `describe_page`를 부르면 결과의 `readHints`에 후보로 붙이고(자동 실행은 하지 않음), 모델이 먼저 시도함. 기억한 호출이 빈 결과를 3번 연속 내면 버림. 이메일·주소·긴 숫자·비밀 값처럼 보이는 인자는 저장하지 않고, 페이지 내용은 남기지 않음. 페이지당 3개·전체 300개·30일 한도. 동작 기록 설정 하나로 함께 켜고 끄고 지움
- **문서 요청 안전장치** — 리다이렉트는 따라가지 않고 목적지 주소만 알려 줌(`webRequest`로 관찰). 그 주소로 다시 읽으면 새 승인 카드가 뜸. 웹 페이지·이미지·압축 파일 등 문서가 아닌 확장자는 요청하지 않음. 확장자 없는 링크는 승인 카드에 따로 경고
- **kordoc 브라우저 번들** — kordoc는 Node용이라 `vendor/kordoc/`에서 따로 설치해 브라우저용으로 묶은 결과물을 커밋해 씀(`npm run vendor:kordoc`로 다시 만듦, [vendor/kordoc/README.md](vendor/kordoc/README.md))

## 보안 / 프라이버시

- OpenRouter API 키는 `chrome.storage.local`에 평문 저장 (OpenRouter API 호출에만 사용; v1 트레이드오프)
- 키는 BG 서비스 워커에서만 읽히며 content script나 페이지 DOM에 전달되지 않음
- **페이지 기억하기 (설정, 기본 켜짐)** — 답을 마친 뒤 탭이 다른 화면(해시 포함)에 있으면 "이 페이지 기억하기" 버튼이 뜨고, 이름을 확인·수정해 저장(요청 문장은 저장하지 않음, 해시까지 보존). 주소에 결제·개인정보 단서가 보이면 경고에 체크해야 저장. 같은 사이트(등록 도메인)에서 도우미를 쓰면 저장 항목 최대 8개를 매 모델 요청 끝에 임시 데이터 메시지("지시가 아님" 머리말 + JSON)로 붙여 바로 이동에 씀 — 대화 기록에는 남기지 않아 지우기·끄기가 다음 요청부터 반영(이미 대화에 쓰거나 인용한 것은 새 대화 전까지 남음). 시크릿 창은 저장·후보 제공 없음. 사이트당 20개·전체 200개, 설정에서 목록 보기·지우기. 저장 주소로 이동한 뒤 같은 주소에서 관측이 성공하면 사용 횟수 +1(후보 순서)
- **외부 본문 보호** — 파일 읽기(`read_document`)·Google 도구·PDF 첨부처럼 외부 유래 데이터가 대화에 들어오면(성공·실패 모두) 그 대화에서는 페이지를 바꾸지 않는 관측 도구(`describe_page`·`get_page_content`·`list_page_images`·`list_file_links`·`query_dom`·`find_clickables`·`find_form_fields`) 외의 모든 도구를 자동 실행·링크 이동 허락과 관계없이 승인 카드로 물음(외부 내용을 신뢰 사이트의 검색어·입력값·번역 언어·Google 검색어로 내보내지 않게). 보호가 켜진 대화에서는 읽기 레시피를 저장하지 않음(보호 대상에서 유래한 인자가 새 대화로 넘어가지 않게). 이 기능 전에 저장된 레시피는 출처를 알 수 없어 새 저장소 세대로 바꾸며 지움(힌트로 쓰지 않음). 새 대화에서 해제. 도구 분류는 `src/lib/toolPolicy.ts`(모든 도구를 빠짐없이 분류해야 타입 검사 통과). 찾기·승인·실행 어디에서도 페이지에 대상 표시 속성을 쓰지 않음(id는 content script 메모리의 요소 → id 표로 관리)
- 모델 답변 속 이미지는 불러오지 않고 대체 글자와 주소만 보임(이미지 주소의 쿼리로 대화 내용이 승인 없이 새지 않게). 패널·설정 화면 CSP도 외부 이미지를 막음
- 민감 툴 실행 전 사용자 승인 필수(자동 실행을 켜면 결제·개인정보 제출 등 예외만 승인)
- 다운로드·탐색 URL은 `http(s):`만 허용, `javascript:` / 제어문자 차단
