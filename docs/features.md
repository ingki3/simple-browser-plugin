# 기능 상세

사용자용 소개는 [README](../README.md)에 있습니다. 이 문서는 기능마다 동작 규칙과 구현 결정을 적은 개발 기록입니다(괄호의 `#번호`는 GitHub 이슈).

- **설정** (#99) — 사이드 패널의 설정(⚙) 한 곳에서 묶음별로(시작하기·동작·기억·기록·연결·고급, 시작하기만 펼쳐 둠) 바꾸고, 바꾸면 바로 저장(글자 칸은 입력이 멈추면·닫을 때, API 키만 저장 버튼). 설명은 한 줄 요약에 "자세히". 확장 옵션 페이지는 사이드 패널로 안내만 함
- **채팅 기반 ReAct 에이전트** — 요청을 받으면 `describe_page`로 먼저 페이지를 관측하고, 필요한 도구를 체인 호출한 뒤 결과를 답변
- **페이지 조작 도구**
  - `describe_page` — 랜드마크(main/article/nav/aside/header/footer)별 텍스트 미리보기·대표 링크 스냅샷. 같은 구조의 페이지에서 전에 통한 읽기 방법이 있으면 함께 알려 줌
  - `get_page_content` — Readability 스타일 본문 추출
  - `translate_page` — 가시 텍스트 노드 단위 번역 교체 + MutationObserver 동적 재번역
  - `find_form_fields` / `fill_form_fields` — 입력 필드 탐색·자동 입력, 칸마다 반영 여부 확인 (승인 카드). 자동완성 칸(트리거 role=combobox·aria-haspopup인 텍스트 input·textarea — aria-autocomplete 단독·datalist는 범위 밖)은 `fill_form_fields`에서 한 호출에 하나만 채우고 그 뒤 칸은 쓰지 않으며("한 번에 하나씩" note), 다른 칸의 목록이 이미 열려 있으면 채우지 않음. 채운 자동완성 칸이 펼쳐지면 `listOpened`와 "선택지를 고르라"는 note(관측 상태일 뿐 선택 확정 아님). 자동 로그인(`sign_in`)에는 이 순서 규칙을 쓰지 않음. 한계: 칸 묶음에 글자가 전혀 없으면 입력 뒤 목록이 생기며 행이 새로 잡혀 '행 내용 바뀜'으로 반영을 확인하지 못할 수 있음. 찾기 결과에 사용자가 입력한 값은 담지 않음(글자 칸은 값 유무, checkbox·radio는 체크 여부, select는 선택지 글자와 선택 위치). select는 보이는 글자가 정확히 하나와 같을 때만 그 선택지 자체를 고름, checkbox·radio는 true/false로만 지정. 각 칸에 행 문맥(`context`: 칸이 든 행·묶음의 화면 글자, 입력값 제외)을 붙여 라벨 없는 행 체크박스(메일 목록 등)를 구분함. 화면에서 숨긴 checkbox·radio도 구조로 연결된 보이는 label(for·감싼 label, 링크·버튼 안이 아닌 것)이 있으면 돌려줌. checkbox·radio 채우기는 사용자가 누를 때처럼 칸 자신에 상태를 쓰고 click → input → change를 보냄(click만 듣는 필터 대화상자에도 반영됨, label에는 click을 보내지 않음). click은 브라우저 활성화 동작을 일으키지 않는 이벤트로 보내 input·change는 늘 확장이 보내며, click 처리기 뒤·input 처리기 뒤에 재확인해 막히면 input·change를 아예 보내지 않음. 페이지가 click을 취소하면 체크를 되돌리고 applied:false로 알림. 누르는 동작이라 같은 칸을 click_element로 누를 때의 위험 신호(감싼 링크·ping·내려받기·htmx 클릭 요청 등)도 승인 판정과 재확인에 넣음. 이런 대리 label 칸은 자동 실행을 켜도 늘 승인 카드로 물으며, 카드에 '보이지 않는 칸' 경고와 보이는 label의 표시 이름을 보여 줌(aria-labelledby 참조 포함, 승인 뒤 바뀌면 실행하지 않음). 승인 카드는 이름 없는 칸·이름이 겹치는 칸에 행 문맥을 함께 보여 줌
  - `list_page_images` / `download_images` — 이미지 URL 수집 → 지정한 이미지 저장 (선택 카드, 아래 "지정한 이미지·첨부 파일 내려받기")
  - `download_files` — 페이지의 첨부·다운로드 파일 링크 저장 (선택 카드, 로그인 쿠키 포함, 최대 20개)
  - `capture_page` — 보고 있는 페이지를 PNG로 캡처해 저장: 보이는 화면, 또는 `fullPage`로 스크롤해 페이지 전체 (승인 카드, 아래 "페이지 캡처")
  - `find_clickables` / `click_element` — 링크·버튼 탐색·클릭, 클릭 뒤 이동·화면 변화 보고 (승인 카드). 클릭으로 대화상자(`dialog[open]`·role=dialog/alertdialog·aria-modal)가 새로 열리면 그 화면 글자를 `effect.dom.dialog`(modelText 600자, 입력 칸 값·편집 영역 제외 #43, 잘림 표시)로 싣고, 같은 문서 안 주소 변경(필터·정렬 등)이면 "목록이 다시 그려졌을 수 있으니 목록 항목은 다시 찾으라"는 문구를 결과 `note`에 붙임(#158). 스크립트로 누를 때(실제 입력 꺼짐, 또는 실제 입력이 덮개 때문에 스크립트로 바꿀 때) 대상이 열린 목록·대화상자(역할 listbox·menu·dialog, dialog[open], aria-modal, 펼친 트리거의 aria-controls 대상 — 합성 트리 조상)에 덮여 있으면 `effect.dom.covered`와 "그 목록에서 고르거나 닫은 뒤 다시 누르라"는 note(진단 — 클릭은 지금처럼 함). 지침은 같은 버튼 반복만 예전 id를 쓰고, 목록을 바꾸는 클릭 뒤 목록 항목·대화상자 내용은 다시 보고 판단하게 함. 검색어를 `주문|배송|마이페이지`처럼 `|`로 묶으면 맞은 낱말이 많은 순으로 반환. 찾기 조건(query·region·onlyViewport) 때문에 0개가 되면 결과를 `{items: [], note}`로 바꿔 조건 없이 찾을 수 있는 요소 수를 알림(#151, 수만 알리고 동작은 그대로). 디버그 로그 `tool:find_clickables:args`에 찾기 조건(query 앞 40자·region·onlyViewport)을 남김(#152). `matchContext: true`면 query를 대상이 든 묶음 글자(context — modelText 경로)에도 맞추고, context가 200자 한도에서 잘렸으면 `contextTruncated`(#159). `mode: "items"`(#161)는 반복 목록 항목마다 화면 글자(안쪽 항목 제외, 400자, 입력값·편집 영역·숨은 글자 제외)와 그 안의 대상(최대 8개, 넘으면 `moreTargets`)을 묶어 돌려줌. 항목 경계는 구조로만: 대상에서 위로 10단계 안에서 같은 태그·같은 모양 형제가 2개 이상인 조상 중 그 수가 가장 큰 것(같으면 안쪽, 합치기 없음 — 섹션 제목 링크는 섹션 항목, 상품 링크는 상품 항목). 항목이 없는 대상은 `outside` 수만. 순서: 안전한 후보 수집(같은 제외 규칙, region은 여기서, 3,000개 상한 — 넘으면 `scanLimited`와 안내) → 항목 묶기 → query(항목 글자 1·대상 글자 2·주소 1)·onlyViewport → limit(기본 20, 최대 60)·글자 예산 16,000자(넘친 수 `omittedItems`) → 남은 대상만 id 발급(선택지는 트리거 관계 그대로). 항목으로 돌려준 대상은 항목 요소·안쪽 항목·항목 글자를 등록에 결합해, 승인 카드·실행 직전·실제 입력 누르기 직전·손 넘기기 확인에서 항목이 다시 그려졌거나 글자가 바뀌었으면 "다시 찾으세요"로 실행하지 않음(행 내용 바뀜 안내 뒤 같은 id로 다시 불러도 막힘). 한계: 카드 수보다 같은 모양 버튼 수가 많은 작은 목록은 버튼이 각자 항목이 됨(잘못된 짝은 생기지 않음). `query_dom`은 `tool:query_dom:args`에 선택자(120자)·attr(#156). 목록에서 고르는 위젯(role=option·menuitem*·tab, 선택 팝업 트리거 role=combobox·aria-haspopup=listbox — 편집형 입력 칸은 제외)과 체크 위젯(role=checkbox·switch·radio, 진짜 checkbox·radio — 화면에서 숨긴 칸은 대신 보여 주는 label(그 label 클릭은 자동 실행해도 늘 묻고, 판정에 숨긴 칸 쪽 위험 신호와 연결된 모든 label의 전체 글자를 넣음), 지금 체크 상태는 `states.checked`)도 찾아 트리거 클릭 → 다시 찾기 → 선택지 클릭으로 고름. 글자가 같아도 요소마다 따로 돌려주고, 각 대상에 묶음 문맥(`context`: 대상이 든 행·패널의 화면 글자, 구조로 찾은 표제를 앞에)과 상태(`states`: selected·checked·pressed·expanded·current·disabled)를 붙임
  - `navigate_to_url` — 현재 탭을 지정한 URL이나 사이트 홈으로 직접 이동 (승인 카드). 새 탭·설정 같은 브라우저 내부 페이지(chrome://·edge://·about:)에서도 http(s) 주소로는 이동함. 내부 페이지에서는 페이지를 읽거나 조작하는 도구가 "웹 페이지로 먼저 이동하세요" 오류를 내고, 모델은 관측 없이 이동부터 함. 주소가 열리지 않아 Chrome 오류 화면(없는 도메인·인증서 오류 등)이 뜨면, 페이지 도구는 "주입할 수 없음" 대신 `webNavigation.onErrorOccurred`의 오류 코드와 출처(scheme://host, 경로·쿼리 제외)를 알리고 짐작한 주소로 거듭 이동하지 말고 검색하거나 사용자에게 물으라고 안내(`src/lib/navError.ts`). 판단은 Chrome 오류 코드로만 하며, 기록은 탭 주소가 실패한 주소와 같을 때만 씀
  - `query_dom` — CSS 선택자 기반 DOM 조회. 화면 글자와 정해 둔 구조 속성(href·role·aria-selected 등)만 돌려줌. 값에 기대는 선택자 조건은 거부(#45)
  - `get_youtube_transcript` — YouTube 영상의 "스크립트 표시" 패널을 열어 타임스탬프 포함 자막 추출
  - `list_file_links` — 페이지의 첨부·다운로드 파일 링크와 짐작한 형식 목록. 읽을 수 없지만 저장할 수 있는 파일(zip·구형 Office·이미지 등)은 `readable: false`·`ext`로 따로 표시(`download_files`용, `read_document` 판정은 그대로). 사용자 이름·비밀번호가 실린 주소는 이 목록·`list_page_images`·저장 후보 어디에도 넣지 않음
  - `read_linked_pages` — 지금 페이지에 있는 링크(기사 등)를 탭 이동 없이 받아 본문 읽기 (선택 카드, 최대 8개). 페이지의 a[href]에 실제로 있는 주소만(모델이 만든 주소 거절), 로그인 쿠키 없이. 리다이렉트(#47)는 webRequest로 목적지를 관찰해 원래 링크와 같은 사이트(등록 도메인, http→https 승격 포함) 안이면 최대 3번 새 요청으로 따라가고(단계마다 http(s)·계정 정보·결제·개인정보 주소 신호·루프 검사, 쿠키는 계속 싣지 않음), 다른 사이트면 따라가지 않고 목적지를 알림 — 그 목적지는 이번 요청(턴)·이 탭 동안만(최대 16개) 기억해 모델이 그 주소로 다시 부르면 새 승인 카드(다른 사이트·원래 링크 표시)의 후보가 됨. 결제·개인정보 신호가 있는 목적지는 따라가지도 기억하지도 않음. 실패는 리다이렉트(목적지)·HTTP 상태·네트워크 오류로 나눠 알리고, 401·403·429는 blocked로 표시해 클릭 없이 navigate_to_url 한 번으로 열어 읽도록 안내. 결제·개인정보 신호가 있는 주소는 경고와 함께 기본 미선택, 다른 사이트 표시. 받아 온 HTML은 offscreen 문서의 DOMParser로 파싱해(스크립트 실행·하위 자원 요청 없음, offscreen CSP로 외부 자원 차단) 본문을 뽑음 — 요소 수·깊이·순회 글자 예산과 글자 상한으로 작업량 제한, 기사당 4,000자·전체 24,000자, 짧은 본문은 short 표시. 읽으면 외부 본문 보호가 켜짐
  - `read_other_tabs` — 같은 창의 다른 탭 본문 읽기 (선택 카드). 탭 목록은 모델에 보내지 않고, 카드를 띄우기 전에 후보(탭·최상위 문서·주소)를 고정해 패널에만 제목·사이트를 보임. 사용자가 고른 탭(최대 5개)만, 승인 직후 같은 창·시크릿 아님·로딩 완료·같은 문서·같은 주소인지 다시 확인하고 그 문서에서만 읽음(바뀌었으면 읽지 않음, 재주입 없음). 탭당 12,000자·전체 40,000자, 한 요청 2번까지. 읽으면 외부 본문 보호가 켜짐
  - `read_document` — 링크된 파일을 화면 이동 없이 내려받아 텍스트로 읽기 (브라우저 안에서 처리, 최대 20MB, 한 요청에 5개까지) (승인 카드)
    - Word·Excel·PowerPoint(.docx/.xlsx/.pptx), OpenDocument(.odt/.ods/.odp) → Markdown ([docling.rs-wasm](https://github.com/docling-project/docling.rs))
    - PDF → 쪽별 글자 ([pdf.js](https://github.com/mozilla/pdf.js)), 한글(.hwp/.hwpx) → Markdown ([kordoc](https://github.com/chrisryugj/kordoc)), CSV/TSV → Markdown 표(구분자 자동 판별, 설정한 글자 수 한도에서 멈춤 — 기본 40,000자, 1,000~100,000), TXT/MD → 원문
    - 확장자 없는 다운로드 링크(`download.do?fileId=…`)는 응답 헤더와 파일 서명으로 형식 판별. CSV·TXT의 EUC-KR(CP949) 자동 인식
- **지정한 이미지·첨부 파일 내려받기** (#48) — "상품 사진 3번째부터 5번째까지 저장해 줘", "첨부 파일 중 PDF만 받아 줘"처럼 지정하면 모델이 `list_page_images`·`list_file_links`의 관측(순서·형식·alt·링크 글자)으로 어느 것인지 골라 `download_images`·`download_files`에 주소를 넘김(코드는 넘긴 주소만 쓰고 낱말 규칙으로 고르지 않음). 판정은 `src/lib/downloadPick.ts`(순수 함수, 단위 테스트)
  - 후보 고정: 카드를 띄우기 전에 넘긴 주소가 지금 페이지에 실제로 있는 이미지(`list_page_images`와 같은 수집)·링크(최상위 + 같은 출처 프레임 + 열린 shadow root의 `a[href]`·`area[href]`, 해시만 다른 주소는 같은 링크)인지 확인해 후보(id·주소)를 고정. 링크 존재 확인은 넘긴 주소를 문서 끝까지 찾음(카드에 함께 보일 링크 수 한도와 별개). 페이지에 없는 주소·http(s)가 아닌 주소·계정 정보가 실린 주소는 받지 않음(전부 없으면 카드 없이 오류, 섞이면 카드에 "받지 않는 주소"로 알림)

  - 받는 것은 사용자가 고른 고정 후보뿐: 패널은 후보 id만 돌려주고 백그라운드는 고정한 후보에 있는 id만 받아들이며, 실행은 모델 인자의 주소를 다시 쓰지 않음(패널 메시지로 임의 주소를 넣을 수 없음). 한 번 실행하면 후보를 버림
  - 파일 이름: 첨부 파일은 브라우저가 정한 이름(Content-Disposition → 주소)을 `onDeterminingFilename`에서 고른 폴더와 정리한 이름으로 바꿈(이 확장이 시작한 내려받기 중 기다리는 주소만, 내려받는 동안만 등록). 확장자가 없거나 서버 처리기 이름(.do·.php 등)이면 받은 형식(MIME)의 확장자를 붙이고, 이름이 없으면 `file-N`. 이미지는 주소의 이름(허락 경로의 data:는 받은 형식으로 확장자). 같은 이름은 uniquify(`report (1).pdf`). 이름 힌트는 실행마다 소유하고 다운로드 id로 묶어(id가 오기 전에 이름 정하기 이벤트가 오면 그 주소의 "시작 중" 힌트로 맞춤, 같은 주소의 시작만 한 번에 하나씩) 두 대화가 같은 주소를 다른 폴더로 받아도 섞이지 않음
  - 결과: 시작부터 끝날 때까지(최대 45초, 응답 헤더가 늦어 시작하지 못한 것도 이 안에서) 기다려 성공·실패 이유(401 로그인 필요·403·404·네트워크 등)와 저장 위치(다운로드 폴더 아래 `폴더/파일 이름` — 사용자 폴더 경로는 모델에 보내지 않음)를 돌려줌. 사용자가 중단하면 바로 끝내고 아직 받는 중이거나 중단 뒤에 늦게 시작된 내려받기는 취소함. 받은 것이 웹 페이지(HTML, 로그인 화면일 수 있음)·이미지가 아닌 응답이거나 다른 사이트로 리다이렉트되어 받았으면 note로 알림. 모델로 가는 이유·note는 고정된 분류 문구만 쓰고 서버가 정한 문자열(MIME·리다이렉트 목적지·오류 문구)은 싣지 않음. 이미지(외부 본문 보호를 켜지 않는 도구)의 저장 위치는 확장이 정한 이름과 uniquify 꼬리표만 알리고, 브라우저가 이름을 바꿨으면 그 이름 대신 note로 알림. 첨부 파일은 서버가 정한 이름(Content-Disposition) 그대로 알리고 보호를 켬
  - 안전: 첨부 파일은 로그인 쿠키가 필요한 경우가 많아 브라우저 다운로드(쿠키 포함, 리다이렉트를 따라감 — 사용자가 그 링크를 누른 것과 같음)로 받으므로 자동 실행·"이번 대화 동안 묻지 않기"의 대상이 아니고 늘 카드에서 고름(외부 본문 보호 중에도). 결과에 서버가 정한 파일 이름이 실려 실행하면 외부 본문 보호를 켬. 이미지의 "이번 대화 동안 묻지 않기"(#53)는 그대로 — 허락 경로는 모델이 넘긴 주소의 후보만(함께 보인 다른 이미지는 아님) 쿠키 없이·리다이렉트 없이 받은 이미지 바이트로 저장

  - 클릭 결과에 팝업을 보고: 클릭하는 동안만 페이지(MAIN world)의 `window.open`을 감싸 불린 주소와 null 반환을 세고(noopener 창은 열려도 null이라, null 반환 수가 그 클릭 동안 만들어진 탭·창 수보다 많을 때만 막힌 것으로 봄), 끝나면 원래 함수로 되돌림(`src/background/popups.ts`). 막혔으면 "새 창(팝업)을 열려 했지만 브라우저가 팝업을 막았습니다(주소) … 팝업 허용을 요청하거나 직접 선택해 달라고 안내하세요". 확장의 클릭은 사용자 활성화가 없어 실제 Chrome에서는 팝업 차단기에 걸리는 경우가 많음 — 사용자가 주소창의 차단 표시에서 그 사이트 팝업을 허용하면 이후에는 열림. 주소는 호스트·경로만(쿼리는 `?…`, 계정 정보 없음, 100자) 싣고 문구는 고정(`popupWhere`·`describePopup`, `src/lib/actionTarget.ts`)
  - 열린 팝업 창 따라가기: 클릭하는 동안 그 탭의 문서가 연 탐색 대상(`webNavigation.onCreatedNavigationTarget` — 탭 줄 opener가 없는 별도 창·noopener 창도, 보조로 `openerTabId`) 중 창 종류가 `popup`인 것만, 그 턴의 도구가 그 창에서 동작하게 함(결과에 "이제 도구는 팝업 창에서 동작합니다"). 사용자가 따로 연 창은 따라가지 않음(일반 새 탭은 아래 "클릭으로 열린 새 탭"). 창이 닫히면(달력이 고른 날짜를 원래 페이지에 써 넣고 닫힘) 원래 탭으로 돌아오고 그 클릭 결과나 다음 도구 결과(`tab`)에 알림. 팝업이 또 연 팝업은 3단계까지(팝업이 다음 창을 열고 닫히면 새 창을 따라감). 따라간 적 있는 창을 페이지가 같은 이름으로 다시 쓰면(`window.open(url, "calendar")` — 새 탭 없이 그 창이 이동) 이 클릭의 성공한 `window.open` 주소와 그 창의 이동 주소가 같을 때만 다시 따라감. 같은 원래 탭에서 시작한 다음 턴은 아직 열린 팝업을 이어 따라감(탭 머리말의 URL·제목·PDF 판별도 그 창 기준). 단 원래 탭이 따라가기를 시작할 때의 문서(최상위 `documentId`)가 아니면(다른 페이지로 옮겼거나 새로 고침) 잇지 않고 원래 탭에서 시작
  - 탭으로 열린 팝업: 팝업을 요청한 `window.open`을 브라우저가 같은 창의 일반 탭으로 여는 경우(macOS 창 전체 화면 등)도 따라감. 조건은 모두 구조로만 봄 — 이 클릭 동안 브라우저 관계로 새로 만들어진 탭이 정확히 하나, 성공한(창을 돌려준) `window.open` 기록이 정확히 하나이고 기록이 완전함(모든 프레임을 한도 안에서 읽음, 주소 2,000자·창 옵션 1,000자 이하), 그 호출의 창 옵션이 HTML 표준 "check if a popup window is requested"로 팝업 요청(noopener·noreferrer 제거 뒤 판정, `src/lib/popupMatch.ts`), 탭이 클릭한 탭과 같은 창에서 브라우저가 앞에 띄운 활성 탭이고 확정된 문서 주소가 그 호출 주소와 해시까지 같음. 크기 없는 `window.open`·`target=_blank`·noopener 창은 아래 "클릭으로 열린 새 탭" 규칙으로 봄. 따라가는 동안 도구마다 그 탭이 아직 그 창의 활성 탭이고 창이 내려가 있지 않은지 확인하고(아니면 작업하지 않고 사용자에게 앞에 띄워 달라고 안내), 첫 도구 전에는 따라가기 시작할 때의 문서인지도 확인(그 사이 바뀐 것이 모두 페이지가 스스로 넘긴 이동 — `webNavigation` 커밋의 `client_redirect` 표시, 뒤로 가기 제외 — 이면 넘어간 문서를 따라감. 광고 중간 주소처럼 로드를 마친 뒤 스크립트로 넘어가는 탭, #146. 사용자가 주소창·링크로 옮긴 이동이 끼면 그대로 막음). 다음 턴은 그 탭이 앞에 있을 때만 이어 따라가고(원래 탭은 기록한 원래 탭으로 유지), 원래 탭이 앞에 있으면 원래 탭에서 시작. `navigate_to_url`은 원래 탭을 앞으로 띄워 이동. 따라가지 않은 후보는 디버그 로그(`popup:skip`)에 이유를 남김(탭 id와 고정 문구만)
  - 클릭으로 열린 새 탭(0.2.26): `target=_blank` 링크·양식, 팝업을 요청하지 않은 `window.open`이 연 일반 새 탭도 따라감. 조건은 브라우저가 알려 준 사실로만 봄 — 이 클릭 동안 이 탭이 연 새 탭이 정확히 하나, 클릭한 탭과 같은 일반 창에서 브라우저가 앞에 띄운 활성 탭, 확정된 최상위 문서가 http(s)(열린 직후 이동은 5초까지 기다림, `newTabIneligible`). 뒤에 열린 탭(광고 탭 등)·여러 탭은 따라가지 않고 원래 탭에 남음. 따라간 뒤 규칙은 탭으로 열린 팝업과 같음(도구마다 앞에 보이는지 확인, 닫히면 원래 탭, `navigate_to_url`은 원래 탭을 앞으로 띄워 이동). 결과 문구는 "클릭으로 새 탭이 열려 앞에 떴습니다… 이제 도구는 그 새 탭에서 동작합니다"

    - 실제로 실릴 값: 누른 제출 버튼의 name=value(`<button name="action" value="delete">확인</button>`), 클릭·입력으로 바뀌는 checkbox·radio 자신의 name=value, 양식을 제출하면 실릴 선택 컨트롤(숨은 칸, 이미 체크된 checkbox·radio, select의 선택된 option의 value·글자)의 name=value(입력은 쓰기 전 상태로 판정). 누르지 않은 다른 제출 버튼의 값과 사용자가 치는 글자 칸·textarea의 값(검색어 등)은 보지 않음
    - htmx는 **허용 목록 방식**: htmx가 관여하면 기본은 "htmx 요청(GET 아님·확인할 수 없음)"으로 묻고, 카드 없이 자동 실행되는 것은 이번 클릭·입력이 일으킬 수 있는 htmx 요청 요소(대상·연결 컨트롤·제출자·양식에서 문서 끝까지의 경로, 페이지의 모든 `from:` 리스너 — 선택자를 해석하지 않고 열린 shadow root·같은 출처 iframe까지 찾음(닫힌 shadow root·다른 출처 iframe 안은 볼 수 없는 한계), hx-boost 적용 요소)와 그 조상의 htmx 속성(hx-*·data-hx-*)이 모두 {hx-get, hx-target, hx-swap, hx-select, hx-select-oob, hx-push-url, hx-replace-url, hx-indicator, hx-disabled-elt, hx-sync, hx-boost, hx-trigger(이벤트 필터 `[…]`와 `js:` 없음)} 안이고 요청이 GET(hx-get, hx-boost의 링크·GET 양식)일 때뿐. hx-get 없는 `from:` 리스너(hx-boost POST 양식 등)도 물음. htmx가 관여하는 경로에서는 양식의 method가 있으면 'get'이어야 하고, 경로의 모든 button·input(type 무관 — htmx는 type=button도 추적해 그 버튼의 덮어쓰기와 값을 씀)의 form* 속성은 formmethod=get·formaction(주소의 삭제 단서를 봄)·formnovalidate 밖이면 묻고, 그 name=value의 삭제 단서도 봄. htmx는 이전에 추적한 버튼의 덮어쓰기를 나중 요청에도 쓰므로, 경로에 htmx가 있거나 페이지에 `from:` 리스너가 있으면 페이지(접근 가능한 모든 루트)의 버튼 전체를 같은 규칙으로 봄(버튼이 2000개를 넘으면 모름). 통과한 GET 요청에도 주소·요청 요소 자신의 name=value(글자 칸·textarea는 이름만 — 입력값은 보지 않음)·양식이면 실릴 값의 삭제 단서 검사를 그대로 적용(묶음 입력이 승인한 선택 칸 쓰기는 제외). rails-ujs `data-params`의 글자에 삭제 단서가 있어도 물음. 경로가 1만 단계를 넘거나 from: 요소가 200개를 넘거나 양식 칸이 5000개를 넘거나 hx-get 주소가 풀리지 않으면 모르는 것으로 보고 물음
    - 자동 실행되는 htmx GET 요청도 그 목적지(hx-get 주소, 요청하는 양식의 action, htmx가 쓸 수 있는 버튼의 formaction)를 다른 목적지처럼 사이트 경계·결제·개인정보·삭제 주소로 검사함(클릭과 입력 모두, 승인 뒤 바뀌면 실행하지 않음, 50개를 넘으면 묻기)
    - 글자: 버튼 자신과 실제로 작동하는 바깥 버튼·링크(입력 칸은 라벨)의 글자·aria-label·title·alt에 삭제·지우기·제거·휴지통·스팸·차단·영구·비우기·탈퇴·delete·remove·trash·spam·junk·discard·erase·purge·block 등(아이콘 버튼은 aria-label·title로). select는 고를 선택지의 글자·value에 같은 단서가 있으면 물음(다른 선택지를 고르면 묻지 않음)
    - 주소: 링크·감싼 링크·양식 제출 주소(action·formaction)·ping·선택지 주소와 `navigate_to_url`의 이동 주소의 경로·쿼리 낱말
    - 선택지(메뉴 항목)는 펼친 트리거에도 적용. 행 문맥(메일 제목 등)은 보지 않아 제목에 '삭제'가 든 메일 행의 체크박스·열기 버튼은 그대로 자동 실행됨(그 행의 링크 글자 자체가 제목이면 물음). 범위 안 다른 양식·누르지 않은 제출 버튼의 주소는 보지 않음(목록 양식의 '삭제' 버튼 하나로 화면의 모든 체크가 걸리지 않게 — 처리기가 다른 양식을 대신 제출하는 삭제는 놓침)
    - "이번 요청 동안 링크 이동 묻지 않기"·"이번 대화 동안 묻지 않기"로도 건너뛰지 않고, 자동 실행이 꺼져 있어도 카드에 경고를 붙임. 승인 뒤 삭제 선언·실릴 값·삭제 선택지가 새로 생기면 실행하지 않음(같은 입력 묶음이 선택 칸에 쓴 상태(쓴 직후·페이지 처리기 전에 기록: select는 선택된 option 요소·그 value·선택 상태·select name, checkbox·radio는 name·value·checked)만으로 생긴 신호(실릴 값의 삭제 단서와 `<select name="_method">`의 DELETE 같은 구조 선언 모두)는 묶음의 모든 칸에서 예상된 변화로 보고 끝까지 실행 — 지금 상태가 기록과 하나라도 다르거나(처리기가 글자는 두고 value만 바꾼 경우 등) 그 칸들을 뺀 나머지로 신호가 생기면 멈춤)
    - 구조 선언 밖의 신호는 낱말·경로 단서라 더 묻는 쪽의 최선일 뿐 완전하지 않음(글자·주소·값 어디에도 단서가 없는 삭제는 놓침)
  - 비밀번호·결제 정보·개인정보 칸(이름·연락처·이메일·주소·생년월일 등) 입력
  - 개인정보·비밀번호·결제 값이 채워진 양식 안의 버튼
  - 이미지·첨부 파일 저장·파일 읽기·Google 문서 쓰기(자동 실행 대상이 아님. 이미지 저장은 위의 "이번 대화 동안 묻지 않기"로만 생략, 첨부 파일 저장은 늘 카드)

  카드에는 자동 실행하지 않은 이유가 붙음. 승인 뒤 실행 직전에 칸이 개인정보로 채워지거나 결제 화면으로 바뀌면 실행하지 않음. 판정은 버튼 글자·칸 이름·autocomplete 속성을 보는 규칙이라 놓칠 수 있고, 웹페이지에 숨긴 지시문이 모델을 속여 원치 않는 곳으로 이동하거나 누르게 할 수 있으므로 믿을 수 있는 사이트에서만 켜 두기를 권함
- **반복 작업** (#138) — 사용자가 "~마다 확인해서 ~하면 ~해 줘"라고 하면 모델이 `schedule_repeat_task`(제목·주소·조건·할 일·간격·기간·최대 횟수)를 부른다. 등록은 실행 방식·맡긴 작업·이번 대화 허락과 관계없이 **늘 카드**로 묻고(요청 원문·주소·조건·할 일·간격·끝·제공자로 보내는 것과 최대 호출 수를 보임), 승인은 맡긴 작업·대화 허락을 주지 않는다. 확인 중인 작업은 5개까지, 간격 1~1440분, 기간 1~168시간(기본 24), 최대 횟수 500(기본 기간÷간격).
  - 확인(`src/background/repeatTasks.ts`, 상태 전이는 `src/lib/repeatTask.ts`): 알람(`repeat:<id>`, 간격마다)과 등록 직후·"지금 확인"(작업마다 30초에 한 번)에 돈다. 확인할 때마다 등록한 주소로 새 비활성 탭을 열고 확인이 끝나면 닫는다(사용자가 그 탭을 앞으로 가져왔거나 등록한 사이트 밖으로 옮겼으면 닫지 않음). 사용자가 쓰는 탭을 다시 쓰거나 옮기지 않는다. 다 뜬 뒤 최종 주소가 등록한 사이트(등록 도메인) 밖이면 읽지 않는다. 문서(documentId)와 주소를 고정해 content의 `watch_snapshot`(제목, `modelText` 화면 글자 6000자, `findClickables`의 글자·역할·상태 80개 — 입력 칸 값·편집 영역 제외, #43)을 받고, 읽는 사이 문서·주소가 바뀌었으면 버린다. 자동 로그인 가림 목록을 읽지 못하면 보내지 않는다.
  - 판단: 제공자 `complete()` 한 번(JSON `{verdict: met|unmet|blocked|login_required|unknown, reason}`, 키 두 개·타입을 엄격히 검사, 아니면 unknown). 조건 판단은 모델이 하고 코드에 낱말 목록은 없다. met → 조건 맞음(알람 끔), blocked·login_required → 멈춤(사람이 그 사이트를 직접 열어 확인·로그인한 뒤 다시 시작), unknown·오류 3번 연속 → 멈춤, 기간이 지난 뒤 끝난 확인은 met이어도 끝남. 단계별 시간 제한(탭 30초, 글자 15초, 모델 25초)과 확인하는 동안 20초마다 확장 API 호출로 서비스 워커를 붙잡는다. 멈춤·지우기·새 실행이면 진행 중인 확인의 결과를 버린다(실행 토큰). 저장은 한 줄 큐로 처리하고, 서비스 워커가 뜰 때 켜진 작업의 알람을 다시 만든다.
  - 알림: 새 권한 없이 확장 아이콘 배지(조건이 맞은 작업 수)와 열린 패널의 띠. 다음 일은 사용자가 띠의 **이어서 진행**을 눌러야 시작한다: 백그라운드가 조건 맞음 → 이어서 진행함으로 한 번만 바꾸고(두 번째는 거절, 하루가 지난 결과는 멈춤으로 되돌림), 저장된 작업 내용(제목·주소·조건·할 일)만으로 첫 요청 글을 만들어, 등록한 주소로 연 새 탭에서 새 대화 객체로 시작한다(자동 실행 기준 사이트는 등록한 주소의 출처로 고정). 확인 결과의 이유는 페이지에서 유래한 글이라 띠·목록에 보이기만 하고 모델에 넣지 않는다. 이어서 진행한 대화의 승인은 그때 실행 방식 그대로다.
  - 관리: 설정 → 반복 작업(지금 확인·멈추기·다시 확인 시작·지우기, 마지막 확인 결과와 멈춘 이유).
- **텔레그램 연동 (선택, #139)** — 설정 → 텔레그램 연동에서 BotFather 봇 토큰을 저장(getMe로 확인, 패널에 돌려주지 않음)하고 확인 코드(6자리, 10분, 5번 틀리면 폐기)를 봇과의 개인 대화에 보내면 그 채팅 하나만 허용한다(개인 대화·보낸 사람=채팅만, 그 밖은 답하지 않고 버림). 구현 `src/background/telegram.ts`, 순수 함수 `src/lib/telegram.ts`.
  - 받기: 웹훅 서버를 열 수 없어 `getUpdates`. 평소 1분 알람마다, 요청을 처리하는 동안에는 이어서(20초 대기, /stop을 빨리 받으려고). 수신 루프는 하나만. 다음 offset을 처리 전에 저장(두 번 실행하지 않고 유실을 택함). 연결 전·10분보다 오래된 메시지는 실행하지 않고 다시 보내라고 답한다. 401·409면 멈추고 설정에 알린다(알람이 다시 켜지 않음).
  - 실행: 원격 대화(`ChatAgent` channel `telegram`)는 전역 실행 방식과 관계없이 '묻지 않고 실행'의 판정 규칙을 쓰되 **승인 카드를 띄우지 않는다** — 카드가 필요한 이동·클릭과 도구 한도는 설정(기본 켬)에 따라 텔레그램 [승인][거절] 버튼으로 묻고(#185, 질문은 `src/lib/remoteApproval.ts`가 모델용 글로 만든 것, 보안 규칙은 docs/security.md "원격 요청의 승인"), 승인하면 실행한다. 거절(`remote_user_denied`)·10분 무응답(`remote_approval_expired`)·물을 수 없음(`remote_needs_approval` — 그 밖의 도구·잘린 대상·설정 끔)이면 하지 않고 도구 없이 답을 마무리한다. 원격 안내는 물을 수 있으면 "이동·클릭은 승인을 묻는다", 아니면 지금처럼 "요청 글에 적은 사이트만"으로 바뀐다. 작업 맡기기·자동 로그인(승인한 사이트여도)·저장 링크 열기·반복 작업 등록은 원격에서 쓰지 않는다. 새 탭(chrome://newtab, 비활성)에서 시작하므로 자동 이동은 요청 글에 사용자가 적은 주소·도메인과 같은 등록 도메인으로만 된다. 원격 안내에 그 사이트 목록과 범위(첫 이동만, 들어간 뒤에는 그 사이트 안, 공유 호스팅 제외)를 함께 넣어 모델이 미리 포기하지 않게 하고, 적은 사이트가 없으면 볼 사이트 주소를 띄어 써서 다시 보내 달라고 답하게 한다(조사를 붙인 "naver.com에서"는 사이트로 보지 않는다). 앞 턴의 팝업 창을 이어받지 않는다. 대화의 작업 탭은 지난 요청이 끝난 주소에 그대로 있을 때만 다시 쓴다(사용자가 옮겼으면 새 탭). 한 번에 요청 하나(/stop, /new, 1시간 무응답이면 새 대화).
  - 보내는 글: 최종 답(이번 요청에서 도구 호출이 없는 마지막 답)만 평문으로(링크 미리보기 끔, 4096자 나눔), 자동 로그인 값을 가린 뒤 보낸다(가림 목록을 못 읽으면 내용을 보내지 않음). 오류는 고정 문구(키·모델 확인/사용량 확인/잠시 뒤 다시)만, 제공자 원문 없음. 도구 결과·생각·진단 기록은 보내지 않는다.
  - 반복 작업 알림(설정에서 켤 때만): 조건이 맞은 회차에 작업 이름만 보낸다(확인 결과의 이유·할 일은 보내지 않음). 이어서 진행은 패널에서.
  - 저장소 접근을 확장 화면·서비스 워커로 제한한다(`storage.local.setAccessLevel(TRUSTED_CONTEXTS)` — content script는 저장소를 쓰지 않음). 텔레그램 API 오류·로그에는 메서드와 상태 코드만 남기고 요청 주소(토큰)는 남기지 않는다. 연결 끊기·토큰 바꾸기는 진행 중인 요청과 받기를 멈춘다. 토큰이 새면 BotFather의 /revoke로 폐기하라고 설정에 안내한다.
- **MCP 연동 (선택, #140)** — 다른 AI 도구(Claude Code·Claude Desktop 등)가 브라우저 일을 시키고 최종 답을 받는다. 확장은 포트를 열 수 없어, 함께 배포하는 다리 `mcp/sbp-mcp.mjs`(Node 22+, 내장 모듈만)가 MCP 클라이언트에는 stdio MCP 서버(도구 `browser_task`)로, 확장에는 127.0.0.1의 작은 HTTP 창구(`GET /v1/next` 최대 20초 대기, `POST /v1/result`)로 동작한다. 확장 구현 `src/background/mcp.ts`, 프로토콜 `src/lib/mcpProtocol.ts`(다리와 같은 계산 — `tests/mcpProtocol.test.mjs`가 교차 검증).
  - 인증·기밀성: 확장이 만든 32바이트 비밀(설정에서 보기·복사, 다리 환경변수 SBP_SECRET)에서 HKDF로 방향별 AES-GCM 키와 요청 서명 키를 만든다. 확장 요청은 머리(버전·시각·nonce)와 HMAC 서명으로 인증하고(시각 ±60초, nonce 재사용 거절, 인증 전에는 큐를 꺼내지 않음), 모든 본문은 메서드·경로·머리에 묶은 AES-GCM으로 암호화한다. 확장은 복호화하지 못한 응답을 버린다 — 그 포트를 차지한 다른 로컬 프로그램은 명령을 꾸미지도, 결과를 읽지도 못한다. 다리는 127.0.0.1에만 묶고, Host·경로·메서드를 정확히 보고, http(s) Origin(웹 페이지)은 거절하며 CORS 헤더를 주지 않는다. 비밀은 `mcp_secret` 메시지로만(확장 화면) 돌려준다.
  - 작업 계약: 한 번에 하나(진행 중이면 busy 오류). 확장이 90초 안에 가져가지 않으면·10분이 넘으면 오류. MCP의 `notifications/cancelled`·stdin 종료·기한 만료는 취소로 바꿔 다음 폴링에서 확장에 알리고, 확장은 그 작업을 멈춘 뒤 취소 확인을 보낸다(늦은 결과는 버림). 확장은 실행 전에 작업 id를 저장해 같은 작업을 다시 실행하지 않고, 결과 전송만 다시 시도한다. 다리에 60초 넘게 닿지 않거나 기한이 지나면 스스로 멈춘다. 서비스 워커가 다시 뜨면 진행 중이던 작업은 중단으로 보고한다. 다리가 바뀌면(bridgeId) 대화·작업 탭을 버린다.
  - 승인 질문(#185, 설정 "MCP 클라이언트에 승인 묻기" 기본 끔): 다리가 `/v1/next`에 `features: ["ask"]`와 작업별 `canAsk`(클라이언트의 form elicitation 지원 — 2025-06-18은 `capabilities.elicitation` 객체, 2025-11-25는 빈 객체·`form` 키, 2024-11-05는 없음)를 싣는다. 켜져 있고 지원하면 카드가 필요한 이동·클릭·한도를 `POST /v1/ask`(ask·ack·withdraw, 모두 멱등, 같은 인증·암호화)로 보내고 다리가 `elicitation/create`(`requestedSchema` approve boolean 기본 false, 2025-11-25면 `mode: "form"`)로 묻는다. accept+approve true만 승인, decline·accept false는 거절, cancel은 닫음, RPC 오류·모양 틀림은 물을 수 없음. 답은 ack까지 `/v1/next`의 `answers`로 다시 온다. 질문은 5분(작업 기한 30초 전까지), 만료·중단이면 withdraw(다리가 `notifications/cancelled`를 보내고 늦은 답을 버림, 모르는 id도 거둔 것으로 기억해 늦은 ask가 질문을 열지 않음), 작업이 끝나면 열린 질문을 모두 거둔다. wire 버전은 1 그대로라 구 다리(1.0.x)·구 확장과 섞여도 묻지 않을 뿐 동작한다.
  - 실행: 원격 대화(`channel "mcp"`)로 텔레그램과 같은 정책(전역 실행 방식과 관계없는 auto 판정, 카드가 필요한 동작은 거절 후 도구 없이 마무리, 자동 로그인·저장 링크·반복 작업 등록 안 함, 새 탭 화면에서 시작). 요청마다 새 대화로 시작하고 끝나면 닫는다(앞 요청의 외부 본문 보호·남은 페이지 번역이 이어지지 않게). 결과는 최종 답(자동 로그인 값 가림, 가림 목록을 못 읽으면 보내지 않음)과 고정 오류 문구.
  - MCP: 줄 단위 JSON-RPC, 지원 버전 2025-11-25·2025-06-18·2024-11-05(batch가 필수인 2025-03-26은 뺌), 초기화 전 tools 호출 거절, 알림 무응답, stdout에는 JSON-RPC만. 다리 하나·확장 프로필 하나만 지원(포트 충돌이면 오류로 끝남).
  - 수신: 설정에서 켜면 단일 루프로 이어서 폴링(전체 25초 제한), 다리가 없으면 몇 번 재시도한 뒤 1분 알람으로. 루프가 도는 동안 20초마다 확장 API를 불러 서비스 워커를 붙잡는다. 릴리스 ZIP에 `mcp/sbp-mcp.mjs`를 넣는다.
- **자동 로그인 (KeePassXC, 선택 기능)** — 일을 하다 로그인 화면을 만나면 모델이 `sign_in`을 부르고, 도우미가 KeePassXC에서 받은 아이디·비밀번호(2단계 인증 코드는 사이트마다 켤 때만)를 직접 넣고 제출한다. 값은 모델에 가지 않는다. 사용자가 승인한 사이트(정확한 출처 → KeePassXC 항목 묶음)에서는 카드 없이, 그 밖에는 카드에서 항목을 고르고 "앞으로 자동 로그인"으로 묶을 수 있다. KeePassXC를 연결하지 않았거나 항목이 없으면 칸을 표시해 직접 로그인하게 한다. 설계·보안 모델: `docs/design/login-automation.md`
- **OpenRouter 모델 지원** — `provider/model` 형식의 모델 ID를 직접 선택하며, reasoning과 tool calling 결과를 실시간 스트리밍
- **생각 중 표시** — 모델이 추론하는 동안 추론 글자 대신 "생각 중…"과 움직이는 아이콘만 보임(도구 전 짧은 설명과 답변은 그대로). 설정의 "생각 과정 보기"를 켜면 추론 글자를 접이식 상자로 봄
- **이 페이지 기억해줘** — 내장 도구 `remember_page`: 사용자가 보고 있는 페이지(팝업·새 탭을 따라가는 중이면 그 탭)의 저장 카드를 펼친 채 띄우고 초안을 자동으로 채움(외부 본문 보호가 켜진 대화면 자동으로 보내지 않고 "다시 채우기"를 누를 때만). 저장은 늘 사용자가 카드에서 누를 때만(페이지 글의 지시로 불려도 저장되지 않음, 맡긴 작업이어도). 설정 꺼짐·시크릿·웹 주소 아님·자동 로그인 값이 보이면 고정 문구로 거절. 같은 턴 끝의 자동 제안은 같은 주소면 띄우지 않음. 원격(텔레그램·MCP)에서는 쓰지 않음
- **이 페이지 기억 버튼(#174)** — 패널 헤더의 📌: 말하지 않고 패널이 붙은 창의 활성 탭으로 저장 카드를 펼쳐 띄우고 초안을 자동으로 채움(대화 밖 동작이라 요청·답은 보내지 않고 탭 제목·주소·화면 글자만). 패널이 버튼을 보일 때의 탭·주소와 지금 탭이 다르면, 문서를 확인하지 못하면, 읽는 사이 문서·주소가 바뀌면 거절. 설정 꺼짐·웹 주소 아님·시크릿 창이면 버튼 비활성(백그라운드가 다시 확인). 응답을 받는 중이면 카드를 스트리밍 중인 답 앞에 넣음. 저장은 카드에서 누를 때만
- **지워질 링크 다시 확인(#174)** — 저장 링크가 가득 찬 상태에서 카드가 예고한 지워질 링크와 저장 순간 실제로 지워질 링크가 다르면(다른 카드를 먼저 저장) 저장하지 않고 새 예고를 보여 다시 누르게 함
- **방문 기록에서 찾기(#175)** — 설정 → 기억·기록의 "방문 기록에서 찾기": 누를 때만 선택 권한 `history`를 요청하고, 최근 30일 방문 기록에서 구조 신호(누적 방문·직접 입력 수, 최근성, 같은 주소 형태에서 쿼리 값을 바꿔 다시 쓴 흔적)로 후보를 최대 30개로 줄인다(`src/lib/historyPick.ts`). 자동 로그인 값·이미 저장한 링크 형태(보수적 비교)는 빼고, 결제·개인정보 단서가 보이는 주소는 빼지 않고 ⚠로 보이며 기본으로 체크하지 않는다. 보낼 내용(제목·출처+경로·쿼리 이름 — 쿼리 값과 통계 제외)과 보낼 곳(제공자·모델)을 먼저 보여 주고, 체크한 항목만 보낸다. 모델이 고른 페이지(최대 8개, 보낸 항목만)마다 이름·용도·이유를 보이고 "저장 카드 열기"로 채팅에 카드를 띄운다(추천이 초안, 초안을 다시 묻지 않음). 저장은 카드에서 누를 때만. 설정 화면 전용 포트(`history_pick`)로만 동작해 화면을 닫으면 작업을 버린다(`src/background/historyPickStore.ts`). 주기 실행·같은 요청 반복 시 자동 제안은 하지 않음
- **페이지 제안(#173, 설정 기본 켜짐)** — 사용자가 만든 규칙(출처 + 경로 패턴 → 제안 문구·보낼 요청, 최대 30개, `src/lib/pageSuggest.ts`)과 패널 창의 활성 탭 주소가 맞으면 입력창 위에 칩("💡 번역해 드릴까요? [실행] [이 제안 끄기] [×]")을 띄운다. 판단은 주소의 구조(출처 정확히 일치, 경로 세그먼트 `*`·끝의 `**`, 쿼리·해시 무시)로만 하고 모델·페이지 글자는 쓰지 않는다. 페이지마다 한 번(실행·×하면 그 페이지에선 다시 안 띄움, 새로고침은 새 페이지). 규칙은 내 요청 말풍선의 "이 페이지에서 제안"(출처는 지금 탭, 경로 기본값은 마지막 칸을 `*`로) 또는 설정 → 기억·기록 → 페이지 제안에서 만들고 고친다. [실행]은 백그라운드가 전역 설정·규칙 켜짐·버전, 패널 창의 활성 탭·주소, 문서를 다시 확인한 뒤 저장된 규칙의 요청을 일반 요청처럼 보낸다(같은 대화 유지, 승인 규칙 그대로). 제안 턴은 앞 턴의 팝업을 잇지 않고, 문맥(헤더·PDF)을 읽기 전후로 문서·주소를 다시 확인해 바뀌었으면 기록·모델 요청 없이 멈춘다. 패널이 닫혀 있을 때의 알림·같은 요청 반복 시 자동 제안은 없음
- **빠르게 생각(#160)** — 설정 "동작"의 체크박스(기본 꺼짐). 켜면 모든 에이전트 요청을 낮은 추론 강도(제공자별 기존 `agent_low` 매핑: OpenRouter `effort: low`, OpenAI·Gemini `low`, Claude 낮은 강도)로 보내고, 지침의 Thought 규칙을 "다음 할 일과 이유를 한 문장으로"로 줄임. 턴 시작에 읽어 그 턴 동안 고정하고, 값이 바뀌면 다음 요청부터 새 대화로 시작(지침이 달라져 Claude 등의 이전 생각 서명이 무효가 되지 않게). 길이 초과 재시도는 그대로 한 번. 승인·자동 실행 판정은 바뀌지 않음
