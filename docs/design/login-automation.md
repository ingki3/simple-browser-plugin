# 자동 로그인 설계안 (검토용 초안 3)

상태: 제안. 코드 변경 없음. 리뷰 대상은 이 문서의 보안 모델과 단계 구분이다.

## 1. 목표와 지킬 규칙

**사용자가 승인한 사이트에서는 에이전트가 로그인을 끝까지 한다**(채우기와 제출 모두, 사용자 결정 2026-10-25).
에이전트가 일을 하다 그 사이트의 로그인 화면을 만나면 묻지 않고 로그인한 뒤 하던 일을 이어 간다.
승인하지 않은 사이트에서는 묻는다(채울지 카드, 또는 손 넘기기).

지켜야 할 규칙(CLAUDE.md·사용자 결정):

- **비밀 값은 모델에 가지 않는다.** 아이디·비밀번호·일회용 코드는 모델 요청, 도구 결과·오류, 동작 기록(actionLog),
  디버그 로그(debugLog), chrome.storage 어디에도 남기지 않는다(#43 "사용자가 입력한 값은 보호").
- **키워드로 승인을 면제하지 않는다.** 자동 로그인의 면제는 사용자가 사이트를 승인했다는 명시적 선택과, 구조(정확한 출처,
  `type=password` 칸, 양식 관계, 제출 주소의 출처)로만 정한다. "login" 같은 낱말·버튼 글자로 로그인 화면이나 제출 버튼을 추론하지 않는다.
- **봇 탐지 우회를 하지 않는다.** 자동화를 막는 사이트, CAPTCHA, 패스키(WebAuthn), SMS 인증은 손 넘기기로 사용자에게 맡긴다.
- 확장에 비밀번호 저장소를 새로 만들지 않는다(암호화·백업·동기화를 다시 만드는 일이고, 확장 저장소는 평문이다).
  비밀번호는 이미 쓰고 있는 비밀번호 관리자에 둔다.

## 2. 조사한 방법

| 방법 | 확장에서 쓸 수 있나 | 판단 |
|---|---|---|
| Chrome 내장 비밀번호 관리자 | 확장 API가 없다. 채운 값도 사용자 동작 전에는 페이지 스크립트에 보이지 않는다 | 값을 꺼낼 수 없음. 승인하지 않은 사이트·관리자 미연결일 때의 손 넘기기로만 |
| KeePassXC (오픈소스) | native messaging(`keepassxc-proxy`)과 공개된 KeePassXC-Browser 프로토콜(`associate`, `get-logins`, `get-totp`). 연결 승인·사이트별 접근 허락을 KeePassXC 창에서 사용자가 한다 | 1순위 공급자 |
| Bitwarden CLI (`bw`) | `bw serve`는 localhost REST라 확장 fetch에 Origin이 붙어 기본 출처 보호에 막힌다. 보호를 끄면 잠금 해제된 금고가 아무 웹페이지에도 열린다 | `bw serve` 직접 연결은 쓰지 않음. 쓰려면 native messaging 도우미가 `bw get`을 부르는 형태 |
| 1Password CLI (`op`) / Secure Agentic Autofill | `op`는 데스크톱 앱 연동·생체 인증으로 세션을 연다. Secure Agentic Autofill은 Browserbase 전용 조기 제공(엔터프라이즈) | `op`는 Bitwarden과 같은 도우미 형태로 후보. Agentic Autofill은 우리 구조(사용자 Chrome)에 맞지 않음 |
| browser-use `sensitive_data` | 모델에는 자리표시자만 보내고 실행할 때 실제 값으로 바꾼다. 도메인별로 비밀을 묶는다 | 설계 원칙을 가져옴(모델은 "로그인"만 요청하고 값은 모름, 사이트별 묶음) |
| 쿠키·세션 유지 | 확장은 사용자의 실제 Chrome 프로필에서 돌아 이미 로그인된 상태를 그대로 쓴다 | 이미 됨. 자동 로그인은 세션이 끊긴 경우만 다룬다 |

## 3. 사이트 승인

- 단위: **정확한 출처**(scheme·host·port). https만(개발용 localhost 예외). 하위 도메인·eTLD+1로 넓히지 않는다
  (`accounts.example.com`과 `www.example.com`은 따로 승인).
- 승인 방법(둘 다 사용자 명시 선택):
  1. 설정(⚙) → "자동 로그인 사이트"에서 출처를 추가·삭제.
  2. 승인하지 않은 사이트에서 `sign_in`이 불리면 카드: "accounts.example.com에 KeePassXC의 로그인 정보로 로그인합니다"
     [이번만] [이 사이트는 앞으로 자동 로그인] [직접 할게요(손 넘기기)] [취소].
- 사이트마다 일회용 코드 자동 입력을 따로 켠다(기본 꺼짐). 비밀번호와 2단계 코드를 둘 다 에이전트가 넣으면 2단계 인증의 의미가
  줄기 때문에 따로 고르게 한다.
- **승인은 출처와 항목의 묶음이다.** KeePassXC의 `get-logins`는 정확한 출처만 돌려주지 않는다(하위 도메인을 맞추고, 저장 URL에
  포트가 없으면 다른 포트도 맞춘다 — `BrowserService.cpp`). 그래서 브라우저가 조회 주소를 정하는 것만으로는 출처 검증이 되지 않는다.
  승인할 때 사용자가 **전체 출처**(`https://accounts.example.com:443`)와 **항목**(KeePassXC 항목 이름·아이디)을 보고 직접 고르며,
  항목이 하나뿐이어도 자동으로 고르지 않는다. 저장하는 것은 `출처 → 항목 uuid` 묶음이다.
- 자동 로그인은 `get-logins` 결과에 **그 출처에 묶은 uuid가 있을 때만** 그 항목을 쓴다. 없으면(항목이 지워졌거나 다른 출처) 묻는다.
  다른 항목은 결과에 있어도 쓰지 않는다.
- 승인 목록에는 출처·uuid·표시용 항목 이름만 둔다(비밀 값 없음). KeePassXC의 사이트별 "기억" 허락은 KeePassXC 쪽 선택으로 따로 남는다.

## 4. 동작

### 도구 `sign_in` (모델이 부른다)

- 인자: 대상 칸 id(`find_form_fields` 결과의 비밀번호 칸 또는 아이디 칸 id) 하나. 사이트 주소·아이디·항목 이름은 받지 않는다.
- 언제: 모델이 로그인 화면이라고 보고 부른다(뜻 판단은 모델 몫). 코드는 아래 구조 조건이 맞을 때만 실행한다.

### 실행 순서 (백그라운드)

1. **대상 프레임과 출처를 브라우저에서 정한다.** 대상 칸이 있는 프레임의 `documentId`·URL(`webNavigation.getAllFrames`).
   모델이 준 주소를 쓰지 않는다. 이 대화의 작업 탭(turnTab)일 때만.
2. **구조 조건** (content script가 그 문서에서 다시 확인):
   - 비밀번호 단계: 대상이 보이는 `input[type=password]`이거나, 대상과 같은 양식(form 또는 `submitScopes` 범위)에 그런 칸이 하나 있다.
     새 비밀번호 칸(`autocomplete=new-password`)이 있으면 가입·변경 화면일 수 있으니 자동 실행하지 않고 묻는다.
   - 아이디만 먼저 받는 단계(여러 단계 로그인): 대상이 `autocomplete=username`(또는 `email`)인 보이는 칸이고 같은 범위에 다른 보이는
     입력 칸이 없다. 이 속성이 없는 사이트는 아이디 단계를 자동으로 하지 않고 묻는다(낱말로 추론하지 않는다).
   - 제출 주소: 그 양식의 action·제출 버튼의 formaction, 범위 안 다른 양식의 제출 주소(기존 `scopeSubmitUrls`·`otherDestinations`)가
     모두 **그 프레임과 같은 출처이거나 승인한 출처**. 다른 출처로 보내는 양식이면 묻는다.
   - 대상 프레임이 최상위가 아니면 최상위 문서의 출처도 승인 목록에 있어야 한다(다른 사이트에 끼워 넣은 로그인 iframe을 막는다).
3. **승인 판정** (`decideApproval`에 한 갈래로 넣는다): 출처가 승인 목록에 있고 2가 모두 맞으면 자동 실행. 아니면 3절의 카드.
   이 면제는 `sign_in`에만 있고, `fill_form_fields`·`click_element`로 비밀번호 칸을 다루는 기존 규칙(늘 묻는다)은 그대로다.
4. **값 받기**: KeePassXC에 `get-logins(url=그 프레임 URL)`. KeePassXC가 잠겨 있거나 사이트별 허락을 묻는 동안 기다린다(시간 제한).
   - 승인한 출처: 묶어 둔 uuid의 항목만 쓴다(3절). 없으면 묻는다.
   - 승인하지 않은 출처(카드에서 "이번만"·"앞으로 자동 로그인"): 전체 출처와 함께 항목 목록(이름·아이디)을 사이드 패널에 보여 주고
     사용자가 고른다. 하나뿐이어도 고르게 한다. 아이디는 사용자에게만 보이고 모델에는 가지 않는다.
   - 0개: 손 넘기기로 바꾼다.
5. **채우기와 제출** (content script, `documentId` 고정):
   - 값을 넣기 직전에 2의 구조 조건과 출처를 다시 본다. 문서가 바뀌었으면 넣지 않고 실패로 알린다.
   - 아이디 칸(같은 범위의 `autocomplete=username`, 없으면 비밀번호 칸 바로 앞의 보이는 text·email 칸)과 비밀번호 칸에 넣는다.
     아이디 칸이 이미 같은 값이면 건드리지 않는다.
   - 제출은 구조로 고른다: `<form>`이면 `form.requestSubmit()`(양식의 기본 제출 버튼이 있으면 그 버튼으로). 양식 요소가 없는 화면은
     제출 버튼을 구조로 특정할 수 없으므로 채우기까지만 하고, 누를 버튼은 모델이 `click_element`로 고른다 — 이때 승인한 출처이고
     그 클릭의 기존 위험 신호(다른 출처 이동·결제·삭제 등)가 없으면 "로그인 정보 제출" 한 번은 자동 실행한다.
     (실제 입력 클릭 설정이 켜져 있으면 그 방식으로 누른다. 사람처럼 보이게 하는 지연·궤적은 넣지 않는다.)
6. **결과 확인**: 제출 뒤 문서가 바뀌거나 비밀번호 칸이 사라진 것은 **로그인 완료가 아니라 "제출함, 다시 살펴볼 것"** 신호다
   (SMS·OTP·CAPTCHA·"새 기기 확인" 화면으로 넘어가도 같은 모양이다). 코드는 완료를 판정하지 않는다. 도구 결과는 "제출했습니다.
   지금 화면을 다시 살펴보세요"이고, 모델이 다음 화면을 관측해 이어 가거나 손 넘기기를 부른다. 비밀번호 칸이 같은 문서에 그대로면
   실패로 본다.
   - **다시 시도하지 않는다.** 같은 출처의 자동 로그인은 한 대화에서 1번(아이디 단계·비밀번호 단계·코드 단계를 한 번의 로그인으로 셈).
     실패하면 손 넘기기로 바꾼다(계정 잠김 방지).
   - 일회용 코드 화면(`autocomplete=one-time-code` 칸)이 이어지면: 그 출처에 코드 자동 입력이 켜져 있고 KeePassXC 항목에 TOTP가 있으면
     `get-totp`로 같은 방식으로 넣는다. 아니면 손 넘기기.
7. **도구 결과**: "https://accounts.example.com에 로그인 정보를 제출했습니다. 화면을 다시 살펴보세요" /
   "로그인하지 못했습니다(비밀번호 칸이 그대로 있음). 사용자에게 넘겼습니다"처럼 값이 없는 문장. 실패 이유에도 값을 넣지 않는다.
8. **채운 값이 다른 관측으로 새지 않게** (아래 "비밀 값 가리기").

### 비밀 값 가리기

`sign_in` 결과에 값을 넣지 않아도, 페이지가 채워진 값을 일반 글자(`<div>`, 접근성 이름, 링크 주소 등)로 옮기면 이후의 읽기 도구
(`describe_page`, `find_*`, `query_dom`, `read_document`, 탭 제목·주소)가 그 글자를 화면 글자로 모델에 보낼 수 있다.
`modelText`는 요소 구조로만 보호하므로 이 경로를 막지 못한다.

- 백그라운드가 이 대화에서 넣은 비밀 값(아이디는 제외 — 화면에 원래 보이는 값이다; 비밀번호와 일회용 코드)을 대화 메모리에만 둔다
  (저장소·로그에는 두지 않음, 대화가 끝나거나 새 대화면 지움).
- **모델로 나가는 모든 요청의 한 지점**(제공자 어댑터에 넘기기 직전의 메시지 직렬화)에서 그 값과 흔한 표현(URL 인코딩,
  HTML 엔티티, base64)을 `[가린 값]`으로 바꾼다. 도구 결과뿐 아니라 사용자 메모·페이지 제공 문맥·오류 글까지 한 지점에서 걸러
  새 도구가 생겨도 빠지지 않게 한다. 디버그 로그·동작 기록에도 같은 거르기를 쓴다.
- 가린 일이 있으면 결과에 "페이지가 입력한 비밀 값을 화면에 다시 보여 주어 가렸습니다"를 붙이고, 그 문서에서의 자동 로그인 판정을
  다시 묻는 쪽으로 바꾼다(정상 사이트는 비밀번호를 화면에 다시 쓰지 않는다 — 구조 신호로 더 묻는 쪽).
- 한계: 페이지 스크립트가 값을 마음대로 바꿔(뒤집기, 나눠 쓰기) 내보내면 거르기로 다 막을 수 없다. 그러나 그런 스크립트는 값을
  자기 서버로 바로 보낼 수도 있으므로, 이는 그 사이트를 믿고 비밀번호를 맡기는 모든 관리자의 공통 한계다. 이 설계가 지키는 것은
  "확장이 값을 모델·로그로 보내지 않는다"와 "정확한 값·흔한 표현은 페이지가 옮겨도 모델에 가지 않는다"까지이고,
  나머지는 사이트 승인(사용자 판단)의 몫으로 문서·설정 설명에 적는다.

### KeePassXC 연결 준비

- `nativeMessaging` 권한을 설정에서 켤 때 `optional_permissions`로 요청한다.
- 사용자가 우리 확장 ID를 `allowed_origins`에 넣은 호스트 manifest를 설치한다(이름 예 `com.simple_browser_helper.keepassxc`,
  `path`는 KeePassXC에 들어 있는 `keepassxc-proxy`). 설정 화면이 OS별 경로와 manifest 내용을 보여 주고 복사하게 한다.
- 처음 `associate`를 보내면 KeePassXC 창이 연결 승인과 이름을 묻는다. 받은 식별 키는 chrome.storage에, 세션 키는 메모리에만 둔다.

### 관리자를 연결하지 않았거나 승인하지 않은 사이트

손 넘기기 카드("로그인해 주세요")를 띄우고 사용자가 Chrome 자동 채우기 등으로 직접 로그인한다. 끝남은 사용자가 카드의 "완료"를
누를 때만이다. 문서가 바뀌면 카드는 유지한 채 표시만 다시 붙인다(2단계 인증 화면이 이어질 수 있다).

## 5. 위협과 대응

| 위협 | 대응 |
|---|---|
| 페이지 글자의 프롬프트 주입으로 다른 사이트 칸에 채우게 함 | 조회 주소·대상 프레임을 브라우저가 정하고, 그 프레임 출처의 항목만 받는다. 승인 목록은 정확한 출처 |
| 승인한 사이트 안의 가짜 로그인 양식(사용자 글, 끼워 넣은 HTML)이 값을 다른 곳으로 보냄 | 제출 주소가 모두 같은 출처·승인 출처일 때만 자동. 페이지 스크립트가 값을 읽어 보내는 것은 모든 비밀번호 관리자의 공통 한계이고, 이를 막는 것은 사이트 승인(사용자 판단)의 몫 |
| 승인한 사이트에 다른 사이트가 로그인 iframe을 끼워 넣음 | 최상위 문서의 출처도 승인 목록에 있어야 자동 |
| 주입으로 모델이 승인 사이트에 반복 로그인 시도 → 계정 잠김 | 출처별 대화당 1번, 실패하면 손 넘기기 |
| 가입·비밀번호 변경 화면에 기존 비밀번호를 넣음 | `new-password` 칸이 있으면 자동 실행 안 함 |
| 채운 뒤·제출 전에 문서가 바뀜 | `documentId` 고정, 넣기 직전에 구조·출처 재확인 |
| 값이 모델·로그로 샘 | 결과 문장에 값 없음, 로그·동작 기록 직렬화에서 빠지는지 테스트, 캡처 이미지는 모델에 안 보냄(0.2.14) |
| 페이지가 채운 값을 화면 글자·주소로 옮겨 읽기 도구로 샘 | 모델 요청 한 지점에서 값·흔한 표현 가리기, 가렸으면 그 문서는 다시 묻기. 임의 변형은 사이트 신뢰의 한계로 명시 |
| KeePassXC가 하위 도메인·다른 포트 항목을 돌려줌 | 출처 → 항목 uuid 묶음으로만 자동. 승인할 때 전체 출처와 항목을 보여 주고 직접 고름 |
| 2단계 화면을 로그인 완료로 오판 | 코드는 완료를 판정하지 않음. 제출 뒤에는 모델이 다시 관측 |
| 2단계 인증 약화 | 코드 자동 입력은 출처별로 따로 켜는 선택(기본 꺼짐) |
| 다른 로컬 프로그램이 우리 호스트로 위장 | 호스트는 사용자가 설치한 manifest의 경로로만 실행된다. 설정 화면에 경로를 보여 준다 |
| 자동 로그인을 봇 우회에 씀 | 하지 않는다. 막는 사이트·CAPTCHA·패스키는 손 넘기기 |

## 6. 구현 순서

1. 손 넘기기 "로그인해 주세요"와 끝남 판정(관리자 없이도 쓰는 바탕).
2. 비밀 값 가리기(모델 요청 한 지점)와 그 테스트, 승인 목록(출처 → 항목 uuid, 설정·카드)과 `decideApproval` 갈래, 구조 조건 판정 — 하네스 시나리오: 같은 출처/다른 출처 action, iframe, new-password,
   아이디 단계, 재시도 금지.
3. KeePassXC 연결(associate, get-logins, 여러 항목 고르기)과 `sign_in` 채우기·제출. 하네스는 모의 native host 대신
   공급자 인터페이스의 모의 구현으로 본다.
4. 일회용 코드(get-totp, 출처별 켜기).
5. (후보) Bitwarden·1Password 도우미.
