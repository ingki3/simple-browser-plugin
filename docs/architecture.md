# 구조

개발 환경과 기여 절차는 [CONTRIBUTING](../CONTRIBUTING.md)에 있습니다.

## 흐름

```
[Side Panel React UI] ⇄ long-lived port ⇄ [Background Service Worker] ⇄ tabs.sendMessage ⇄ [Content Script]
                                                    │
                                                    ├── OpenRouter Chat Completions API
                                                    ├── ReAct stream loop (reasoning_details 보존)
                                                    ├── Tool dispatcher (zod 인자 검증)
                                                    └── webNavigation 통합 (settle 대기)
```

## 주요 구성

- **Manifest V3** — `sidePanel`, `storage`, `scripting`, `activeTab`, `downloads`, `tabs`, `alarms`, `webNavigation`, `identity`, `offscreen`, `webRequest`, `debugger`(실제 입력 클릭, 설정에서 켤 때만 사용) 권한 + `host_permissions: ["<all_urls>"]`
- **모델 제공자 어댑터** (#97) — 에이전트 루프·번역·저장 링크 초안·키 확인은 `src/lib/providers`의 공통 인터페이스(`openStream`·`complete`)만 씀. 대화 기록·스트림 조각의 내부 기준은 OpenAI 호환 형식이고, 생각 강도는 의도(`agent`·`agent_low`·`off`)로 넘겨 어댑터가 제공자 설정으로 바꿈. OpenRouter·OpenAI·Gemini·Anthropic 어댑터(Anthropic은 Messages API와 내부 형식을 서로 바꿈). 제공자가 도구 호출에 붙여 돌려받아야 하는 값(`extra_content`)은 그 제공자 어댑터만 보냄
- **Port 하트비트 + 자동 재연결** — MV3 서비스 워커 유휴 종료 대응
- **스트림 청크 무활동 워치독** (60초) + **초기 연결 타임아웃** (20초) + **툴별 타임아웃** (기본 30초, translate 180초)
- **webNavigation 기반 settle 대기** — URL 이동·클릭 직후 페이지 전환 중에 후속 툴이 경쟁 조건 만나지 않도록
- **캡처 이어 붙이기** (#49) — 전체 캡처의 화면들(PNG Blob)을 offscreen 문서(`BLOBS` 사유 추가)에서 조각마다 캔버스 하나씩 만들어 그 조각에 걸친 화면만 디코드해 그리고 PNG로 만든 뒤 캔버스를 놓음(한 번에 한 조각만 메모리에). 결과 blob: 주소는 저장 뒤 놓고, 놓지 않아도 5분 뒤 스스로 놓음
- **문서 변환 격리** — `read_document`는 offscreen 문서 안의 Worker에서 변환하고(형식에 맞는 변환기만 불러옴), 10초가 지나거나 사용자가 중단하면 Worker를 강제 종료. zip 기반 문서(Office·OpenDocument·HWPX)는 직접 풀어 크기를 센 뒤(본문 6MB·전체 40MB) 다시 만들어 넘기며, 이미지 등 바이너리는 비워서 넘김. PDF(pdf.js 워커에 빌드 때 패치)와 HWP(zlib 셰임)도 압축 해제량에 한도를 둠(문서당 128MB·256MB). 1분 동안 쓰지 않으면 offscreen 문서를 닫음
- **클릭·입력 확인 경로** — `find_clickables`·`find_form_fields`가 준 id마다 그때의 대상 기술(역할·글자·주소·영역·목록 순번·대상이 든 행의 글자)을 content script 메모리에 둠. 승인 카드를 띄울 때 지금 요소가 그때와 같은지 확인해 사람이 알아볼 수 있게 보여 주고(비밀번호 칸은 값을 가림), 실행 직전과, 클릭은 스크롤·포커스 뒤 누르기 바로 앞에서 다시 승인한 기술과 같을 때만 실행. 요소가 다시 그려져 사라졌으면 비슷한 요소로 대신하지 않고 멈춤(다시 찾아 새로 승인). 클릭 대상은 모델에 준 묶음 문맥과 상태도 비교함(승인 뒤 이미 체크·펼침으로 바뀐 대상을 누르면 반대로 되므로 멈춤). 입력 칸도 모델에 준 행 문맥과 '보이는 label로 바꾸는 칸' 여부를 비교함. 다만 입력 도중(입력 처리기 뒤 change 전, 같은 묶음에서 앞 칸을 채운 뒤의 칸)과 입력 뒤 반영 확인에서는 원문 행 글자가 그대로이고 모델용 행 문맥에 글자가 더해지기만 한 것(행 안의 숨은 안내 글이 보이게 됨 — 승인 당시 낱말이 같은 순서로 모두 남음)은 허용함. 문구를 바꿔 보여 주는 것은 거부(#43 C의 오탐을 늘리지 않게). 목록 다중 선택은 지침으로 '전체 선택' 대신 항목별로 고르고, 지우기·옮기기 같은 되돌리기 어려운 동작 전에는 고른 목록을 사용자에게 확인받으며, 화면 밖 항목은 다음 페이지 링크로 넘김(스크롤로만 더 불러오는 목록은 미지원).
- **선택지와 트리거의 관계** (#43 B) — 선택지(option·menuitem*)는 펼쳐진(aria-expanded=true) 트리거와의 관계를 구조로만 정함: aria-controls/aria-owns로 선택지나 그 목록을 가리키는 펼친 트리거가 정확히 하나면 linked(직접 연결이 없을 때, 펼친 트리거들이 가리키는 요소 중 목록을 감싼 것이 정확히 하나인 aria-controls이고, 그 요소가 최상위 문서의 shadow DOM 밖에 있으며 목록·트리거 안에 있지 않고, 그 안에 이 목록 말고 다른 목록·트리거·shadow root·슬롯·프레임이 없을 때만 같은 연결로 봄 — Google 항공편 공항 추천), 연결이 없고 펼친 트리거가 0~1개면 unlinked, 그 밖(펼친 트리거 둘 이상·연결 없음, 연결 둘 이상)은 어느 위젯의 선택지인지 정할 수 없어 클릭 대상으로 돌려주지 않음. 관계(트리거·목록 요소, 연결 방식, 트리거 기술)는 승인 카드 때·실행 직전·스크롤과 포커스 뒤에 다시 계산해 같아야 누름. 트리거의 위험 정보(결제 화면·개인정보가 채워진 양식·제출 주소 등)는 선택지와 따로 background로 보내 승인·사이트 판정을 양쪽 모두에 적용(포털로 그린 목록이라도 트리거가 결제 대화상자 안이면 카드). 트리거 자신이 다른 목록 안의 항목인 중첩 메뉴의 항목은 상위 트리거들의 위험을 따라가지 않으므로 자동 실행하지 않고 늘 카드로 물음. 한계: unlinked는 소속을 증명하지 않음 — ARIA 펼침 상태를 표시하지 않는 위젯이 같은 목록을 넘겨받는 경우는 구조로 구분할 수 없음(공유 팝업 안의 일반 버튼과 같은 한계). ARIA 역할이 없는 div·li 위젯, pointerdown·keydown에만 반응하는 위젯은 지원하지 않음 승인은 그 호출에 한 번만 쓰임. id에는 페이지마다 바뀌는 꼬리표가 붙어 이전 페이지의 id는 거부
- **실행 결과 확인** — 클릭 뒤 이동 종류(없음·페이지 안 위치(#)·같은 사이트·다른 사이트·오류), 페이지 안 주소 변경, 새 탭, 팝업 창(열림·막힘·닫힘), 화면 변화(DOM 변경 수·대화상자)를 결과로 돌려줌. 입력은 페이지 처리가 끝날 틈(150ms)을 둔 뒤 칸마다 값을 다시 읽어 실제로 반영됐는지 알려 줌
- **동작 기록** — 승인한 클릭·입력마다 페이지 구분 키(주소 틀 + 페이지 뼈대 해시), 대상 요약, 결과(완료·일부 반영·직전 중단·실패·취소)를 `chrome.storage.local`에만 남김. 주소 틀은 사람이 붙인 이름처럼 보이는 경로 낱말만 남기고 숫자·토큰·이메일·한글 이름 같은 칸은 자리표시로 바꾸며, 쿼리는 이름만 남김(`/board/{n}/view?id`). 대상 이름에 섞인 주소·이메일·key=value·긴 숫자·비밀 값처럼 보이는 낱말도 가림. 입력 칸은 이름 글자 대신 해시만 남기고(값·숫자를 지운 뒤 계산), 비밀번호·결제 칸은 해시도 남기지 않음. 뼈대 해시는 랜드마크·목록·표·폼의 중첩만 보고 같은 틀의 목록 항목은 하나로 접어, 내용과 항목 수가 달라도 같은 값. 입력 값, 대상이 든 행의 글자, 링크 주소의 값은 남기지 않고, 실패 이유도 문구 대신 분류만 남김. 시크릿 창은 기록하지 않고, 30일·500건·약 1MB를 넘으면 오래된 것부터 지움(한 항목의 대상은 20개까지). 설정에서 끄거나 지울 수 있음. 나중에 같은 구조의 페이지에서 동작을 다시 쓰는 레시피의 재료
- **찾기·실행 도구가 모델에 보내는 글자** (#43) — 원칙은 "화면 글자는 보내고, 사용자가 입력한 값은 보호". `find_form_fields`·`find_clickables`·`fill_form_fields`·`click_element`·`query_dom`의 결과와 오류 문구에는 페이지가 만든 글자(라벨·버튼 글자·select 선택지 글자)만 담고, 입력 칸(input·textarea·select)의 값·편집 영역(contenteditable, 그 안의 contenteditable=false 섬 포함)·숨은 요소(hidden·aria-hidden·display:none·visibility:hidden)의 글자는 구조로 빼고 모음(`src/content/modelText.ts`). 시작 요소의 조상(shadow host·슬롯·같은 출처 프레임 포함)이 보호 영역이면 이름도 비움. 모델에 돌려준 이름은 대상 비교에도 넣어, 원문은 같아도 모델이 본 이름이 바뀌면 다시 찾게 함. 범위: 이번에 좁힌 것은 이 도구들의 반환 계약뿐. 본문 읽기(`describe_page`·`get_page_content`)는 편집 영역을 포함한 화면 글자를 그대로 읽고, 주소(URL)는 주소창에 보이는 화면 정보로 보고 지금처럼 보냄(#44 결정). `query_dom` 선택자는 허용 문법만 받는 파서로 검사하고 값에 기대는 조건을 실행하지 않음(#45, `src/lib/selectorPolicy.ts`): 태그·#id·.class·[속성]·구조 의사 클래스·결합자만(이스케이프·주석·함수·의사 요소 등 브라우저와 해석이 갈릴 수 있는 형태는 거부), 속성 값 비교는 구조 속성(id·class·name·type·role·href, aria-label·aria-expanded 같은 구조·상태 aria)에만, `[value]` 존재 조건과 입력값 상태 의사 클래스(`:valid`·`:placeholder-shown`·`:dir()` 등)는 거부(`:has()`·`:is()`·`:not()` 안쪽 포함)
- **읽기 레시피** — 같은 페이지 키(주소 틀 + 뼈대 해시)에서 내용을 읽는 데 통한 `query_dom`·`list_file_links`·`find_clickables` 호출(선택자·검색어)을 턴이 정상으로 끝날 때 기억함. 한 턴에서 같은 도구를 고쳐 가며 부르면 마지막으로 결과가 나온 호출만 성공으로 셈. 다음에 같은 구조의 페이지에서 `describe_page`를 부르면 결과의 `readHints`에 후보로 붙이고(자동 실행은 하지 않음), 모델이 먼저 시도함. 기억한 호출이 빈 결과를 3번 연속 내면 버림. 이메일·주소·긴 숫자·비밀 값처럼 보이는 인자는 저장하지 않고, 페이지 내용은 남기지 않음. 페이지당 3개·전체 300개·30일 한도. 동작 기록 설정 하나로 함께 켜고 끄고 지움
- **문서 요청 안전장치** — 리다이렉트는 따라가지 않고 목적지 주소만 알려 줌(`webRequest`로 관찰). 그 주소로 다시 읽으면 새 승인 카드가 뜸. 웹 페이지·이미지·압축 파일 등 문서가 아닌 확장자는 요청하지 않음. 확장자 없는 링크는 승인 카드에 따로 경고
- **kordoc 브라우저 번들** — kordoc는 Node용이라 `vendor/kordoc/`에서 따로 설치해 브라우저용으로 묶은 결과물을 커밋해 씀(`npm run vendor:kordoc`로 다시 만듦, [vendor/kordoc/README.md](../vendor/kordoc/README.md))
