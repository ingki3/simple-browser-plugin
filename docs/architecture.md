# 구조

개발 환경과 기여 절차는 [CONTRIBUTING](../CONTRIBUTING.md)에 있습니다.

## 흐름

```
[Side Panel React UI] ⇄ long-lived port ⇄ [Background Service Worker] ⇄ tabs.sendMessage ⇄ [Content Script]
                                                    │
                                                    ├── 모델 제공자 어댑터 (OpenRouter·OpenAI·Gemini·Anthropic·로컬 호환 서버)
                                                    ├── ReAct stream loop (reasoning_details 보존)
                                                    ├── Tool dispatcher (zod 인자 검증)
                                                    └── webNavigation 통합 (settle 대기)
[설정 페이지(옵션 탭) React UI] ⇄ runtime.sendMessage·storage ⇄ [Background]   (#127, 패널과 같은 저장소 값을 storage.onChanged로 따라감)
```

## 주요 구성

- **Manifest V3** — `sidePanel`, `storage`, `scripting`, `downloads`, `tabs`, `alarms`, `webNavigation`, `offscreen`, `webRequest`, `debugger`(실제 입력 클릭, 설정에서 켤 때만 사용) 권한 + Google 클라이언트 ID를 넣은 빌드에만 `identity`·`oauth2`(`src/lib/manifestGoogle.ts`, 웹 스토어 최소 권한 — `activeTab`은 `<all_urls>`와 겹쳐 두지 않음, CI가 `scripts/checkManifest.mjs`로 검사) + 선택 권한 `nativeMessaging`(KeePassXC 자동 로그인)·`history`(방문 기록에서 찾기) + `host_permissions: ["<all_urls>"]`. `web_accessible_resources`는 없다(#215)
- **content script 한 파일** (#215) — crxjs의 content script loader는 본체를 `import(chrome.runtime.getURL(…))`로 불러와 그 조각을 웹 접근 가능하게 둬야 한다(웹 페이지가 그 주소로 설치 여부를 알 수 있음). 빌드가 끝나면 `vite.config.ts`의 `contentScriptBundle`이 `src/content/index.ts`를 IIFE 한 파일(`dist/content.js`, 동적 import 안에 묶음 — 조각이 둘 이상이거나 import가 남으면 빌드 실패)로 따로 빌드해 manifest의 `content_scripts`가 그 파일을 가리키게 하고, content script용 `web_accessible_resources`와 loader를 지운다. 번들은 `Symbol.for("sbp.content.loaded")` 표시로 감싸 같은 isolated world에서 다시 실행돼도(설치 전 열린 탭 주입의 중복·동시 주입, allFrames) 한 번만 초기화된다(초기화 횟수 `sbp.content.inits`). 프로그램 주입(`getContentScriptFiles`)도 manifest의 같은 파일을 쓴다. 개발 서버(crx HMR)는 그대로
- **대화 에이전트** (#263) — `src/background/agent/chatAgent.ts`의 `ChatAgent`가 대화 상태·턴·도구 루프·승인·실행을 맡는다. 시스템 지침과 요청에 붙이는 안내 문구(`composeSystemPrompt`·`remoteTurnNote`·`*_NOTE` 등)는 `agent/prompts.ts`(순수 문자열·함수, 대화 상태 없음)에 있고, 보안·한도 상수(`REMOTE_BLOCKED_TOOLS`·요청별 읽기 한도)는 chatAgent.ts에 둔다. 턴 탭 문맥(탭이 다 떴는지·탭 머리말·도구가 동작하는 탭의 주소)은 `agent/tabContext.ts`, 대화 기록 계산(`closeDanglingToolCalls`·`answerSince`·`lastAnswerText`·`confirmRebases`)은 `agent/history.ts`에 있다. 둘 다 대화 상태를 갖지 않는다 — 탭 머리말은 지금 턴의 탭을 getter로 받아 기다린 뒤 다시 읽고(옮기기 전 시점 그대로), 기록 계산은 값을 돌려주며 필드 대입은 ChatAgent가 한다. 모델 응답 스트림 조각 누적(본문·생각 이어 붙이기, index별 도구 인자 이어 붙이기·id 없으면 UUID, `extra_content` 보존, 마지막 사용량·finish_reason)은 `agent/streamReply.ts`의 `createReplyAccumulator`가 맡는다(호출마다 새로 만듦, 조각 처리에 기다림 없음). 요청 준비(저장 링크 후보 조회, 문맥을 서명하는 제공자의 후보 규칙, 현재 시각·맡기기·후보·마무리 안내 조립, 보내기 직전의 마지막 가림, 그 사이의 대상 확인)는 `agent/requestPrep.ts`의 `prepareRequest`가 맡는다 — 대화 상태는 getter로 읽고(옮기기 전 시점 그대로), `targetChangedTurn`·`forceNewConversation`·`activeRequest` 쓰기는 ChatAgent가 넘긴 콜백으로 한다. 마지막 대상 확인(`targetMoved(latest)`)과 `openStream` 호출은 같은 함수·같은 동기 구간이어야 해서(#193 — 확인과 요청 사이에 기다림 없음, `tests/agentRequestModel.test.mjs` R2) ChatAgent.requestModel에 남고, 연결 `try`·중단·화면에서 거두기·stale 확인·사용량 기록·연결 타이머도 그쪽에 남는다. 요청이 어떻게 끝나든(응답을 다 받음·중단·준비 단계의 예외나 stale·대상 바뀜으로 멈춤·연결 실패) 연결 타이머를 지우고, 진행 중 요청(`activeRequest`)은 그 요청의 것일 때만 비운다(#266 — 남으면 `idle()`이 거짓이라 끊김 때 쉬는 대화로 보관되지 않고, 남은 타이머가 나중에 그 요청을 끊는다. 늦게 끝난 옛 요청이 새 요청의 표시를 지우지 않게 소유를 확인). 준비 실패는 호출로 세지 않고 연결 실패만 센다. 턴 시작(`runUserTurn`)은 이 턴의 탭을 지역 값으로 고정한 뒤 탭 잡기·가림 목록 읽기(`warmSecrets`, 성공·실패 모두)를 기다릴 때마다 stale을 확인해, 그 사이 새 턴이 시작됐으면 `this.turnTab`·앞 턴 팝업 잇기(`inheritPopups`)를 건드리지 않고 패널에 오류·답 끝도 보내지 않은 채 조용히 끝낸다(#267). 특수 도구(반복 작업 등록 `scheduleRepeat`·이 페이지 기억 `rememberPage`)는 `agent/specialTools.ts`, 손 넘기기(`handOff`·팝업 감시 `watchHandoffPopups`·사용자가 마친 호출의 결과 `finishHandoff`)는 `agent/handoffFlow.ts`에 있고, 둘이 ChatAgent와 함께 쓰는 호출 문맥(`ToolCallContext`·`STALE`·`DONE`·`logToolFail`)은 `agent/toolCall.ts`에 있다. 대화 상태는 ChatAgent가 주인이다 — 요청 글·외부 본문 보호는 getter로 옮기기 전 읽던 자리에서 다시 읽고, 기록 추가·저장 카드 주소 기록·대기 풀기는 콜백, 탭은 호출마다 받은 고정 인자(`call.turnTab`)다. 카드 대기는 ChatAgent가 넘기는 `waitApproval(callId)`로 한다: 대기 등록(`pendingApprovals.set`)을 그 호출 안에서 동기로 하고 그 Promise를 그대로 돌려준다(async로 감싸지 않음). 원격 대화의 `send`는 카드 대신 거절을 `setTimeout(0)`으로 예약하므로 등록이 그 타이머보다 늦으면 대기가 영원히 풀리지 않는다(마이크로태스크 지연은 괜찮다 — `tests/agentSpecialTools.test.mjs`, 하네스 mcp·telegram의 "원격 요청이 직접 조작할 사이트에서 클릭하면 …"). 풀린 뒤 지우기(`clearApproval`)는 부르는 쪽이 하며, 손 넘기기는 감시 멈춤 → 대기 지움 → 표시 해제 → 팝업 감시 멈춤 순서다. 반복 작업 등록은 실행 방식·맡긴 작업·이번 대화 허락과 무관하게 늘 카드로 묻는다. 원격에서 막는 도구 목록(`REMOTE_BLOCKED_TOOLS`)은 chatAgent.ts의 `handleCall`이 이 모듈들을 부르기 전에 본다. 승인·허락 상태(카드·원격 질문으로 이동을 허락한 사이트 `approvedSites`, 이번 요청 링크 허락 `linkGrant`, 이번 대화 허락 `chatGrants`, 개인정보 주소 허락 `allowedPersonalUrls`, 그 카드들이 보인 제안과 자동 로그인 묶기 선택·sign_in 준비 열쇠)는 `agent/grants.ts`의 `ConversationGrants`가 대화마다 하나씩 가진다(순수 상태 — chrome·저장소·패널 전송 없이 debugLog만, 메서드는 모두 동기). 허락은 그 선택지를 보여 준 카드의 제안만 받아들이고(`acceptOffers` — 대기 중인 카드만, 링크·주소 허락은 같은 턴의 제안만), 승인 판정(`decideApproval`)에는 같은 객체를 읽기 전용 getter로 넘긴다. 지우는 곳은 메서드로 나뉜다: `clearForCancel`(cancelInFlight — 허락 제안만, 받은 허락·로그인 제안은 남김), `clearForReconnect`(suspendForReconnect — 10개 전부), `takeCallOffers`(카드 대기가 끝난 그 callId). 새 기록(ensureCredentials)은 허락을 지우지 않는다. 승인·허락 상태를 더하면 ConversationGrants에 두고 정리 메서드와 `tests/agentGrants.test.mjs`의 필드표를 함께 고친다. 선택 카드의 선택 저장(`setChosen*`·`chooseSignInEntry`)과 승인 대기 풀기는 ChatAgent.approveTool에 남는다(선택 → 허락 → 대화 허락 표시 전송 → 승인 순서), 맡긴 작업(`taskApproved`·`taskEpoch`)과 보호 상태(외부 본문 보호·로그인 값 가림·자동 로그인 시도)도 ChatAgent에 있다.
- **모델 제공자 어댑터** (#97) — 에이전트 루프·번역·저장 링크 초안·키 확인은 `src/lib/providers`의 공통 인터페이스(`openStream`·`complete`)만 씀. 대화 기록·스트림 조각의 내부 기준은 OpenAI 호환 형식이고, 생각 강도는 의도(`agent`·`agent_low`·`off`)로 넘겨 어댑터가 제공자 설정으로 바꿈. OpenRouter·OpenAI·Gemini·Anthropic·로컬 호환 서버 어댑터(Anthropic은 Messages API와 내부 형식을 서로 바꿈, 로컬은 `src/lib/providers/local.ts` — docs/features.md "로컬·호환 서버 제공자"). 제공자가 도구 호출에 붙여 돌려받아야 하는 값(`extra_content`)은 그 제공자 어댑터만 보냄. 어댑터는 `ProviderAuth`(키·로컬 기본 주소)를 받고, 첫 await 전에 fetch를 시작한다(부르는 쪽이 대상 확인 다음 줄에서 부르면 그 사이 설정이 바뀔 틈이 없음). 보낼 대상 고정은 `src/background/modelTarget.ts`(가드 — 준비 뒤 verify, 받은 뒤 assert, 대상이 바뀌면 진행 중 요청 abort)와 번역 세션(`translator.ts` — translate_page 한 번을 대화 대상에 묶은 불투명 id, content는 id만), 대화는 `targetKey` 비교(#193)
- **도구 호출의 내부 키** (#221) — 모델이 준 호출 id(`fc.id`)는 대화 기록의 `tool_call_id`에만 쓴다. 패널 카드(승인·취소)·선택 저장소(탭·링크·다운로드 후보)·content 대상 레지스트리·동작 기록의 키는 `ChatAgent`가 호출마다 만든 내부 키(`k<대화 난수>-<순번>`)다 — 로컬 모델처럼 `call_0`을 주는 제공자에서 패널·텔레그램·MCP 대화가 동시에 같은 id를 써도, 같은 대화가 턴마다 같은 id를 다시 써도 겹치지 않는다. 중단된 호출 블록의 빠진 결과 채우기는 마지막 호출 블록 뒤의 결과만 센다. 하네스 모의 모델은 실제 API처럼 결과가 바로 앞 호출 블록과 맞지 않으면 400으로 거절하고 시나리오마다 확인한다
- **Port 하트비트 + 자동 재연결** — MV3 서비스 워커 유휴 종료 대응. 패널 연결 규칙(#243):
  - 연결은 `useChatSession`의 `connect(reason)` 한 경로로만 연다(처음·예약·즉석). 끊긴 직후(예약 재연결 500ms 전) 보내는 요청은 예약 타이머를 지우고 같은 경로로 바로 연다 — 리스너·heartbeat를 설치하지 않은 임시 포트를 따로 열지 않는다(고치기 전에는 그 포트로 승인 카드가 버려졌다). 연결마다 세대(`gen`)를 올리고 옛 포트의 늦은 메시지·끊김은 무시한다.
  - 같은 패널 문서의 재연결이고 **끊긴 순간** 그 대화에 보낸 요청이 있었으면(`resumeNeeded` — 빈 패널에서 끊긴 직후 보낸 첫 요청은 이을 대화가 아니라 묻지 않음) 그 포트의 첫 메시지로 `resume_conversation {conversationId, gen}`을 보낸다(같은 포트는 순서대로 처리되어 user_msg보다 먼저 닿음). 답 `conversation_resume`은 지금 세대·지금 대화일 때만 받는다(`acceptResume`).
  - 백그라운드는 연결이 끝나면(`close()`, 연결마다 한 번) 쉬던 대화(`ChatAgent.idle()` — 턴·승인 대기·모델 요청·도구 없음)를 `suspendForReconnect()`로 허용을 넓히는 상태를 지운 뒤 같은 워커 메모리에 60초·최대 4개 보관하고(`ParkedConversations`, 저장하지 않음, 만료·밀려나면 abort), 진행 중이던 대화는 지금처럼 멈추고 버린다. 보관한 대화는 확장 화면 sender의 `resume_conversation`으로만 한 번 꺼내 `attachPort()`로 새 포트에 붙인다(사용자 요청 메시지로는 꺼내지 않는다). 지우는 것: 대화 허락·맡긴 작업·이동 허락 사이트·링크 허락·개인정보 주소 허락·자동 로그인 선택·행 기준(#233). 남기는 것: 기록, 보호 상태(외부 본문 보호·로그인 값 가림·자동 로그인 시도), 기록 형식 상태, 디버거 세션(사용자의 디버깅 취소 선택 — 연결은 abort가 뗌).
  - 대화 상태를 지우는 경로(새 상태를 더하면 어디서 지울지 정한다). 새 대화는 `index.ts`가 새 `ChatAgent`를 만들어 저절로 비워진다. 같은 대화 안에서는 다음 넷이다(지금 동작 그대로 — 경로마다 지우는 것이 다르다).
    - `cancelInFlight()`(턴 시작·`abort()`): 진행 중 모델 요청·도구·원격 질문을 멈추고 승인 대기를 거절로 풀며, 링크·대화·개인정보 주소 허락 제안을 지운다(`ConversationGrants.clearForCancel()`). 로그인 사이트 제안·자동 로그인 선택·로그인 토큰은 지우지 않는다(카드 대기가 끝나면 호출별로 지움 — `takeCallOffers(callId)`).
    - `abort()`: 턴 세대를 올리고 `cancelInFlight()`, 번역을 멈추고 디버거 연결을 뗀다(디버거 세션 객체·취소 선택은 남김).
    - `suspendForReconnect()`: `abort()`에 더해 위 "지우는 것"(허락·제안 전부 — `ConversationGrants.clearForReconnect()`, 맡긴 작업, 행 기준).
    - 새 기록(`ensureCredentials` — 제공자·모델·키·주소·지침·빠르게 생각이 바뀌었거나, 이미 보낸 저장 링크 후보를 거둘 수 없어 멈춘 뒤): 기록·행 기준·사용량 누계·첨부 PDF·저장 링크 후보를 지우고 맡긴 작업을 거둔다. 허락(이동 허락 사이트·링크·대화·개인정보 주소)과 외부 본문 보호는 남긴다.
  - 잇지 못하면(워커 재시작·만료·진행 중이었음) 패널이 "앞 대화를 이어 가지 못했습니다" 안내를 띄우고 다음 요청은 새 대화가 된다. 같은 대화에서는 새 요청을 보내기 전까지 한 번만(`LostNotice`). 끊길 때 응답 중이었거나 미결 카드가 있으면 패널이 `dropLocal()`로 응답 중 표시를 끄고 카드를 취소로 닫는다(수동 중단 없이 다음 요청 가능, 안내에 "진행 중이던 요청을 멈췄습니다").

- **클릭·입력 확인 경로** — `find_clickables`·`find_form_fields`가 준 id마다 그때의 대상 기술(역할·글자·주소·영역·목록 순번·대상이 든 행의 글자)을 content script 메모리에 둠. 승인 카드를 띄울 때 지금 요소가 그때와 같은지 확인해 사람이 알아볼 수 있게 보여 주고(비밀번호 칸은 값을 가림), 실행 직전과, 클릭은 스크롤·포커스 뒤 누르기 바로 앞에서 다시 승인한 기술과 같을 때만 실행. 요소가 다시 그려져 사라졌으면 비슷한 요소로 대신하지 않고 멈춤(다시 찾아 새로 승인). 클릭 대상은 모델에 준 묶음 문맥과 상태도 비교함(승인 뒤 이미 체크·펼침으로 바뀐 대상을 누르면 반대로 되므로 멈춤). 입력 칸도 모델에 준 행 문맥과 '보이는 label로 바꾸는 칸' 여부를 비교함. 다만 입력 도중(입력 처리기 뒤 change 전, 같은 묶음에서 앞 칸을 채운 뒤의 칸)과 입력 뒤 반영 확인에서는 원문 행 글자가 그대로이고 모델용 행 문맥에 글자가 더해지기만 한 것(행 안의 숨은 안내 글이 보이게 됨 — 승인 당시 낱말이 같은 순서로 모두 남음)은 허용함. 문구를 바꿔 보여 주는 것은 거부(#43 C의 오탐을 늘리지 않게). 대상이 든 행의 글자만 바뀐 경우(row_drift — 운임 갱신·장바구니 합계 등)와 클릭이 그 행·항목 글자를 바꾼 경우(#233)는 공용 기준을 바꾸지 않고, 바뀐 글자(행은 모델용 행 글자, 항목은 항목 글자 전체)를 결과로 보여 준 뒤 그 상태를 **대화별 기준**(nonce, 모델에 보내지 않음)으로 남긴다: 결과를 기록에 넣은 대화만 가져가고(`src/background/tools/rowRebase.ts`), 그 결과를 실은 모델 요청의 응답이 온 뒤에만 그 대화의 대상 확인에 넘긴다(같은 응답의 뒤 호출·다른 대화·기록을 비운 대화는 쓰지 못함, 승인 기록의 항목 글자도 고른 기준으로 고정). 모델용 행 글자가 200자에서 잘린 행은 바뀐 곳이 보이지 않을 수 있어 기준을 만들지 않고 다시 찾게 한다. 한계: 찾기 기준(공용)은 문서마다 하나라, 같은 문서를 다루는 다른 대화가 다시 찾으면 그 기준으로 바뀐다(#233 이전부터). 목록 다중 선택은 지침으로 '전체 선택' 대신 항목별로 고르고, 지우기·옮기기 같은 되돌리기 어려운 동작 전에는 고른 목록을 사용자에게 확인받으며, 화면 밖 항목은 다음 페이지 링크로 넘김(스크롤로만 더 불러오는 목록은 미지원).
- **선택지와 트리거의 관계** (#43 B) — 선택지(option·menuitem*)는 펼쳐진(aria-expanded=true) 트리거와의 관계를 구조로만 정함: aria-controls/aria-owns로 선택지나 그 목록을 가리키는 펼친 트리거가 정확히 하나면 linked(직접 연결이 없을 때, 펼친 트리거들이 가리키는 요소 중 목록을 감싼 것이 정확히 하나인 aria-controls이고, 그 요소가 최상위 문서의 shadow DOM 밖에 있으며 목록·트리거 안에 있지 않고, 그 안에 이 목록 말고 다른 목록·트리거·shadow root·슬롯·프레임이 없을 때만 같은 연결로 봄 — Google 항공편 공항 추천), 연결이 없고 펼친 트리거가 0~1개면 unlinked, 펼친 트리거가 둘 이상이고 연결이 없으면 nearest를 시도(선택지 목록에서 위로 6단계 안에 트리거를 품는 첫 묶음이 트리거를 정확히 하나 — 그것이 펼쳐짐 — 와 그 목록 하나만 담고, body·html이 아니며 숨은 트리가 없고, 트리거가 중첩 메뉴 항목이 아닐 때만 그 트리거; 출발·도착 칸마다 목록을 붙이는 자동완성). nearest는 구조로 추정한 관계라 실행 방식(자동·맡긴 작업 포함)과 관계없이 늘 승인 카드로 묻고 카드에 추정임을 표시(approvalDecision `inferredChoice`). 그 밖(위로도 정할 수 없음·연결 둘 이상)은 클릭 대상으로 돌려주지 않고 find_clickables 결과 note에 뺀 수(`unrelatedChoices`, 이번에 본 범위)를 알림. 선택지 결과에는 그 목록을 연 칸의 라벨 `listFor`(트리거의 modelName — 입력값 제외, 같은 이름·이름 없음이면 "칸 n")를 붙임(표시용, 판정은 내부 관계). 관계(트리거·목록 요소, 연결 방식, 트리거 기술)는 승인 카드 때·실행 직전·스크롤과 포커스 뒤에 다시 계산해 같아야 누름. 트리거의 위험 정보(결제 화면·개인정보가 채워진 양식·제출 주소 등)는 선택지와 따로 background로 보내 승인·사이트 판정을 양쪽 모두에 적용(포털로 그린 목록이라도 트리거가 결제 대화상자 안이면 카드). 트리거 자신이 다른 목록 안의 항목인 중첩 메뉴의 항목은 상위 트리거들의 위험을 따라가지 않으므로 자동 실행하지 않고 늘 카드로 물음. 한계: unlinked는 소속을 증명하지 않음 — ARIA 펼침 상태를 표시하지 않는 위젯이 같은 목록을 넘겨받는 경우는 구조로 구분할 수 없음(공유 팝업 안의 일반 버튼과 같은 한계). ARIA 역할이 없는 div·li 위젯, pointerdown·keydown에만 반응하는 위젯은 지원하지 않음 승인은 그 호출에 한 번만 쓰임. id에는 페이지마다 바뀌는 꼬리표가 붙어 이전 페이지의 id는 거부
- **실행 결과 확인** — 클릭 뒤 이동 종류(없음·페이지 안 위치(#)·같은 사이트·다른 사이트·오류), 페이지 안 주소 변경, 새 탭, 팝업 창(열림·막힘·닫힘), 화면 변화(DOM 변경 수·대화상자)를 결과로 돌려줌. 입력은 페이지 처리가 끝날 틈(150ms)을 둔 뒤 칸마다 값을 다시 읽어 실제로 반영됐는지 알려 줌
- **설정 화면의 동기화** (#127) — 설정 화면은 여러 개·오래 열릴 수 있어 화면이 들고 있는 값이 옛 값이 될 수 있다. 일반 설정은 `useSettings`(저장소 구독 — 첫 조회가 변경 알림보다 늦게 오면 버림) 위에 보내지 않은 변경을 얹어 보이고, 바뀐 필드만 `settings_patch`로 보낸다. 따로 상태를 들고 있는 칸(API 키·음성 입력 모델·MCP 포트)은 `useSyncedDraft`로 저장 값과 편집 초안을 나눠, 고치지 않은 칸은 다른 곳의 변경을 따라가고 고치는 중이면 초안을 두고 "다른 곳에서 바뀌었습니다"를 보임. 백그라운드에서 읽어 오는 목록·상태(저장 링크·반복 작업·동작 기록·페이지 제안·텔레그램·MCP·KeePassXC·Google)는 해당 저장소 키(Google은 `googleAuthVersion`, KeePassXC는 선택 권한 변경도)가 바뀌면 다시 읽고, 요청 순번(`useLatestGate`)으로 마지막 요청의 응답만 쓴다. MCP 비밀이 다른 곳에서 새로 만들어지면 보이던 비밀을 지운다. 페이지 제안 고치기는 시작할 때의 규칙 버전과 같을 때만 저장된다. 숨겨지기만 한 화면은 남은 변경을 일반 저장으로 보내 오류를 추적한다(닫히는 pagehide만 최선 노력). 목록형 승인 설정은 docs/security.md "목록형 승인 설정의 저장"
- **동작 기록** — 승인한 클릭·입력마다 페이지 구분 키(주소 틀 + 페이지 뼈대 해시), 대상 요약, 결과(완료·일부 반영·직전 중단·실패·취소)를 `chrome.storage.local`에만 남김. 주소 틀은 사람이 붙인 이름처럼 보이는 경로 낱말만 남기고 숫자·토큰·이메일·한글 이름 같은 칸은 자리표시로 바꾸며, 쿼리는 이름만 남김(`/board/{n}/view?id`). 대상 이름에 섞인 주소·이메일·key=value·긴 숫자·비밀 값처럼 보이는 낱말도 가림. 입력 칸은 이름 글자 대신 해시만 남기고(값·숫자를 지운 뒤 계산), 비밀번호·결제 칸은 해시도 남기지 않음. 뼈대 해시는 랜드마크·목록·표·폼의 중첩만 보고 같은 틀의 목록 항목은 하나로 접어, 내용과 항목 수가 달라도 같은 값. 입력 값, 대상이 든 행의 글자, 링크 주소의 값은 남기지 않고, 실패 이유도 문구 대신 분류만 남김. 시크릿 창은 기록하지 않고, 30일·500건·약 1MB를 넘으면 오래된 것부터 지움(한 항목의 대상은 20개까지). 설정에서 끄거나 지울 수 있음. 나중에 같은 구조의 페이지에서 동작을 다시 쓰는 레시피의 재료
- **찾기·실행 도구가 모델에 보내는 글자** (#43) — 원칙은 "화면 글자는 보내고, 사용자가 입력한 값은 보호". `find_form_fields`·`find_clickables`·`fill_form_fields`·`click_element`·`query_dom`의 결과와 오류 문구에는 페이지가 만든 글자(라벨·버튼 글자·select 선택지 글자)만 담고, 입력 칸(input·textarea·select)의 값·편집 영역(contenteditable, 그 안의 contenteditable=false 섬 포함)·숨은 요소(hidden·aria-hidden·display:none·visibility:hidden)의 글자는 구조로 빼고 모음(`src/content/modelText.ts`). 시작 요소의 조상(shadow host·슬롯·같은 출처 프레임 포함)이 보호 영역이면 이름도 비움. 모델에 돌려준 이름은 대상 비교에도 넣어, 원문은 같아도 모델이 본 이름이 바뀌면 다시 찾게 함. 페이지 번역(`translate_page`)도 같은 판정으로 편집 영역 글자를 보내지 않음(#256, `src/content/translate.ts`의 `textProtected`). 범위: 이번에 좁힌 것은 이 도구들의 반환 계약뿐. 본문 읽기(`describe_page`·`get_page_content`)는 편집 영역을 포함한 화면 글자를 그대로 읽고, 주소(URL)는 주소창에 보이는 화면 정보로 보고 지금처럼 보냄(#44 결정). `query_dom` 선택자는 허용 문법만 받는 파서로 검사하고 값에 기대는 조건을 실행하지 않음(#45, `src/lib/selectorPolicy.ts`): 태그·#id·.class·[속성]·구조 의사 클래스·결합자만(이스케이프·주석·함수·의사 요소 등 브라우저와 해석이 갈릴 수 있는 형태는 거부), 속성 값 비교는 구조 속성(id·class·name·type·role·href, aria-label·aria-expanded 같은 구조·상태 aria)에만, `[value]` 존재 조건과 입력값 상태 의사 클래스(`:valid`·`:placeholder-shown`·`:dir()` 등)는 거부(`:has()`·`:is()`·`:not()` 안쪽 포함)
- **읽기 레시피** — 같은 페이지 키(주소 틀 + 뼈대 해시)에서 내용을 읽는 데 통한 `query_dom`·`list_file_links`·`find_clickables` 호출(선택자·검색어)을 턴이 정상으로 끝날 때 기억함. 한 턴에서 같은 도구를 고쳐 가며 부르면 마지막으로 결과가 나온 호출만 성공으로 셈. 다음에 같은 구조의 페이지에서 `describe_page`를 부르면 결과의 `readHints`에 후보로 붙이고(자동 실행은 하지 않음), 모델이 먼저 시도함. 기억한 호출이 빈 결과를 3번 연속 내면 버림. 이메일·주소·긴 숫자·비밀 값처럼 보이는 인자는 저장하지 않고, 페이지 내용은 남기지 않음. 페이지당 3개·전체 300개·30일 한도. 동작 기록 설정 하나로 함께 켜고 끄고 지움. 디버그 로그에 제안한 레시피(`read_recipe:offered` 도구·인자·성공 수)와, 모델이 제안과 같은 도구·인자로 다시 부른 것(`read_recipe:used`, 결과 유무)을 남김(#156)
- **문서 요청 안전장치** — 리다이렉트는 따라가지 않고 목적지 주소만 알려 줌(`webRequest`로 관찰). 그 주소로 다시 읽으면 새 승인 카드가 뜸. 웹 페이지·이미지·압축 파일 등 문서가 아닌 확장자는 요청하지 않음. 확장자 없는 링크는 승인 카드에 따로 경고
- **kordoc 브라우저 번들** — kordoc는 Node용이라 `vendor/kordoc/`에서 따로 설치해 브라우저용으로 묶은 결과물을 커밋해 씀(`npm run vendor:kordoc`로 다시 만듦, [vendor/kordoc/README.md](../vendor/kordoc/README.md))
