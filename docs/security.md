- **페이지 기억하기 · 저장 링크 (설정, 기본 켜짐, #30·#86)** — 답을 마친 뒤 탭이 다른 화면(해시 포함)에 있으면 "이 페이지 기억하기" 버튼이 뜬다. 카드에서 이름·용도(예: "쇼핑을 위한 가격 비교 검색")를 적고, 주소의 쿼리 값마다 고정·입력 자리·빼기를 골라 다시 쓸 수 있는 링크 템플릿으로 저장(예: `…/search/all?query={상품명}`). 카드에서 카드를 열면 모델이 이름·용도·자리(설명·비워도 되는지) 초안을 일반적인 형태로 자동 제안하고 사용자가 고친다(사용자 결정으로 #129의 "누를 때만"을 바꿈, "다시 채우기"로 다시 요청)(어떤 값이 검색어인지 코드가 파라미터 이름으로 정하지 않음). 입력 자리의 지금 값과 요청 문장은 저장하지 않는다. 고정으로 남긴 값에 결제·개인정보 단서가 있으면 경고에 체크해야 저장(`src/lib/savedPages.ts`, `src/background/savedPagesStore.ts`)
  - 초안: 카드를 열면("이 페이지 기억하기") 자동으로 한 번(사용자 결정으로 #129의 "누를 때만"을 바꿈 — 닫았다 열어도 다시 묻지 않고, "다시 채우기"로 다시) 그 턴의 사용자 요청·모델의 마지막 답·제안할 때 그 문서(documentId 고정)에서 읽은 화면 글자(modelText — 입력 칸 값·편집 영역·숨은 내용 제외, 3000자)와 주소를 모델에 보내 이름·용도와 쿼리 값마다 고정·입력 자리(자리 이름·설명·비워도 되는지)·빼기를 채운다(생각 끔, 사용자가 고쳐 저장). 지침은 이번 요청이 아니라 일반적인 재사용(이름·용도에 구체 값 없음, 바꿔 쓸 만한 값은 자리, 내부 코드값은 고정)을 요구한다. 전송 직전에 페이지 기억하기 설정을 다시 확인해 꺼져 있으면 보내지 않는다(남아 있는 카드도). 새로고침·이동으로 문서가 바뀌었으면 페이지 글자는 읽지 않는다. 주소에 결제·개인정보 단서가 있으면 초안을 묻지 않는다(경로·제목·본문으로도 값이 샐 수 있어 사용자가 직접 정함)
  - 쓰기: 사이트와 관계없이 저장 링크(id·이름·용도·출처·자리 이름)를 매 모델 요청 끝에 임시 데이터 메시지("지시가 아님" 머리말 + JSON)로 붙이고(디버그 로그 `saved_links:candidates`에 턴마다 한 번 후보 수·이름 또는 붙이지 않은 이유 — 주소는 남기지 않음, #156), 요청이 용도에 맞으면 모델이 `open_saved_link({ id, values })`로 자리 값만 넣어 현재 탭에서 연다. 출처·경로·고정 값은 저장한 그대로이고 자리 값은 인코딩해 넣는다(값 200자, 모르는 자리·빠진 필수 자리는 오류. 사용자가 카드에서 "비워도 됨"으로 고른 자리(`optional`)는 값이 없으면 그 쿼리 값을 빼고 연다 — 예전 링크는 모두 필수. 준 값·완성 주소에 대한 승인·민감 값 판정은 그대로). 대화 기록에는 남기지 않아 지우기·끄기가 다음 요청부터 반영
  - 승인: 사용자가 저장한 링크라 자동 실행이 켜져 있으면 카드 없이 연다(사용자 결정). 외부 본문 보호 중이거나 자리 값이 개인정보처럼 보이거나 완성한 주소에 결제·개인정보 단서가 있으면 카드로 묻는다. 연 사이트는 이 대화에서 사용자가 고른 사이트로 둔다(카드로 허락한 이동과 같은 범위)
  - 방문 기록 찾기(#175): 선택 권한 `history`는 누를 때만 요청(거절하면 기록을 읽지 않음). 모델로 가는 것은 확인 화면에 보인 스냅샷 중 사용자가 체크한 항목의 제목(80자)·출처+경로(200자)·쿼리 이름(앞 10개, 30자)뿐 — 쿼리 값·방문 통계는 보내지 않는다. 자동 로그인 값이 있는 주소는 후보에서 빼고, 결제·개인정보 단서(낱말)가 보이는 주소는 ⚠와 함께 기본으로 체크하지 않는다(사용자가 골라야 보냄 — 낱말은 더 묻는 쪽으로만). 보낼 곳(제공자·모델)과 설정 세대를 준비할 때 고정해, 보내기 전 설정이 바뀌었으면 보내지 않고 보내는 중 바뀌면 멈춘다. 작업은 패널 🕘 시트의 포트(`history_pick`, 확장 화면 발신만)에 묶여(시트를 닫으면 취소) 한 번만 보낸다. 모델 응답의 번호는 보낸 항목만, 카드는 추천한 항목만 만든다(주소는 백그라운드가 보관한 원본). 추천 카드는 초안을 다시 묻지 않아 보낸 범위가 넓어지지 않는다. 패널 창이 시크릿이면 거절
  - 페이지 제안(#173): 규칙은 사용자가 만든 것만(출처·경로 패턴은 구조 비교, 낱말로 뜻을 추론하지 않음). 칩은 제안일 뿐 실행·승인 면제가 아니다 — [실행]을 누르면 백그라운드가 설정·규칙 버전·패널 창 활성 탭·주소·문서를 다시 확인하고 저장된 요청(패널이 보낸 글자 아님)을 일반 요청으로 보낸다. 제안 턴은 팝업을 잇지 않고, 문맥을 읽기 전후(PDF는 받기 전)에 문서·주소를 확인해 바뀌었으면 기록·모델 요청 없이 멈춘다. 규칙 저장 때 자동 로그인 값이 있으면 거절. 칩을 띄우는 데 모델·페이지 글자를 쓰지 않는다
  - 기억하기 버튼(#174): 패널 창(`chrome.windows.getCurrent`)의 활성 탭만(`src/background/panelTarget.ts`, 시크릿 창 거절). 패널이 보인 탭·주소와 다르거나 문서를 확인하지 못하거나 읽는 사이 문서·주소가 바뀌면 만들지 않음. 초안에는 요청·답 없이 탭 제목·주소·화면 글자만. `remember_page` 도구도 문서 확인 실패면 거절하고 주소까지 고정
  - 최대 20개, 넘으면 가장 오랫동안 쓰지 않은(마지막으로 연 시각) 링크를 지움(저장 카드에 미리 보임). 저장 순간 실제로 지워질 링크가 카드가 예고한 것과 다르면 저장하지 않고 새 예고로 다시 확인받음. 지난 형식(주소 하나)은 자리 없는 템플릿으로 옮김. 설정에서 이름·용도 고치기·지우기. 시크릿 창은 저장·후보 제공 없음
- **페이지 번역과 편집 영역 (#256, #43 기준)** — 번역은 화면 글자만 모델에 보낸다. 편집 영역 글자(편집 호스트 안 전부·input·textarea·select·designMode 문서)는 번역하지 않는다: `inProtectedArea`(찾기·실행 도구와 같은 판정)로 처음 훑기·관찰 큐 진입·보내기 직전·쓰기 직전에 걸러, 응답을 기다리는 사이 편집 가능해진 노드도 보내지도 쓰지도 않는다. 제한: 번역을 적용한 뒤 편집 가능해진 노드는 원문으로 자동 복원하지 않는다. `describe_page`·`get_page_content`가 읽는 편집 영역 글자는 이 변경의 범위 밖(사용자 결정 대기)
- **현재 시각** — 매 모델 요청 끝에 사용자 컴퓨터의 날짜·요일·시각(분 단위)·시간대 이름·UTC 오프셋을 "사용자 글 아님" 안내로 붙인다(대화 기록에는 넣지 않음). 모델이 지난 연도로 검색·예약하지 않게 하려는 것으로, 시간대(예: Asia/Seoul)가 OpenRouter와 모델 제공자에 전달된다
- **외부 본문 보호** — 파일 읽기(`read_document`)·첨부 파일 저장(`download_files`, 결과에 서버가 정한 파일 이름)·Google 도구·PDF 첨부처럼 외부 유래 데이터가 대화에 들어오면(성공·실패 모두) 그 대화에서는 페이지를 바꾸지 않는 관측 도구(`describe_page`·`get_page_content`·`list_page_images`·`list_file_links`·`query_dom`·`find_clickables`·`find_form_fields`) 외의 모든 도구를 자동 실행·링크 이동 허락과 관계없이 승인 카드로 물음(맡기기 방식으로 작업을 맡긴 동안은 제외, #123)(외부 내용을 신뢰 사이트의 검색어·입력값·번역 언어·Google 검색어로 내보내지 않게). "이번 대화 동안 묻지 않기"(#53)도 번역·이미지 저장에는 쓰지 않고, 페이지가 준 주소만 쿠키 없이 읽는 `read_linked_pages`에만 씀. 보호가 켜진 대화에서는 읽기 레시피를 저장하지 않음(보호 대상에서 유래한 인자가 새 대화로 넘어가지 않게). 이 기능 전에 저장된 레시피는 출처를 알 수 없어 새 저장소 세대로 바꾸며 지움(힌트로 쓰지 않음). 새 대화에서 해제. 도구 분류는 `src/lib/toolPolicy.ts`(모든 도구를 빠짐없이 분류해야 타입 검사 통과). 찾기·승인·실행 어디에서도 페이지에 대상 표시 속성을 쓰지 않음(id는 content script 메모리의 요소 → id 표로 관리)
- **음성 입력 (#184)** — 음성은 사용자가 설정에서 고른 음성 제공자 한 곳으로만 보낸다(대화 제공자와 다를 수 있어 녹음 중 그 이름을 보임). 보낼 곳은 녹음을 시작할 때 백그라운드가 고정하고, 보내기 직전·보내는 동안 설정(제공자·모델·언어·키)이 달라지면 보내지 않거나 멈춘다. 녹음은 버튼을 누른 동안만(최대 60초) 하고 녹음 데이터는 메모리에만 둔다(저장·로그 없음). 패널 → 백그라운드는 base64 WAV(디코딩 기준 4MB, 머리글 검사), 받은 글자는 2,000자까지 입력창에 넣고, 바로 보내기(기본 켜짐, 사용자 결정)면 그대로 보낸다 — 잘못 알아들은 글도 요청이 되므로 설정 도움말에 끄는 방법을 적음. 보낸 요청은 입력해 보낸 요청과 같게 승인 규칙을 따른다(사용자가 직접 입력한 요청과 같음 — 페이지 글자·입력칸 값과 무관, #43 영향 없음). 오류에는 제공자 상태 코드와 짧은 메시지만(키·음성 없음). 모델 ID·언어 코드는 구조로만 검사. 새 권한 없음(마이크는 웹 권한, 확장 출처로 받음)

- **자동 로그인** — KeePassXC와는 native messaging(`keepassxc-proxy`, 선택 권한 `nativeMessaging`)과 KeePassXC-Browser 프로토콜(세션마다 새 키, 응답 nonce 확인)로만 주고받고, 연결 승인·사이트별 접근 허락은 KeePassXC 창에서 사용자가 한다. 받은 값은 그 호출의 메모리에만 두고 결과·오류·로그에 싣지 않는다. 출처는 모델 인자가 아니라 브라우저가 아는 탭 주소로 정하고, 자동 실행은 그 출처에 묶은 항목이 KeePassXC 응답에 있을 때만 한다. 승인한 사이트라도 https가 아님·다른 사이트에 끼워 넣은 칸·다른 출처로 보내는 양식·POST가 아닌 제출·새 비밀번호 칸·삭제·결제 신호·외부 본문 보호 중·이 대화에서 이미 시도한 출처면 카드로 묻는다. 넣은 값(아이디 포함)은 브라우저를 끌 때까지 가림 목록(`chrome.storage.session`)에 두고, 도구 결과를 기록에 넣을 때와 모든 모델 요청(대화·번역·저장 링크 초안)에서 그 값과 흔한 표현(URL·폼 인코딩, HTML 엔티티, base64, JSON 이스케이프, 공백 정리, 잘린 앞·뒷부분)을 `[가린 값]`으로 바꾼다(페이지 스크립트가 값을 바꿔 쓰는 것까지는 막지 못함 — 페이지 자체는 넣은 값을 읽을 수 있으니 믿는 사이트만 승인)
- **목록형 승인 설정의 저장 (#127)** — 직접 조작할 사이트(빠지면 대신 클릭·입력하게 됨)와 자동 로그인 승인 목록은 화면이 들고 있는 배열 전체를 저장하지 않는다(여러 설정 화면이 옛 목록을 들고 있으면 뺀 항목이 되살아난다). 화면은 항목 하나의 변경(`manual_site_op`·`login_site_op`)만 보내고, 백그라운드가 확장 화면 발신·값(정규화한 출처, 승인 식별자 형식)을 검사한 뒤 저장 직렬화 안에서 그때의 저장 목록에 적용한다(`src/lib/settingsOps.ts`). 자동 로그인 항목은 승인할 때마다 새 `grantId`를 받고(같은 항목으로 다시 승인해도), 빼기·코드 변경은 사용자가 보던 승인의 grantId와 지금 값이 같을 때만 적용한다 — 다시 승인할 때 코드 자동 입력을 끄는 보호를 옛 화면이 되돌리지 않게. 식별자가 없는 옛 항목은 백그라운드가 시작할 때 한 번 채워 저장한다. 백그라운드 설정 캐시는 읽는 사이 저장으로 무효화되면 옛 조회 결과를 넣지 않고 다시 읽는다(`src/lib/genCache.ts` — 옛 제공자·모델·키로 보내지 않게).
- **동작 기록·읽기 레시피 메시지의 발신자 (#297)** — `action_log_count`·`action_log_clear`·`recipes_list`·`recipe_delete`는 `settings_patch`와 같이 이 확장의 화면 발신(`sender.id === chrome.runtime.id`이고 `sender.url`이 확장 URL로 시작)만 받는다. content script·웹 페이지가 보낸 것은 "허용되지 않은 요청"으로 거절해, 페이지가 저장된 읽기 방법(주소 틀·선택자)을 읽거나 기록을 지우지 못한다. `recipe_delete`의 key는 문자열 배열(최대 400개)만 받고, 지울 때 그때의 저장 목록에서 그 key만 뺀다(화면이 든 목록을 통째로 저장하지 않음 — #127 원칙). 목록에는 자동 로그인 값이 보이는 항목을 넣지 않고(비동기 검사, 가림 목록을 못 읽으면 오류), 값은 React 텍스트로만 보인다. 레시피 목록·삭제는 후보 제시용 저장소만 바꾸며 승인 판정의 입력이 아니다.

- **원격 요청의 승인 (#185)** — 텔레그램·MCP 요청은 패널과 같은 판정 규칙을 쓰고, 카드가 필요한 호출은 카드 대신 원격 채널로 묻거나 거절한다. 원격 질문은 패널 카드 글이 아니라 `src/lib/remoteApproval.ts`가 모델에 보낸 글(`modelName`·`modelContext`)과 코드가 만든 고정 문구로만 만든다(원문 대상 글자·입력값·편집 영역 글자는 넣지 않음, #43). 묻는 것은 이동(주소 전체·출처)과 클릭(역할·모델용 이름·행 문맥·위치·체크 상태·대리 라벨 경고·페이지 출처·링크 주소)과 도구 한도(수치·도구별 횟수 — 결과 글은 넣지 않음), 그리고 #192에서 더한 입력(페이지 출처 필수, 칸마다 모델용 이름·칸 종류·위치·넣을 값(모델 인자) — 비밀번호는 글자 수만, 체크·라디오와 이름이 겹치는 칸은 행 문맥 필수, 결제 칸·이름 없거나 잘린 칸·트리거가 있는 칸·제출/요청 주소가 있는 칸·지금 값이 있으면 묻지 않음)·파일 읽기(주소·출처·로그인 쿠키 고정 안내)·화면 캡처(대상 host·전체 여부·저장 폴더·이미지에 담기는 것 고정 안내)·이미지/파일 저장과 링크 읽기(원격에서 고를 수 없어 기본 선택만 — 그 주소와 코드가 만든 짧은 경고, 쿠키 사용 고정 안내, 미리보기에서 정리해 확정한 폴더)다. 사유 줄은 원문 이름이 섞일 수 있는 자동 실행 예외 글 대신 고정 문구만 보인다. 그 밖(다른 탭 읽기·Google 쓰기·트리거 선택지 클릭·손 넘기기)은 원격으로 묻지 않고 거절(텔레그램 task 모드는 #185대로 맡긴 뒤 실행). 대상 이름·문맥이 한도에서 잘렸거나(`modelNameClipped`·`modelContextClipped` — 실행 직전 비교에도 포함), 링크 주소 말고 다른 목적지(양식 제출 등)가 있거나, 주소가 1000자·질문이 2000자를 넘거나, 자동 로그인 값이 들어 있으면(목록을 못 읽으면 들어 있다고 봄) 자르거나 가리지 않고 묻지 않는다. 원격으로 허락한 이동의 출처는 카드로 허락한 이동과 같게 그 대화의 자동 실행 범위가 된다(결제·삭제·개인정보는 계속 묻는다). 텔레그램은 묻기가 켜져 있으면 실행 방식이 '처음에 승인 받고 끝까지 실행'이라 작업 맡기기를 묻는다(`remoteTaskQuestion`): 사용자가 그 채팅으로 보낸 요청 글(500자)·모델이 `confirm_task`로 넘긴 할 일·위험(자르지 않음 — 넘치면 묻지 않음)·효과 고정 문구("이 요청이 끝날 때까지 결제·삭제·다른 사이트 이동도 묻지 않음"), 모델이 맡기지 않고 부른 첫 동작은 위 이동·클릭 재료(`remoteActionLines`)로만 보이고 못 만들면 묻지 않는다(패널의 "첫 동작" 카드 글은 쓰지 않음). 맡긴 범위는 요청 하나이고, 묻기를 끄면 즉시 거둔다(`RemoteRunner.withdrawTask`), 묻는 사이 거두거나 끄면 그 승인은 쓰지 않는다(세대·실행 방식 재확인). 맡긴 뒤에도 자동 로그인·저장 링크·반복 작업 등록·페이지 기억은 원격에서 거절. 거절·응답 없음·물을 수 없음은 실행하지 않고 도구 없이 마무리

- **로그인된 탭으로 링크 읽기 (#293, `read_links_in_tabs`)** — 쿠키 없이 받는 `read_linked_pages`와 달리 사용자의 로그인 상태(쿠키)로 브라우저 탭에서 연다. 사용자가 그 링크를 누른 것과 같다: 페이지 스크립트가 실행되고, 읽음 표시·조회 기록 같은 흔적이 남을 수 있으며, 브라우저가 리다이렉트를 따라 다른 사이트로 넘어갈 수 있다. 그래서 `read_linked_pages`는 그대로 기본 수단이고, 이 도구는 그걸로 읽지 못했을 때만 쓰도록 선언·지침에 적는다(본문이 로그인 안내뿐인지의 판단은 모델 — 코드는 낱말을 보지 않음).

  - 남는 위험: 탭 id를 저장소에 기록하기 직전에 서비스 워커가 죽으면 그 탭은 남는다(사용자가 닫아야 함). 확장자 없는 다운로드 링크는 걸러내지 못해 탭을 열면 파일이 내려받아질 수 있다(사용자가 그 링크를 누른 것과 같음). GET만으로 동작하는 링크(로그아웃·구독 해지 등)를 모델이 고르면 실행된다 — 카드가 방어선이고, task 방식에서는 맡긴 작업이 덮는다(기존 `navigate_to_url`·`click_element`와 같은 수준). 뒤에서 연 탭에서는 화면에 보일 때만 그리는 페이지가 본문을 못 낼 수 있다(그때는 본문 없음 오류 → navigate_to_url 안내).
- **반복 작업 확인 작전 (#284)** — 작전(볼 영역 선택자·기준점·모양 설명·판단 기준·안 맞는 신호)은 확인용 탭의 페이지를 보고 모델이 만든 글이라 **페이지에서 유래한 믿을 수 없는 데이터**로 다룬다. 보내는 범위를 좁히기만 하고 판정·할 일·승인을 넓히지 못한다: 작전 영역만 보고 확정하는 판정은 unmet뿐이고, 그 밖의 판정(met·blocked·login_required·unknown·off_plan)과 영역 호출 실패는 같은 회차에 전체 화면으로 판단해 그 결과를 쓴다(작전 글만으로 알림·멈춤·실패 누적을 일으킬 수 없음 — 남는 위험은 잘못된 unmet으로 알림을 놓치는 것으로, 검산 회차가 줄인다). **변화 없으면 생략**은 늘 unmet만 기록하고(met·blocked를 만들지 않음), 영역 판단이 unmet을 확정한 직전 회차와 영역 관측 전체(제목·최종 주소·선택자·영역 글자·영역 버튼의 모든 상태 — 영역 판단 프롬프트와 같은 객체)가 같을 때만이다. 관측 글자는 저장하지 않고 SHA-256만 저장한다. **검산 회차**(10회차째·6시간)는 저장된 회차 수·시각(코드가 센 값)으로만 정해 페이지에서 유래한 값으로 건너뛸 수 없고, 영역·전체를 둘 다 물어 전체 판정을 쓰며, 다르면 작전을 다시 만든다. 자동 다시 만들기(연속 안 맞음 2번·검산 불일치·영역 met + 전체 unmet)는 작전의 범위만 다시 정하고 판정·할 일·승인을 바꾸지 않으며, 자동으로 만든 작전이 3개를 넘으면 그만두고 전체 판단으로 돌아간다(비용 상한). 작전 이벤트에는 종류와 코드가 만든 사유 코드만 넣는다(페이지·모델 글자 없음). 회차 중 사용자의 작전 지우기·만들기와 겹치면 시작 때 작전 상태(작전 id·요청 세대)와 다르니 그 회차의 작전 결과를 버린다. 작전 글은 영역 판단 요청의 user 메시지 안 `<plan_notes source="page-derived">` 데이터 블록에만 넣고(꺾쇠는 바꿔 블록을 닫지 못함) system 글·전체 판단 요청·이어서 진행 대화(`followUpText`)·텔레그램 알림에는 넣지 않는다. 저장 전 자동 로그인 값을 가리고(`maskDraft` — 선택자·기준점 글자가 가림으로 바뀌면 비밀 값이 든 작전으로 보고 거부), 가림 목록을 못 읽으면 어느 요청도 보내지 않는다(같은 회차에 다른 판단으로 다시 보내지 않음). 선택자는 `query_dom`과 같은 정책(`selectorBlock`, #45)을 응답 검사·content 실행에서 두 번 보고, 접근 가능한 같은 출처 루트에서만 실행한다. 영역 글자·영역 후보·기준점 비교 글자는 `modelText`·`groupLabelInfo` 경로로만 만들고 영역 뿌리가 보호 영역(값 컨트롤·편집 영역·숨김)이면 찾지 못한 것으로 본다(#43). 영역은 전체 화면 글자(`modelText(document.body)`)가 보는 자리에 있을 때만 본다 — 같은 합성 트리 규칙과 같은 숨김 판정을 거꾸로 따르는 `reachedByPageText`로 확인한다(화면에 없는 옛 글자로 unmet을 확정하지 않게). 영역의 정체에 쓰는 요소(기준점 제목 — 영역 안 제목과 합성 트리의 바로 앞 형제 제목, 이름표의 aria-labelledby 대상, 영역 후보의 제목·이름표)도 그려진 것만 쓰고, 영역 모양은 글자와 같게 숨김·글자 아닌 하위 트리를 뺀 합성 트리로 잰다. 영역 뿌리 안(shadow 포함)에 iframe·frame이 있거나 영역 글자(3,000자)나 영역 버튼(30개)이 상한을 넘으면 잘린 영역으로 보고 작전으로 받지 않으며 확인 회차엔 전체 판단한다(잘린 목록 밖의 버튼만 바뀌면 같은 요청으로 잘못 unmet을 확정할 수 있어서). 영역 후보의 선택자는 사람이 붙인 이름처럼 보이는 id·class(`plainWord`)와 역할·태그로만 만든다. 코드는 기준점 글자를 그대로 포함 비교하고 모양 해시·잘림만 보며 판단 기준의 뜻은 보지 않는다(낱말 목록 없음). 영역 버튼 목록의 `within`은 내부 전용 인자라 도구 인자(JSON)로는 받지 않는다. 작전을 만드는 동안 멈춤·지우기면 판정·작전을 모두 버리고, 확인 읽기 사이 문서가 바뀌면 작전만 버린다. 설정의 작전 "자세히"는 React 텍스트로만 보인다. 로그에는 결과 종류·사유 코드만 남긴다.
