# 크롬 웹 스토어 등록 자료

웹 스토어 개발자 대시보드에 넣을 내용과 올리는 절차입니다. 계정 등록(일회성 등록비, 2단계 인증, 연락 이메일 인증, Trader/Non-Trader 신고)은
게시자가 직접 합니다. 공식 안내: [게시](https://developer.chrome.com/docs/webstore/publish),
[개인정보 탭](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy), [심사](https://developer.chrome.com/docs/webstore/review-process).

## 올릴 파일

- 릴리스(`vX.X.XX` 태그)마다 `simple-browser-plugin-vX.X.XX-webstore.zip`이 함께 올라갑니다(`.github/workflows/release.yml`).
  `manifest.json`이 ZIP 최상위에 있고, 소스 맵과 MCP 다리(`mcp/`)는 없습니다. 릴리스 워크플로가 `scripts/checkManifest.mjs`로
  최상위 manifest, 버전, 권한(identity·activeTab 없음), 소스 맵 없음, `web_accessible_resources` 없음, content script가 다른 조각을 불러오지 않는
  한 파일(`content.js`)인지를 검사합니다(#215 — 웹 페이지가 확장 파일 주소를 불러 보아 설치 여부를 알 수 없게).
- 대시보드 → 항목 → 패키지에 이 ZIP을 올립니다. manifest 버전이 지금 올라가 있는 것보다 높아야 합니다(릴리스마다 수정 번호를 올리므로 맞음).
- 첫 게시는 등록 정보를 다 채워야 하므로 대시보드에서 직접 합니다. API(`chromewebstore.googleapis.com` v2)로 자동 업로드하는 일은 나중에 따로 합니다.

## 스토어판과 압축해제판의 차이

- **확장 ID**: 스토어판은 ID가 고정되고, 압축해제판(폴더에서 불러오기)과 다릅니다. Chrome은 둘을 다른 확장으로 보므로 설정·API 키·저장 링크가
  옮겨지지 않습니다. 옮겨 가는 사람은 키를 다시 넣고, KeePassXC 호스트 manifest의 `allowed_origins`도 새 ID로 다시 만듭니다(설정 화면이 보여 줌).
- **업데이트**: 스토어판은 Chrome이 자동으로 업데이트합니다.
- **MCP 다리**: 스토어 패키지에는 없습니다. 설정 화면과 [설치 안내](install.md#mcp-연동선택-claude-codeclaude-desktop-등)가 GitHub 릴리스의 설치용 ZIP에서 받도록 안내합니다.
- **Google 연동**: 스토어판에서도 꺼져 있습니다(클라이언트 ID 없음 → identity 권한도 없음). 켜려면 Drive 전체 범위가 Google의 제한된 범위라
  OAuth 앱 검증이 필요합니다.

## 스토어 등록 정보

- **이름**: 간편 브라우저 도우미
- **요약**(manifest description, 132자 이하): 사이드 패널에서 말로 시키는 브라우저 도우미. 페이지 요약·번역, 입력칸 채우기, 클릭·이동, 파일 읽기와 저장을 대신합니다.
- **카테고리**: 생산성(Productivity) → 도구(Tools)
- **언어**: 한국어
- **설명**(초안):

  > 지금 보는 웹 페이지를 사이드 패널에서 말로 시키는 도우미입니다. 페이지를 요약·번역하고, 입력칸을 채우고, 버튼을 누르고, PDF·한글·Office 파일을 읽고,
  > 이미지와 첨부 파일을 저장합니다. AI 모델은 직접 고르고 자기 API 키를 넣습니다(OpenRouter, OpenAI, Google Gemini, Anthropic Claude).
  >
  > 페이지를 바꾸는 동작(이동·클릭·입력·저장)은 기본으로 실행 전에 승인 카드로 묻습니다. 실행 방식에서 위험한 동작만 묻거나 처음에 한 번만 묻게 바꿀 수 있습니다.
  >
  > 선택 기능: 반복 확인(정한 간격으로 페이지를 확인해 조건이 맞으면 알림), 텔레그램으로 시키기, 다른 AI 도구에서 시키기(MCP), 음성 입력,
  > KeePassXC 자동 로그인.
  >
  > 대화와 페이지 내용은 사용자가 고른 AI 서비스로만 보냅니다. 이 프로젝트의 서버는 없습니다. 개인정보처리방침: https://github.com/ingki3/simple-browser-plugin/blob/main/docs/privacy.md
  > 소스 코드: https://github.com/ingki3/simple-browser-plugin

- **이미지**: 아이콘 128×128은 패키지 안(`icons/icon-128.png`)에 있습니다. 스크린샷은 최소 1장(1280×800 또는 640×400, 모서리 둥글리지 않음,
  여백 없이 꽉 채움)이 필요하고 아직 없습니다. 실제 사용 화면으로 만듭니다(예: 페이지 요약 답, 클릭 승인 카드, 설정 페이지). Chrome 창을
  1280×800으로 맞춰 캡처하고, 개인 정보·API 키·방문 기록이 보이지 않게 합니다. 만든 파일은 `docs/webstore/`에 둡니다.
  작은 홍보 타일(440×280)은 선택이지만 없으면 목록에서 뒤로 밀립니다.
- **개인정보처리방침 URL**: `https://github.com/ingki3/simple-browser-plugin/blob/main/docs/privacy.md`
- **지원 사이트**: `https://github.com/ingki3/simple-browser-plugin/issues`

## 개인정보 처리 탭

### 단일 목적

> 사이드 패널에서 사용자가 말로 요청하면, 사용자가 고른 AI 모델로 지금 보는 웹 페이지를 읽고 조작(요약·번역·입력·클릭·이동·파일 읽기와 저장)하는 브라우저 도우미입니다.
> 반복 확인, 텔레그램·MCP, 음성 입력, 자동 로그인은 같은 일을 다른 경로로 시키거나 돕는 선택 기능입니다.

### 권한별 사용 이유

| 권한 | 이유(대시보드에 넣을 문장) |
|---|---|
| `host_permissions: <all_urls>` | 사용자가 요청한 페이지(어느 사이트든)를 읽고 입력칸을 채우고 버튼을 누르려면 content script와 스크립트 주입이 모든 사이트에서 필요합니다. 페이지의 첨부 파일·링크 문서를 읽는 데도 씁니다. 페이지를 바꾸는 동작은 실행 전에 승인 카드로 묻습니다. |
| `sidePanel` | 확장의 화면이 사이드 패널입니다. |
| `storage` | 설정, API 키, 저장한 링크, 반복 작업, 동작 기록을 이 브라우저에만 저장합니다. |
| `tabs` | 지금 탭의 주소·제목을 알고, 클릭으로 열린 새 탭을 따라가고, 반복 작업을 위해 백그라운드 탭을 엽니다. |
| `scripting` | 확장을 설치하기 전에 열려 있던 탭에 content script를 넣고, 클릭 뒤 팝업 창이 열렸는지 확인합니다. 넣는 코드는 모두 패키지 안의 고정된 코드입니다. |
| `webNavigation` | 이동·클릭 뒤 페이지가 다 열릴 때까지 기다립니다. |
| `downloads` | 사용자가 요청한 이미지·첨부 파일·화면 캡처를 저장합니다. |
| `webRequest` | 파일을 읽을 때 리다이렉트 목적지를 알리려고 응답을 관찰만 합니다. 요청을 바꾸거나 막지 않습니다. |
| `offscreen` | PDF·한글·Office 문서 변환과 전체 페이지 캡처 이어 붙이기를 보이지 않는 문서의 Worker에서 합니다. |
| `alarms` | 사용자가 등록한 반복 작업의 간격, 텔레그램·MCP 요청 받기, 긴 작업 중 서비스 워커 유지에 씁니다. |
| `debugger` | 설정 → 동작에서 "실제 마우스 입력으로 클릭"을 켰을 때만, 스크립트 클릭에 반응하지 않는 사이트에서 승인된 클릭 한 번을 실제 입력으로 보냅니다. 누르는 동안 Chrome의 "디버깅 중" 막대가 뜹니다. Chrome이 이 권한을 선택 권한으로 둘 수 없게 해 설치 때 요청합니다. |
| `nativeMessaging`(선택) | 사용자가 켤 때만 요청합니다. 이 컴퓨터의 KeePassXC와 연결해 자동 로그인합니다. |
| `history`(선택) | 사용자가 "방문 기록에서 찾기"를 누를 때만 요청합니다. 다시 쓸 만한 페이지 후보를 고릅니다. |

### 원격 코드

"원격 코드를 사용하지 않습니다"를 고릅니다. 근거:

- 모든 스크립트(pdf.js, docling.rs-wasm, kordoc 포함)는 패키지 안에 있고, 원격 스크립트를 불러오지 않습니다(MV3 CSP `script-src 'self' 'wasm-unsafe-eval'`).
- AI 모델의 답은 코드로 실행하지 않습니다. 확장이 정한 도구(zod로 인자 검사)의 호출로만 쓰입니다.
- 번들의 kordoc 안 setImmediate polyfill에 `new Function`이 있지만 쓰지 않는 경로이고 확장 CSP가 막습니다.

### 데이터 사용 공개

로컬에서만 처리하는 것도 공개 대상입니다([FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)). 체크할 항목과 이유:

| 항목 | 체크 | 무엇을, 어디로 |
|---|---|---|
| 웹사이트 콘텐츠 | ✓ | 페이지 글자(숨은 요소·편집 영역 포함 가능), 파일 → 사용자가 고른 AI 서비스 |
| 웹 기록 | ✓ | 지금 탭의 전체 주소·제목(요청마다, 반복 작업은 주기마다) → AI 서비스. 방문 기록 찾기(선택)는 체크한 항목의 제목·사이트·경로·쿼리 이름만 |
| 사용자 활동 | ✓ | 동작 기록(승인한 클릭·입력의 대상 요약·결과, 입력값 없음) → 이 브라우저에만 |
| 인증 정보 | ✓ | 자동 로그인 아이디·비밀번호(KeePassXC에서 받아 그 로그인 페이지에 제출, AI로 보내지 않음, 세션 동안 가림 목록), API 키·텔레그램 토큰(로컬 저장, 그 서비스 호출에만) |
| 개인 통신 | ✓ | 사용자가 쓴 요청과 답 → AI 서비스, 텔레그램을 켠 경우 텔레그램 |
| 개인 식별 정보 | 상황에 따라 | 사용자가 요청에 쓰거나 페이지에 있는 이름·이메일 등은 위 항목으로 함께 보내질 수 있음(따로 모으지 않음) |
| 위치 | ✓ | 시간대 이름(예: Asia/Seoul)과 UTC 오프셋 → AI 서비스(정확한 위치는 아님) |
| 건강·금융·결제 | 체크하지 않음 | 따로 모으지 않음. 사용자가 그런 페이지에서 요청하면 웹사이트 콘텐츠로 보내질 수 있음 |

인증 세 가지(판매하지 않음, 목적과 무관한 용도로 쓰거나 넘기지 않음, 신용 판단·대출에 쓰지 않음)에 모두 체크합니다. 근거는 [개인정보처리방침 4절](privacy.md#4-limited-use-준수)입니다.

## 테스트 안내(심사자용)

> 1. 툴바 아이콘을 눌러 사이드 패널을 엽니다. 처음 화면의 "설정 열기"로 설정 탭을 열고, 모델·연결에서 OpenRouter 등 제공자를 고른 뒤 API 키를 넣고 저장합니다.
>    (심사용 키가 필요하면 여기에 사용 한도를 건 키를 적습니다.)
> 2. 아무 뉴스 페이지에서 "이 페이지 세 줄로 요약해 줘"를 보냅니다.
> 3. 검색창이 있는 페이지에서 "검색창에 날씨를 입력하고 검색해 줘"를 보내면, 입력·클릭 전에 승인 카드가 뜹니다.
> 4. 텔레그램·MCP·KeePassXC·음성 입력은 선택 기능이며, 각각 외부 계정이나 프로그램이 필요합니다(설정 화면에 절차가 있음).
> 5. 모델의 답은 코드로 실행하지 않고, 정해진 도구 호출로만 쓰입니다. 소스: https://github.com/ingki3/simple-browser-plugin

## 배포 설정 권장

- 처음에는 **비공개 링크(Unlisted)**로 올려 심사 결과를 봅니다. 권한(`debugger`, `<all_urls>`+`webRequest`)에 대한 지적이 오면 대응한 뒤 공개로 바꿉니다.
- 지역은 전체, 무료.
